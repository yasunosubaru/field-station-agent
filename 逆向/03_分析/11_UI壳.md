# UI 壳（Convert / Manage / Playback / Graph）

> 状态：**v0.2 可运行**。本文记录 `逆向/04_重实现/packages/app/` 的本地 Web 壳——
> 它把已有的协议层、转换管线、回放引擎与 Graph 导出数据接到一个可打开就用的界面上，
> 不追求像素级还原原版。证据等级沿用 `_约定.md`：`[观察]` 指本仓库代码/实测结果，
> 不涉及对原版的新取证。

---

## 1. 定位

`packages/app` 是一个**零依赖的 Node HTTP 服务 + 单页前端**。它只做三件事：

1. 把 `packages/protocol` 的确定性能力（SBF 拆帧、EDIE 解码、ASCII/缩略 ASCII/BINARY/KML/RINEX 写出）暴露成 HTTP 端点；
2. 提供一个不依赖外网的单页界面：Convert / Manage / Playback / Graph 四页；
3. 把 Playback 接到 `packages/playback` 的回放引擎（**只读 import**），把 Graph 页直接接到
   Graph 已经导出的 CSV（**不 import `packages/graph`**，那个包由平行任务重写中）。

它**不**重新实现任何协议逻辑：拆帧、解码、编码全部 `import` 自 `packages/protocol/src/*.ts`，
回放的时间轴与裁剪全部 `import` 自 `packages/playback/src/*.ts`（均只读引用，未修改一行）。

## 4. 端点清单

所有响应都是 JSON（下载端点除外），错误体固定为 `{"ok":false,"error":"…"}`。
除 `POST /api/convert`、`/api/playback/frames`、`/api/playback/export` 外均为只读 `GET`；
那两个也能用 `GET + 查询串` 调用，`HEAD` 在同一条路由上可用。

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/` | — | 单页 HTML（内联 CSS/JS）；CSP 只允许 `'self'` + 内联 |
| GET | `/api/health` | — | 服务名、版本、Node 版本、samples 相对路径、格式清单、预览/请求体上限 |
| GET | `/api/captures` | — | 枚举 samples 下 `.gps` / `.bin`（递归，深度 ≤ 6），返回 `path/name/bytes` |
| POST | `/api/convert` | body `{"capture":"…","format":"ASCII","at":"ISO 可选"}` | 跑转换；返回元信息 + 前 200 行预览 + `downloadUrl` |
| GET | `/api/download` | `token` | 下载上一次转换的完整产物（内存缓存，重启即失效） |
| GET | `/api/logs` | `capture` | 按 messageId 聚合：条数、CRC 失败数、GPS/UTC 时间范围、示例一行 |
| GET | `/api/records` | `capture`,`msgId`,`offset`(默认 0),`limit`(1..25) | 解码指定报文的第 N 帧，返回头部信息 + 字段表 |
| GET | `/api/playback/info` | `capture` | 时间轴：帧数、时长、首末 GPS、每类报文条数、速度档 |
| GET·POST | `/api/playback/frames` | `capture`,`from`,`to`（POST 放 JSON 体，均可省略） | 帧列表；无窗口时返回整个抓包，`offsetMs` 单调不减 |
| GET | `/api/playback/frame` | `capture`,`index` | 时间轴第 index 帧的头部 + 解码字段（≤400 项） |
| GET·POST | `/api/playback/export` | `capture`,`from`,`to` | 下载原始 SBF 片段（`exportRange` 逐字节），响应头带 `X-Playback-Frames/-From/-To` |
| GET | `/api/graph/files` | — | `samples/graph/export/csv/` 下实际存在的 CSV：行数、列数、数值列 |
| GET | `/api/graph/data` | `file`,`column`（可选） | 注释元数据 + 列名 + 一条 x/y 序列 + 前 20 行 |

### 4.1 `POST /api/convert` 细节

- `format` ∈ `ASCII` / `ABBREV_ASCII` / `BINARY` / `KML` / `RINEX21`，缺省 `ASCII`，大小写不敏感。
- 只输出 CRC 通过的记录；ASCII/缩略 ASCII 统一 CRLF 行尾；BINARY 是原记录逐字节拼接。
- 预览是**按行**截断：最多 200 行。`truncated` 表示总行数是否超过 200。
  - 例如 `clean-9600.gps → ASCII` 只有 119 行（每行很长），因此 `truncated=false`，
    全文放在 `text` 里（478 KB）；
  - 同一抓包的 `ABBREV_ASCII` 有 6 294 行，`truncated=true`，`text=null`，只给 `preview`（前 200 行）。
- BINARY 没有文本，`text=null`，`preview` 是 200 行十六进制 dump。
- 响应字段：`fileName / bytes / lineTotal / shownLines / truncated / binary / text / preview /
  downloadUrl / elapsedMs / records{total,accepted,dropped,textRecords} / at`。
- `text` 与 `preview` **互斥**：正文不超过 200 行时给 `text`（完整），超过时给 `preview`（截断）；
  两者不会同时出现，避免把 489 KB 发两遍。
- 计数口径：`total` 是 mirror 模式拆出的记录数（CRC 字段为 0 的记录在拆帧层即被丢弃，不计入）；
  `dropped` 是 CRC 字段非 0 但校验不符的记录；`textRecords` 是 `#`/`%`/`<`/`$`/`[` 文本记录，
  不参与任何二进制转换。对 `clean-9600.gps`：119 / 119 / 0 / 0；对 `broad-clean.gps`：1722 / 1721 / 1 / 0。

### 4.2 下载

`token` 是 9 字节随机十六进制，进程内最多保留 40 份产物（约 300 MB 上限的粗略保护，实际按条目数）。
`Content-Disposition` 同时给 ASCII 回退名与 `filename*=UTF-8''…`。
旧 token 被淘汰后返回 404，提示重新转换。

### 4.3 路径安全

`[观察] packages/app/src/paths.ts`：

- 拒绝绝对路径、盘符（`C:`）、空段、`.`、任何 `..` 段、NUL、非 `.gps/.bin` 扩展名；
- 解析结果必须仍在 `SAMPLES_DIR` 内（`relative()` 不以 `..` 开头且非绝对）；
- 也接受裸文件名（如 `clean-9600.gps`），查找顺序：精确相对路径 → `samples/convert/<name>` → 全树唯一 basename；
- 重名且无法唯一确定时返回 409 并列出候选；
- **不做任何写入**：转换结果只存在内存，样例目录始终只读。

### 4.4 缓存

- `capture.ts` 以 `(绝对路径, 大小, mtime)` 为键缓存拆帧结果，最多 4 份。3 MB 抓包二次访问不再重拆。
- `edie-layouts.json`（496 KB）每进程只解析一次。
- 产物缓存与帧缓存均在重启后失效，无持久化。

### 4.5 Playback 端点

- **引擎只读复用。** `playback.ts` 用 `PlaybackEngine.load()` 把抓包拆成时间轴，按
  `(绝对路径, 大小, mtime)` 缓存最多 3 份引擎；`info` / `frames` / `frame` / `export` 共用同一份，
  页面刷新不会重拆。`packages/playback` 一行未改。
- **`info`** 返回 `frameCount / durationMs / startWeek / startTime / finishWeek / finishTime /
  startUtc / finishUtc / messageCounts[{id,name,known,count}] / stats{textFrames,badCrc,bufferedBytes} /
  speeds`。时长是首末记录的 `offsetMs` 差（不是文件时间戳跨度），`clean-9600.gps` = 119 帧 / 4950 ms。
- **`frames`** 每帧只给轻量摘要 `{index,messageId,name,known,week,milliseconds,offsetMs,time,bytes}`，
  **不含字段**：`broad-clean.gps` 1722 帧 × RANGE 601 字段一次性发出去是数 MB 的无用负载。
  `from`/`to` 秒数含两端，超出抓包会被夹到 `[0, duration]`。
- **`frame`** 解一帧的 EDIE 字段（≤400 项，`fieldsTruncated` 标记截断），页面只在**当前帧编号变化**时
  请求它，并用「单飞 + 一个待取槽」合并快速拖动产生的请求。
- **`export`** 直接返回 `engine.exportRange(from, to)` 的字节：逐字节复制抓包记录，CRC 不重算；
  `from > duration` 是 400，`to` 会被夹到时长。`from=1&to=2` 得 26 帧 / 56 836 B。
- 回放时钟在**浏览器**里：`requestAnimationFrame` 按 `delta × speed` 推进，速度档取自引擎的
  `PLAYBACK_SPEEDS`（0.5 / 1 / 2 / 4 / 8）。服务端不保存播放状态，因此多标签页互不影响。

### 4.6 Graph 端点

- 数据源固定为 `逆向/00_来源/samples/graph/export/csv/`，**不 import `packages/graph`**：
  那个包在平行任务里重写，而页面要的是 Graph 已经导出的产物。
- `files` 列目录里**实际存在**的 `.csv`（当前 12 份），每项带 `rows`（数据行，不含 6 行 `#` 注释与表头）、
  `columns`、`numericColumns`、`hasTimeColumn`；按 `localeCompare('en')` 排序。
- 解析规则（`[观察]` 实测）：UTF-8 BOM 去掉；`#` 开头是注释（前 6 行被读成
  `projectName / projectDirectory / dataFileName / startTime / endTime / duration`）；
  第一条非注释行是表头；其余是数据行，短行补空、长行截断。
- 时间列 = 表头含 `timestamp` 的列，单元格形如 `"2442  463098.000"`（周 + 周内秒，**用空格分隔**），
  解析成绝对 GPS 秒后转成「相对首帧秒数」。没有时间列（`Receiver Status.csv`）时 x 用行序号。
- y 列 = 第一个「非空单元格都能解析成有限数」的列，`?column=` 可指定。全部是枚举文本的文件
  （`Position Status.csv` / `Position Type.csv`）返回 `column:null`、`series.points:[]`，页面只画表格。
- 安全边界同抓包：只接受裸文件名 + `.csv`，拒绝绝对路径、盘符、任何 `/` `\` 与 `..`。

## 5. 前端四页

单文件 `src/web/index.html`，无构建步骤、无外部请求；`fetch` 只打同源 `/api/*`。

### Convert
- 抓包下拉（来自 `/api/captures`）、格式下拉（含一行格式说明）、开始/清空。
- 结果卡片：产物名、大小、行数、有效记录、耗时、下载按钮。
- 预览：等宽字体 + 行号栏，纵向滚动 430 px，横向滚动承载超长 ASCII 行；
  标题旁徽标显示格式（`ASCII` / `HEX`），右侧说明「全部 N 行」或「仅显示前 200 / N 行，完整内容请下载」。
- 下载按钮直接指向 `/api/download?token=…`，由浏览器保存。

### Manage
- 统计卡：总记录 / CRC 有效 / 丢弃 / 报文类型数；下方一行显示抓包与首条 UTC。
- 表格：ID、名称（无 EDIE 布局时标「无布局」）、条数、CRC 失败、GPS 与 UTC 时间范围、示例一行。
- 点击任意行 → 下方「字段表」：
  - 头部 chip：帧序号、端口、序号、GPS、UTC、时间状态、接收机状态、载荷/整帧字节、CRC；
  - 上一帧 / 下一帧（`offset` 翻页），字段筛选框（按路径或显示值）；
  - 三列：字段路径、显示值（枚举名/格式化文本）、原始值（与显示值相同时留空）；
  - 单帧最多 800 个字段，超出标注；RANGE 一帧约 601 个字段（1 个计数 + 60 颗星 × 10）。
- 类型筛选框同时匹配 ID、名称与示例内容。

### Playback
- 抓包下拉 + 倍速下拉 + 「载入时间轴」；切换抓包自动重新载入。载入后统计卡显示
  帧数 / 时长（秒 + 毫秒）/ 报文类型数 / CRC 丢弃数，下面一行给首末 UTC 与每类条数。
- 时间轴是**能拖的**：上方 `<input type=range>` 覆盖整段时长（拖动 → 按百分比换算秒数），
  下方 SVG 把 119 帧按 `offsetMs` 画成 3 px 竖条（按 messageId 上色，同一毫秒的帧重叠），
  播放头是一条竖线 + 顶部圆点，随播放位置移动；刻度每 25 % 标一次秒数。
- 播放 / 暂停 / 回到起点 + 当前时间 `3.084 s / 4.950 s` + 对应 GPS 周/周内秒。
  `▶` 之后由 `requestAnimationFrame` 推进，播到末尾自动变「已结束」，再点 `▶` 从头开始。
- 「当前帧」卡片：报文名 + 帧序号 + GPS + 时间轴偏移 + 整帧字节，下面是最多 12 个
  `path + 显示值` 的字段 chip（RANGE 显示 `obs[0].psr` 这类路径，末尾标「共 601 项」）。
  字段来自 `/api/playback/frame`，快速拖动时只保留最后一次请求。
- 裁剪导出：起 / 止秒数（默认 `0` / 时长），「生成下载」把 `<a download>` 指向
  `/api/playback/export?capture=…&from=…&to=…`，浏览器直接保存原始 SBF（文件名
  `clean-9600_1.000-2.000.sbf`）。

### Graph
- 文件下拉列出 `samples/graph/export/csv/` 里实际存在的 12 份 CSV（带行数/列数/大小），
  第二个下拉列出该文件的数值列（默认第一个，`Tracking Time.csv` 有 60 个可选）。
- 折线图是**手写内联 SVG**（无图表库）：x = 时间列（相对首帧秒数，或行序号），y = 选中列；
  4 条横向网格 + 5 条纵向刻度，点 ≤ 80 时额外画圆点，右上角标 `y = 列名`，底部标
  `时间（相对首帧，s）· W2442 463097.350 → W2442 463102.250`。
- 表格显示前 20 行（列多时在 `.table-scroll` 里横向滚动），标题右侧标「显示前 20 / 99 行」。
- 顶部一行给工程名、数据文件名、GPS 起止与原始 `#Duration`，全部来自 CSV 注释块。

## 7. 当前限制

1. **回放时钟在浏览器**，服务端不持有播放状态：页面切到后台时 `requestAnimationFrame` 会暂停
   （页面把单步上限压到 250 ms，回来不会一次跳过整段）；多标签页各播各的，不共享进度。
2. **帧列表一次全量**：`/api/playback/frames` 默认给整段抓包（`clean-9600.gps` 119 帧约 14 KB，
   `broad-clean.gps` 1722 帧约 200 KB）。二次拆包已避免，但超大抓包（数万帧）应改用 `from/to` 窗口。
3. **单帧字段上限 400**：RANGE 一帧 601 个字段，页面只显示前 12 个 chip + 「共 601 项」；
   想看全部字段要到 Manage 页（上限 800）或直接看 ASCII。
4. **Graph 只读导出产物**：CSV 的解析器假定值与列名里没有逗号/引号转义（这 12 份样例确实没有）；
   也不解析 `.gpf` 工程或重新渲染图表，图表列表取决于 Graph 已经导出了哪些 CSV。
5. **Graph 表格不虚拟化**：只渲染前 20 行，行数再多也不影响；但列多（75 列）时靠横向滚动。
6. **只读**：页面上传/落盘均不支持；服务端不写 samples，也不写临时目录。抓包必须事先放进
   `逆向/00_来源/samples/`（`.gps` / `.bin`）。
7. **预览按行不按字节**：一行可能 4 KB，119 行的 ASCII 仍有约 478 KB 进入 JSON。
   若将来出现单行数 MB 的报文，需要给 `textPreview()` 增加字符上限（当前未加，避免悄悄改变「全文」语义）。
8. **下载链接是内存 token**：进程重启、或超过 40 次转换后旧链接失效。Playback 的导出链接不带 token，
   每次请求现算，因此重启后仍然可用。
9. **无并发控制**：两个请求同时转换同一抓包会各自跑一遍管线（帧缓存只省拆包，不省编码）。
   大抓包（`broad-clean.gps`，3.2 MB）ASCII 转换约 1.8 s，足以让用户连点；前端已禁用按钮，但 API 无锁。
10. **格式面**：仅接已实现的 5 种。RINEX 3.x、Hatanaka、按日志/时间窗筛选、拆分等原版 Convert 能力未接。
11. **时间语义沿用镜像缺陷**：UTC 列与 Summary 一样按「GPS 秒当 UTC」显示，不做 18 s 闰秒修正
    （与 `summary.ts` 的已知缺陷一致）。同一条规则用在 Playback 的首末 UTC 与 CSV 元数据上，
    因此页面里的 UTC 比真实 UTC 早 18 s，而时间轴本身的秒数是相对的、不受影响。
12. **单机单进程**：只监听 `127.0.0.1`，无鉴权、无 TLS、无多用户；CSP 允许内联脚本（因为页面就是内联的）。
13. **无国际化**：界面固定简体中文；原版的 20/9 语言切换未接。
14. **目录假设**：`SAMPLES_DIR` 与 `GRAPH_CSV_DIR` 在模块加载时按 `import.meta.url` 推出
    （`packages/app/src` 上溯到仓库根）。运行时移动仓库目录需要重启。

## 9. 外观按原版重做（2026-10-31，v0.3）

用户指出 v0.2 的页面"和官方软件一点都不一样"：它是一套自绘的青色控制台。v0.3 按原版重做，
**功能不变，外观换成 NovAtel Application Suite 的样子**。

### 9.1 原版外观是怎么来的

- `逆向/01_解包/app/view/css/style.css`（773 KB）是配色/字体/圆角/阴影的**唯一真值**；
  字体是 **Open Sans**（`view/fonts/`），不是 Roboto
- 原版 `view/html/index.html`（77 KB）里有顶栏、左侧轨、状态带的**原始类名**，但 UI 是
  Electron 里由 JS 装配的：直接 `file://` 打开只会停在 "Initializing..." 启动页
  （实测：`require is not defined`，`#wrapper` 只有 53×31），所以**不能整文件照搬**
- 做法：从 `style.css` 里摘出实际用到的规则 → `packages/app/src/web/shell.css`；
  字体只复制 4 个（约 160 KB）→ `web/fonts/`；图片走 `/assets/*` 运行时从
  `FIELD_STATION_VIEW_ASSETS`（默认 `逆向/01_解包/app/view`）读取，避免把 10 MB 图标搬进仓库

### 10.2 字体

原版 `style.css:184-216` 共 8 条 `@font-face`，被 `font-family` 引用的只有 6 款
（Roboto/Akkurat 只在下拉等处用，外壳没有）。我们补齐了真斜体：
`OpenSans-Italic.ttf`、`OpenSans-LightItalic.ttf`（各约 26 KB），挂在原家族名下，
`<em>` 不再靠合成倾斜。`web/fonts/` 合计 214 KB / 6 个文件。

**原版没有图标字体**（8 个 ttf 全是 Open Sans），图标一律是 `images/*.svg`。

### 10.3 light / dark 主题

原版的深色写法是 **`body.darkMode`**（`view/html/index.html:1071-1073` 加 class，
`style.css:23313` 起是 `.darkMode` 那一整段），浅色 = body 上没有 class。

- `web/theme.js`：`setTheme/getTheme/toggleTheme/initTheme`，写 `body.classList`，
  存 `localStorage['nas-theme'] = 'dark-theme'|'light-theme'`（沿用原版名字），
  无保存值时跟随 `prefers-color-scheme` 并监听系统切换；切换按钮由 JS 插在齿轮左侧
  （`[data-theme-toggle]`），不动 HTML。
- `web/theme.css`：72 条规则，颜色逐条注明 `style.css` 行号；含三块面板内部的
  `--nas-*` token 翻转（否则深色下会出现白卡片白字）。

实测：`body.classList` = `["darkMode"]`、`body.matches('body.darkMode')` true、
刷新后仍为深色、0 非 2xx；深色下 body `rgb(18,18,18)`、左轨 `rgb(72,72,72)`、
卡片 `rgba(255,255,255,0.12)` + `rgb(39,160,191)`、表格头 `rgb(29,29,29)`，
与 `style.css` 对应行一致。

### 10.4 现在的接线

`index.html` 头部顺序：`shell.css` → `icons.css` → `theme.css`，body 末尾
`<script type="module" src="/theme.js">`；`server.ts` 静态白名单已包含
`/shell.css`、`/icons.css`、`/theme.css`、`/theme.js`、`/panels/`、`/icons/`、`/fonts/`。

### 10.5 像素比对的现状

工具在 `逆向/tools/ui-diff.ts`，结论与限制见 `15_UI像素比对.md`：
现有参照截图**带夜间滤镜、跨分辨率、跨页面**，只能做结构指纹（8×8 网格 + 行列投影），
颜色无法比对；要做真正的像素级 1:1，需要"无滤镜、同分辨率、同 DPI、同抓包"的成对参照。
