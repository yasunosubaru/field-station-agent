## 3. 为什么真实鼠标点击「有时」不弹对话框

### 3.1 先说本轮**没有**证实什么

- `[未验]` 本轮两次真实（Playwright）点击 Select，`showOpenDialog` **每次都被调用**（2/2），没有复现"完全不调用对话框"的那一次。因此"点击被 React 吞掉 / 按钮 disabled / IPC 没发出"**不是**本轮能给出的结论。
- `[未验]` 原生对话框是否在屏幕上出现，本轮用桩函数替换了 `showOpenDialog`（否则自动化会永远卡住），**没有直接观察窗口渲染**。
- `[源码]` 全文没有 `userActivation` / `isActive` / "user gesture" 检查；渲染进程也没有 `onWindowBlur` / `window-blur` 的使用（`grep` 命中 0）——所以"代码里显式检查用户手势而拒绝弹窗"这条假设**被排除**。

### 3.2 源码级根因（按证据强度排序）

**① 对话框调用被 5~6 次 IPC `await` 从点击的同步栈里推出去了** —— `[源码]`

`createProject()`（@640674）从 `onClick` 到 `selectDirectoryDialog` 之间依次 `await`：

```
getUserSettingsJson() → pathJoin() → getDir() → validateAndGetPath()
   → getDir() → isDirectoryExists() → selectDirectoryDialog()
```

即 **6 个 `await`、每一次都是一次独立的 `ipcRenderer.invoke` 往返**。`[动态]` 实测从 `DOM_CLICK(Select)` 到 `showOpenDialog` 只隔 7 ms（本机 IPC 很快），但逻辑上对话框已经不在用户点击的同步调用栈内。

**② 主进程把「当前聚焦窗口」当作模态父窗口** —— `[源码] + [动态]`

`main.jsc:1:14475` 调 `BrowserWindow.getFocusedWindow()`，紧接着 `1:14594` 把结果作为 `showOpenDialog` 的第一个参数。`getFocusedWindow()` 在应用没有聚焦窗口时返回 `null`，此时 `dialog.showOpenDialog(null, opts)` 是**非模态**对话框 —— 在 Windows 上可能落最大化后的 Graph 主窗口**后面**，用户看到的就是"点了没反应"。

**③ 应用自己知道焦点会丢，但渲染进程从不消费这个信号** —— `[源码]`

`main.jsc@76129 browser-window-blur` → `main.jsc@70389 window-blur` → preload 暴露 `app.onWindowBlur`（`preload.jsc@19651`；通道串 `window-blur` 在 `preload.jsc@3256`），
但 `index-B86bHcCD.js` 里 `onWindowBlur` / `window-blur` 命中数 **0**。
`[推断]` 焦点状态在两侧之间没有闭环，② 的 `getFocusedWindow()` 结果不会再被校验一次。

**④ 一个更隐蔽的源码脆弱点（低概率但确实存在）** —— `[源码]`

```js
const userSettings=await getUserSettingsJson(),
      {projectDirectory:lastOpenedDirectory}=userSettings.lastOpened;
```

`userSettings.lastOpened` 无可选链/默认值；若 `file:get-user-settings` 返回的对象缺 `lastOpened`，这里会 `throw`，`validateAndGetPath()` 根本不会执行 → 对话框完全不弹。`main.jsc@10554 userSettings.json`、`@11074 lastOpened`、`@11100 recents` 显示主进程**有**构造默认设置，所以正常首次运行不会触发；`[未验]` 设置文件损坏/被外部改写时的行为未测。

### 3.3 一句话结论

> **Select 的 onClick 是一个串了 6 次 IPC `await` 的 async 函数，等它终于走到 `window.file.selectDirectoryDialog` 时已不在用户手势的同步栈里；主进程又用 `BrowserWindow.getFocusedWindow()` 的返回值做模态父窗口，一旦这段异步期间焦点/前置窗口变化，父窗口为 `null`，原生 `dialog.showOpenDialog` 变成非模态并可能藏到 Graph 主窗口后面——表现为"真实点击有时不弹对话框"。**

`[推断]` 上面"藏到窗口后面"这一段是推理（依据 ①②③ + 仓库既有的两处自动化事实：`06_Graph应用.md §9.2` 记录导出时被目的地对话框卡住、`14_Graph第二份样本.md §6.1` 明确说"两条路都堵死原生弹窗，因为单独一条不保证"）。**能确定的事实**只有：调用链被 6 次 IPC await 打断、父窗口取自 `getFocusedWindow()`、源码里没有任何手势检查。
