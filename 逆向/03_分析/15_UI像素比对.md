# UI 像素比对（`tools/ui-diff.ts`）

> 状态：**v1 可用**。本文记录一个可重复的"像不像"量化工具：解 PNG、比像素、按矩形分区统计、
> 以及在没有可比颜色时只比结构的 8×8 指纹。文中的数字全部是本机实跑结果，命令附在每节。
> 证据等级沿用 `_约定.md`：`[观察]` 指本仓库工具/实测输出，不涉及对原版的新取证。

---

## 1. 为什么要它

`11_UI壳.md` 里的界面是"能跑通"的复刻，不是像素级还原。判断"改完更像了还是更不像了"，
靠肉眼看截图不可重复：换一台机器、换一次缩放、换个夜间滤镜，结论就会翻转。

这个工具只做三件可重复的事：

1. **像素差**（同尺寸、同状态时可信）：差异像素占比、平均绝对差、最大通道差，外加一张差异图；
2. **分区差**：把顶栏/导航轨/内容区拆开分别看，避免整页平均把局部塌陷抹平；
3. **结构指纹**：二值化后 8×8 网格的深色像素比例 + 64 档行/列投影，用于"参照带夜间滤镜、
   颜色不可比"时只比骨架。

它**不**判断"像不像原版"，只输出可复算的数字；判断仍由人做，但每次可以用同一条命令复现。

---

## 2. 工具

`逆向/tools/ui-diff.ts`，Node 24 直跑，**零第三方依赖**：PNG 的解码与编码全部自己写，
压缩用内置 `node:zlib`。

### 2.1 用法

```powershell
# 像素差 + 差异图
node 逆向/tools/ui-diff.ts --a ref.png --b ours.png --out diff.png

# 分区统计（JSON 文件或内联 JSON 均可）
node 逆向/tools/ui-diff.ts --a ref.png --b ours.png --out diff.png --regions 区域.json

# 只比结构（有夜间滤镜、分辨率不同时用这个）
node 逆向/tools/ui-diff.ts --a ref.png --b ours.png --layout

# 对照实验：把 B 水平翻转后再比，不落盘
node 逆向/tools/ui-diff.ts --a ours.png --b ours.png --flip b --out flip.png
```

### 2.2 参数

| 参数 | 说明 |
|---|---|
| `--a` / `--b` | 两张待比 PNG。**A 是参照**，坐标、尺寸都以 A 为准 |
| `--out` | 差异图输出路径（差异像素标红，其余压暗成灰度）。省略则不写文件 |
| `--regions` | 矩形分区。`{"topbar":[0,0,2560,120]}` 或 `{"topbar":{"x":0,"y":0,"w":2560,"h":120}}`，也接受 JSON 文件路径 |
| `--layout` | 只出结构指纹：8×8 深色像素比例 + 余弦/相关系数 + 64 档行/列投影（不给 `--out` 时不做像素差） |
| `--grid N` | 指纹网格边长，默认 8 |
| `--dark N` | 二值化阈值（亮度 < N 记为深色），默认 128 |
| `--tolerance N` | 允许的单通道差（0–255），超过才计为差异像素，默认 0（逐像素严格） |
| `--flip a\|b` | 对比前把指定那张水平翻转，用于对照实验 |
| `-h` / `--help` | 帮助 |

尺寸不同时**只缩放 B**（最近邻）到 A 的尺寸，A 永不缩放；这一点很关键，因为区域坐标、
差异图像素坐标都是以 A 为坐标系。缩放会在输出里显式注明，提醒数值偏高。

### 2.3 输出

stdout 是 Markdown（可直接贴本文这类文档），按参数给出四段：输入、像素差异（整体）、
像素差异（分区，仅 `--regions`）、结构指纹（仅 `--layout`）。每段都是一张表，
结构指纹另给两个 8×8 矩阵和一个 64 档投影的字符图。

错误一律一行 `ui-diff: <原因>` 到 stderr、退出码 1，不打印半个结果。

## 3. 实现与可信度

### 3.1 PNG 解码范围

| 项 | 支持 | 不支持的报错 |
|---|---|---|
| 色彩类型 | 2（RGB）、6（RGBA） | `unsupported PNG — color type 3 (palette)` / `0 (grayscale)` 等 |
| 位深 | 8 | `unsupported PNG — bit depth 16` |
| 扫描方式 | 非隔行 | `unsupported PNG — interlaced (Adam7)` |
| 滤波器 | 0/1/2/3/4 全部（Sub/Up/Average/Paeth） | 未知滤波器报行号 |

不"猜"格式：遇到 palette / 灰度 / 16 位就直接拒绝，避免拿错解出来的像素算出一个看着合理的错数字。
alpha 通道会被读出但不参与比较（截图都是不透明的，比 alpha 只会引入噪声）。

### 3.2 与 PIL 的全量校验 `[观察]`

解码器是手写的，所以用独立实现交叉验过：对三张参照图的 **全部 RGB 字节**算同一个加权校验和
（`Σ byte[i]·(i mod 251 + 1) mod 1e9+7`），Node 侧与 Python/PIL 侧逐字节一致：

| 图 | 格式 | 尺寸 | 校验和 |
|---|---|---|---|
| `ref-ui/manage.png` | RGBA | 2560×1600 | 259621633（两侧一致） |
| `ui-final.png` | RGB | 1440×900 | 142502054（两侧一致） |
| `grit-dashboard.png` | RGBA | 1707×1067 | 120329101（两侧一致） |

三张图恰好覆盖 RGB 与 RGBA 两种色彩类型；滤波器方面，两张参照图是整幅 filter 0，而我们的截图
900 行里 571 行 Up、260 行 Paeth、67 行 Sub、2 行 Average——**四种非零滤波器全部走到**，
解码路径基本被压了一遍。另外抽查了角点、边缘、纯色区各若干像素，RGB 三元组与 PIL 完全相同。

差异图编码器也验过：PIL 打开三张输出（1440×900 / 2560×1600）模式均为 RGB，尺寸正确。

### 3.3 两条对照实验（工具自己的行为）

**(a) 自己跟自己比**：应当零差异。

```powershell
node 逆向/tools/ui-diff.ts --a ui-final.png --b ui-final.png --out diff-self.png
```

| 指标 | 结果 |
|---|---|
| 差异像素占比 | 0.00%（0 / 1,296,000） |
| 平均绝对差 | 0.000 / 255 |
| 最大通道差 | 0 |
| 判定 | 逐像素完全相同 |

差异图再用 PIL 复查：**红像素 0 个**（"匹配"分支确实全部走灰度）。

**(b) 跟自己翻转后比**：应当大量差异。

```powershell
node 逆向/tools/ui-diff.ts --a ui-final.png --b ui-final.png --flip b --out diff-flip.png
```

| 指标 | 结果 |
|---|---|
| 差异像素占比 | 29.26%（379,266 / 1,296,000） |
| 平均绝对差 | 18.054 / 255（7.08% 满量程） |
| 最大通道差 | 255 |
| 最差像素 | (28, 8) |

差异图的红像素数用 PIL 数出来正好 **379,266**，与统计完全吻合——统计和渲染走的是同一判据，
不存在"报了一套、画了另一套"。

29.26% 而不是 100%，原因是这张 Manage 页大面积是纯白与浅灰底：左右翻转后大片空白仍然对上，
真正变的是导航轨、标签页、文字与面板边框。**这说明指标对"内容搬动"敏感、对"空白区"不敏感**，
读数值时必须配合差异图看红区在哪。

- **尺寸不同**（1707×1067 vs 1440×900）。虽然两者长宽比都≈1.60，除得 1.185 / 1.186，
  但 `--layout` 是各自归一化到自己的 8×8，尺寸本身不罚分，罚分来自内容。
- **关键的一行对不上**：A 的第 1 行整行 0.58–0.69 是深色，那是 GRIT 那条**整宽黑色标签条**
  （Dashboard/Settings/Tools/Help）；我们这行是白色内容区（0.01–0.06）。
  仅这一行就贡献了 0.53–0.68 的格差，也是"最大格差 @ 行1"的来源。
- 行分布余弦只有 0.56，正是"上下分区结构不同"的直接读数；列分布 0.91 说明左右骨架（左轨 + 主区）
  反而接近——这两条比单个余弦值信息量大得多。

结论：**0.8123 不是"还原度 81%"**，它只说明"两张 1.6 比例的深色 chrome 界面，骨架有六到八成重合，
但页面不同"。这类跨页、跨分辨率的数字只能当"工具跑通了"的证据，不能写进还原度。

### 4.2 `--regions`：manage.png vs ui-final.png

```powershell
node 逆向/tools/ui-diff.ts --a manage.png --b ui-final.png --out diff-manage-final.png --regions 区域.json
```

区域定义（按 A 的 2560×1600 像素空间；85px 宽的左轨、147px 高的 chrome）：

```json
{
  "titlebar": [0, 0, 2560, 30],
  "appbar":   [0, 30, 2560, 63],
  "tabbar":   [0, 93, 2560, 54],
  "rail":     [0, 147, 85, 1453],
  "content":  [85, 147, 2475, 1453]
}
```

| 区域 | x,y 宽×高 | 占画布 | 差异像素占比 | 平均绝对差 | 最大通道差 |
|---|---|---|---|---|---|
| titlebar | 0,0 2560×30 | 1.9% | 100.00% | 107.25 | 255 |
| appbar | 0,30 2560×63 | 3.9% | 100.00% | 56.26 | 255 |
| tabbar | 0,93 2560×54 | 3.4% | 100.00% | 79.13 | 255 |
| rail | 0,147 85×1453 | 3.0% | 100.00% | 87.36 | 226 |
| content | 85,147 2475×1453 | 87.8% | 100.00% | 96.50 | 255 |
| **全图** | 2560×1600 | 100% | **100.00%** | **94.252**（36.96% 满量程） | 255 |

**每一格都是 100%，这是正确结果，不是 bug**：参照图带橙色夜间滤镜，白底被整体压成 `(255,160,77)`
这类颜色，于是**每一个像素**都变了。加容差也救不回来：同样两组输入用 `--tolerance 40`，
整体仍是 99.78%（4,087,099 / 4,096,000 像素），五个区域分别是 100.00 / 99.94 / 99.80 / 99.98 / 99.76%——
容差只是在"几乎全差"里挑出极少数恰好接近的像素。

数值上能读出来的只有量级差别：`appbar`（56）和 `tabbar`（79）最低，因为参照这两条本身就是深色底，
滤镜把深底改成橙褐只挪动几十级；而 `content`（96）大片是**本该纯白**的底，滤镜把 G/B 各压掉
95–178 级，平均差自然最大。`titlebar`（107）最高则是**真实的结构差异**：参照是 Windows 深色标题栏
（底部 32,20,10），我们这张截图没有标题栏、顶上是蓝色应用条——两者连"有没有这条"都不一样，
值得单独记下来（我们的截图缺 OS 标题栏）。

**缩放会让数值偏高**，这一条单独量过：把 `ui-final.png` 缩到 1024×640，再让工具把它放大回 1440×900，
**同一张图**的差异就有 21.38%（277,121 像素）、平均差 4.45、最大差 219——全部来自"下采样丢细节 +
最近邻放大成块"。本次是 1440×900 → 2560×1600（1.78 倍，面积 3.2 倍），每个源像素要铺成 1.78×1.78
的一小块，文字与 1px 边框必然错位。所以 100% 里有多少是滤镜、多少是缩放，无法从这一组数里拆开。

### 4.3 附带测到的两条校准数据

这两条不属于任务要求，但决定了以后怎么读 `--layout` 的数字：

| 对照 | 余弦 | Pearson | 行分布 | 列分布 | 含义 |
|---|---|---|---|---|---|
| ui-final vs 它自己翻转 | 0.8990 | 0.8672 | 1.0000 | 0.7482 | 8×8 指纹**看不出**左右镜像（暗块换成暗块） |
| grit-dashboard vs manage.png | 0.7648 | 0.6836 | 0.5199 | 0.9804 | 同一产品的两个原版页，只有 0.76 |

- 镜像只掉到 0.90，但**行分布恰好 1.0000**（上下结构逐档相同）、列分布掉到 0.75，
  8×8 差值矩阵呈近似对称：行 0 两端 0.27、行 2/行 3 两端 0.25–0.26、行 5/行 6 左端 0.10–0.11。
  镜像的"指纹"是**对称的差值矩阵**，不是那个标量。所以 `--layout` 只当粗筛，判读必须看矩阵与投影。
- 同一产品的两个页面只有 0.76，列分布却高达 0.98（左轨/主区骨架相同）——说明 0.8 这个量级
  **不能**被解读成"高度还原"；同一组数字必须和"行分布/列分布分开看"一起读。

## 5. 结论

### 5.1 现在能比什么

| 能比 | 前提 | 依据 |
|---|---|---|
| 我们自己前后两版是否逐像素一致 | 同分辨率、同页面状态 | 自比 0.00%，翻转 29.26%，判据明确 |
| 某次改动落在哪一块 | 任意 | 差异图红区 + 分区表；红像素数与统计严格一致 |
| 粗结构（上下分区、左轨有无、面板几栏） | 允许缩放、允许滤镜 | 二值化后 8×8 + 64 档行/列投影，与颜色无关 |
| 深色/浅色主题的整体明暗 | 任意 | 指纹矩阵直接读深色比例 |

### 5.2 现在不能比什么

- **颜色、亮度、对比度**：`ref-ui/manage.png` 带橙色夜间滤镜，像素级比较恒在 100% 附近
  （加 `--tolerance 40` 也还有 99.78%），一分信息都没有。所有涉及"这个蓝是不是原版那个蓝"的问题，
  现在都无法量化。
- **跨分辨率的像素级还原度**：尺寸不一致本身就有两位数的差异占比（实测同图缩放 21.38%），
  叠加放大后的 1px 错位，数值不可解释。
- **字号、字距、1–2px 级别的间距**：缩放后不可判定；这类问题只能同尺寸比。
- **"像不像原版"的单一分数**：跨页比较时 0.81、镜像对照 0.90、同产品两页 0.76，
  三个数字互相矛盾——标量没有绝对含义，只有同一页面、同一尺寸、同一状态下的**版本间相对变化**才有意义。
- **局部置换/搬动**：整页平均会把"某块挪了位置"稀释掉，必须看分区表与 diff 图。

### 5.3 下一步需要什么样的参照

1. **无夜间滤镜的原始截图**。这是当前最大的缺口：有滤镜就永远只能比结构。
   原版自己的 `grit-dashboard.png` 就是合格样本——说明这台机器上可以拍到无滤镜图。
2. **同分辨率、同 DPI、同缩放**。参照与实现都用 2560×1600、浏览器缩放 100%、`devicePixelRatio` 一致；
   否则先各自缩放到同尺寸再比，且必须把缩放罚分（≥20%）记在结论里。
3. **同页面、同状态**：同一页签、同一份数据（同一个 `.gps` 抓包）、面板展开/折叠一致、滚动位置在顶部。
   跨页比较（本次 4.1）只能验证工具，不能当还原度。
4. **成对采集**：同一版本改前/改后各一张，用 `--a 改前 --b 改后` 看增量；
   比"单张参照 vs 实现"的信息量高得多，也不受滤镜影响。
5. **去掉 OS 标题栏或统一窗口尺寸**：本次 `titlebar` 区 100% 差异里有一部分只是"我们没截标题栏"。
   用 CDP/Playwright 截页面（而不是截屏）能消掉这一层噪声。
6. 若必须用 2× 截图（Retina/缩放 200%），**成对**提供，不要一边 1× 一边 2×。

### 5.4 已知局限

- `--layout` 的 8×8 网格天生粗：镜像、局部互换都可能拿到 0.85+。需要更细时用 `--grid 16/24`，
  但判别力提升有限，最后仍要看矩阵与投影。
- 区域内统计是**矩形**的：元素边界不对齐时，区域会把相邻元素一起算进去（本次区域坐标按参照定，
  我们的元素位置本来就不同，所以这一层误差与滤镜误差混在一起）。
- alpha 不参与比较；半透明叠加的界面会漏掉透明度差异。
- 最近邻缩放不插值，边缘差异被放大而不是被平均——这是**故意**的（可复现、无实现依赖），
  代价是跨尺寸数值偏高。
- 输出里的 `%` 都是"占像素/通道满量程"的比例，不是相似度分数，不要反着读。
