# 桌面启动器（纯脚本 + Electron 外壳）

> 状态：**v0.1，双击可用**（2026-10-30 实测）。本文记录 `逆向/04_重实现/packages/desktop/`：
> 它把已经能跑的 `packages/app` 本地 Web 壳变成「双击就打开」的东西，并提供一份真正能起窗口的
> Electron 外壳。证据等级沿用 `_约定.md`：`[观察]` 指本仓库代码或本文实测到的结果，
> 不涉及对原版 NovAtel 的新取证。

---

## 1. 定位

两个入口，一个规则集：

| 入口 | 形态 | 依赖 |
|---|---|---|
| `Start-FieldStation.cmd` | 控制台常驻 + 默认浏览器打开 | 只要 Node ≥ 22.6 |
| `Start-FieldStation-GUI.cmd` | Electron 窗口 | Node ≥ 22.6 + 任意一份 Electron 运行时 |

两者都**只做三件事**：找一个空闲端口、把 `packages/app/src/server.ts` 作为子进程起起来、
等它真能应答再打开界面。它们不 import `packages/app` 的任何模块，也不写那个目录——服务端
是 `spawn` 出来的独立进程，边界只有 HTTP。

`[观察]` 启动器本身零依赖：Node 直接执行 `.ts`（类型擦除），没有 `node_modules`、没有构建步骤、
不访问网络。这条路径正是为了「本机 npm registry 不通」的情况留的。

## 2. 目录结构

```
packages/desktop/
  Start-FieldStation.cmd            纯批处理：找 node → 转发给 src/cli.ts（-Minimize 默认带）
  Start-FieldStation-GUI.cmd        纯批处理：找 node + 找 Electron → 跑 electron/
  package.json                      @nas-reimpl/desktop；start / gui / electron / test
  README.md                         一页速查
  src/
    launcher.ts                     全部逻辑：候选端口、单实例复用、子进程、日志、收尾
    cli.ts                          参数解析 + Ctrl+C/关窗口处理 + 面向人的输出
  test/
    launcher.test.ts                node:test，6 项
  electron/
    package.json                    独立 app 清单，main: main.cjs
    main.cjs                        spawn 服务端 → 轮询端口 → BrowserWindow → 退出时杀子进程
    preload.cjs                     contextBridge：只读信息 + 显式 quit
    README.md                       运行时探测顺序、Electron 8 兼容性、联网后升级
```

依赖方向（→ 表示 spawn，不是 import）：

```
Start-FieldStation.cmd ─► src/cli.ts ─► src/launcher.ts ─► node packages/app/src/server.ts
Start-FieldStation-GUI.cmd ─► electron/main.cjs ──────────► node packages/app/src/server.ts
```

`[观察]` 两个 `.cmd` 都是**纯 ASCII + CRLF**。不是洁癖：本机实测过把含「文件夹」的绝对路径
经 PowerShell 5.1 → `CreateProcess` 传给 `electron.exe` 时，路径被写成
`<仓库上级>\...`，Electron 认不出 app 目录就退回自带默认页（窗口标题就是那个
`github.com 打不开` 的错误页）。所以 GUI 的 `.cmd` 不把路径放进命令行：`pushd` 进 app 目录后
只传一个 `.`，argv 全是 ASCII。`Start-FieldStation.cmd` 里 `%ENTRY%` 仍是中文路径，实测 cmd.exe
直接调 node 没有问题（cmd 内部走 Unicode），但这条差异值得记住。

## 3. 用法

```powershell
.\Start-FieldStation.cmd                  # 双击等价：起服务 + 开浏览器 + 控制台最小化
.\Start-FieldStation.cmd -NoBrowser       # 只起服务（脚本/远程桌面用）
.\Start-FieldStation.cmd -NoMinimize      # 控制台保持可见，方便看日志
.\Start-FieldStation.cmd -Port 7790       # 首选端口

.\Start-FieldStation-GUI.cmd              # Electron 窗口版
```

| 环境变量 | 作用 |
|---|---|
| `FIELD_STATION_PORT` | 首选端口，被 `-Port` 覆盖 |
| `FIELD_STATION_NO_BROWSER=1` | 等价于 `-NoBrowser` |
| `FIELD_STATION_LOG` | 浏览器版日志路径 |
| `FIELD_STATION_NODE` | `node.exe` 完整路径（两个 `.cmd` 都认；找不到 node 时的救命稻草） |
| `FIELD_STATION_ELECTRON` | `electron.exe` 完整路径，优先于所有探测 |
| `FIELD_STATION_CAPTURE` | Electron 首次加载后把页面截图写到该 PNG，只用于验收 |
| `FIELD_STATION_LOG_DIR` | Electron 日志目录 |

退出方式（浏览器版）：**关闭控制台窗口**或 **Ctrl+C**。两种都先杀子进程再退。
`[观察]` Ctrl+C 之后 cmd 可能追问 `Terminate batch job (Y/N)?` ——这是批处理解释器在子进程
退出后问「要不要终止这个批处理」，此时服务其实已经停好、端口已经释放（见 §8.3），答 Y 关窗口
或答 N 回到提示符都无所谓。点窗口的 X 不会有这一步。

`[观察]` 第二次双击（服务已在跑）时，控制台会打印「复用在运行的实例」并**等你按任意键**再关，
不会再起一个 node；非交互场景（stdin 不是终端）则 3 秒后自动退出。

## 4. 端口选择与单实例

`[观察]` `src/launcher.ts` 的规则，按顺序：

1. **候选端口** = `首选 + i`，`i = 0..4`，共 5 个（默认 7788–7792），超过 65535 截断。
2. **先扫整个候选范围**找已有实例：对每个端口 `GET /api/health`，返回 `service: "nas-reimpl-app"`
   即认定为「我们的实例」。命中就直接复用它、打开它的 URL、**不启动任何进程**。
   扫全范围而不只看首选端口，是因为上一次启动可能已经因为 7788 被别的软件占了而漂到 7789。
3. 没有已有实例才依次 spawn：`node <server> --port <p>`。就绪判定有两条并发路径——
   子进程 stdout 里出现 `READY <port>`，或 `/api/health` 探活成功，先到先算；
   30 秒没等到就判失败。
4. 子进程先退出（典型是 `EADDRINUSE`，server.ts 自己会 `exit 1` 并打印
   `端口 7788 已被占用`）则记一条 `port 7788 unusable: ...` 并试下一个。
5. 5 个都失败 → 抛错，`.cmd` 打印错误并 `pause`，让人能读到原因。

`[观察]` 两个 `.cmd` 都不带锁文件：同时双击两次的极端情况下两边都可能探测到「没人」，
最后各自占一个端口（第二个会顺延到 7789）。这是已知竞态，见 §9。

## 5. 日志

| 文件 | 写入者 | 内容 |
|---|---|---|
| `%LOCALAPPDATA%\FieldStation\launcher.log` | `src/launcher.ts` | 启动参数、候选端口、每个端口的失败原因、`READY`、URL、浏览器、服务端 stdout/stderr、收尾 |
| `%LOCALAPPDATA%\FieldStation\electron.log` | `electron/main.cjs` | Electron/Chromium/Node 版本、同样的端口过程、服务端 stdout、`did-finish-load`、渲染进程 console 消息、退出 |

`[观察]` 两份日志都是「每行一个 ISO 时间戳 + 一段文本」，追加前先检查大小，超过 **200 KB**
就从最早的整行开始截掉（按字节切、在换行处切，不会切坏多字节字符），所以文件永远 ≤ 200 KB。
服务端子进程的每一行都会被加上 `[server]` 前缀转存，浏览器版的 `[console]` 前缀那行是控制台
最小化的结果。

## 6. Electron 外壳

### 6.1 运行时从哪来

`[观察]` 本机没有 `node_modules`、装不了 npm 包，但 **DaVinci Resolve 自带一份完整运行时**：

```
C:\Program Files\Blackmagic Design\DaVinci Resolve\Electron\electron.exe   v8.0.1
（同目录有 resources\ locales\ icudtl.dat snapshot_blob.bin *.dll，是完整发行版而不是残件）
```

`Start-FieldStation-GUI.cmd` 的探测顺序（命中即用）：

```
FIELD_STATION_ELECTRON
→ packages\desktop\node_modules\electron\dist\electron.exe      （npm i 之后才有）
→ %ProgramFiles%\Blackmagic Design\DaVinci Resolve\Electron\electron.exe
→ %ProgramFiles(x86)%\Blackmagic Design\DaVinci Resolve\Electron\electron.exe
→ %ProgramFiles%\DaVinci Resolve\Electron\electron.exe
→ PATH 上的 electron.exe
→ %APPDATA%\npm\node_modules\electron\dist\electron.exe
→ %LOCALAPPDATA%\Programs\electron\electron.exe
→ %LOCALAPPDATA%\electron\dist\electron.exe
```

全都没有时打印这份清单并 `pause`，不崩、不抛栈。

### 6.2 服务端子进程用哪个 node

`[观察]` Electron 8 自带 Node **12.13.0**，跑不了 `.ts`（类型擦除要 ≥ 22.6）。所以
`main.cjs` 的 `nodeCommand()` 分两支：

- 自带 Node ≥ 22.6（Electron ≥ 37）→ `ELECTRON_RUN_AS_NODE=1` + `process.execPath`，不需要外部 node；
- 否则 → `PATH` 上的 `node`，找不到就弹一个说明「装 Node 22.6+ 或用 `FIELD_STATION_NODE`」的错误框。

本机走第二支，`.cmd` 会把找到的 `node.exe` 写进 `FIELD_STATION_NODE`，实测命中
`C:\Program Files\nodejs\node.exe`（v24.18.0）。

### 6.3 与 Chromium 80 的兼容性（实测）

`packages/app/src/web/index.html` 里对 Chromium 80 有风险的写法逐项扫过：

| 特性 | 出现次数 | Chromium 80 |
|---|---|---|
| `?.` / `??` | 0 | 支持（80 起），但页面里根本没用到 |
| `??=` / `\|\|=` / `&&=` | 0 | 不支持（85+）——**未使用** |
| `Array.prototype.at` / `String.replaceAll` / `structuredClone` / `Object.hasOwn` | 0 | 不支持——**未使用** |
| 顶层 await / `type="module"` | 0 | 页面是经典脚本 |
| flex `gap` | 26 处 | **不支持（84+）** |
| `:focus-visible` | 2 条独立规则 | 不支持（86+），整条规则被丢弃 |

`[观察]` 实测结果：Electron 8 窗口里页面**无脚本报错**（`electron.log` 的 `console[..]` 行在
关掉 `enableRemoteModule` 之后为空），交互正常；**唯一可见差异是 flex `gap` 全部塌掉**——
logo 压住标题、`Convert格式转换` 这类「英文 + 中文」页签黏在一起、`开始转换` 按钮贴住下拉框。
截图：`%USERPROFILE%\AppData\Local\Temp\opencode\desktop-electron.png`（2019×1295，
`webContents.capturePage()` 抓的页面本身，不受其它窗口遮挡影响）。

修它只能在 `packages/app` 的 CSS 里加 `margin` 回退，那是别的任务的文件，**本任务不改**，
按约定记在这里。换成 `npm i` 装的新 Electron（Chromium ≥ 100）后这个差异自动消失。

### 6.4 有网之后怎么切

```powershell
cd 逆向/04_重实现/packages/desktop
npm i              # 装 devDependencies.electron（^33.2.0）
npm run electron   # = electron electron，跑本目录的 electron/
```

装好之后探测顺序第 2 条会先命中 `node_modules\electron\dist\electron.exe`，
`Start-FieldStation-GUI.cmd` 什么都不用改就换到新运行时。想钉版本就改
`package.json` 的 `devDependencies.electron` 再 `npm i`。

## 7. 与 `packages/app` 的边界

`[观察]`

- 启动器**不 import** `packages/app/**` 的任何模块，只用 HTTP 与它对话（`/api/health` 探活、
  其余交给浏览器/窗口）。
- 启动器**不写** `packages/app/**`，也不写 `逆向/00_来源/samples/**`；子进程继承
  `packages/app/src/paths.ts` 那套只读边界。
- 唯一共享的东西是约定，不是代码：`service: "nas-reimpl-app"`（探活用）、`READY <port>`
  （就绪信号）、`--port` 参数。这三样在 `server.ts` 里已存在，本任务没有改动它。
- 因此 `packages/app` 单独跑（`node packages/app/src/server.ts --port 7788`）与从启动器跑
  行为完全一致；启动器在跑时手动开一个 7788 的实例，第二次双击会自动复用它。

## 9. 已知限制与未解之处

- `[观察]` **双击竞态**：没有锁文件，两次几乎同时双击可能各自起一个实例（第二个顺延端口）。
  要彻底解决需要 `%LOCALAPPDATA%\FieldStation\instance.lock` + 校验存活，本轮没做。
- `[观察]` **Ctrl+C 后的批处理追问**：cmd 会问 `Terminate batch job (Y/N)?`。服务已经停好，
  只是多一次按键；关窗口没有这一步。
- `[观察]` **关窗口这条路**靠 libuv 把 `CTRL_CLOSE_EVENT` 映射成 `SIGHUP`，再由启动器杀子进程。
  测试里只能合成 `CTRL_C_EVENT`（Ctrl+C，已实测），`CTRL_CLOSE_EVENT` 无法程序化产生，
  所以「点 X」这条只有代码路径与 Electron 侧的关窗实测，没有独立的自动化用例。
  `[推断]` 即使 `SIGHUP` 处理失效，服务端子进程与启动器共享同一个控制台，控制台销毁时它自己也会
  被系统终止，因此不会留下占端口的孤儿进程。
- `[观察]` **控制台最小化**是 best-effort：内容是一个隐藏的 PowerShell 附着到启动器控制台后调
  `ShowWindow(SW_MINIMIZE)`。它在真实双击里生效（§8.2），在没有控制台的环境（计划任务、
  某些 CI）会静默跳过，日志里留一行 `minimize skipped: ...`。
- `[观察]` **Electron 8 的 flex `gap`** 见 §6.3：功能无损，排版有可见塌陷，修它要动 `packages/app`。
- `[未知]` Electron 8 在这台机器上会不会因为显卡驱动走软渲染，需要更多机器对比才能说清；
  当前 `capturePage` 与肉眼结果一致，暂不构成问题。

## 10. 复现清单

- `R1` 双击 `Start-FieldStation.cmd`，5 秒内出现服务：`/` 返回 200 且 `<title>` 为
  `野外台站智能体 · 重实现控制台`。 `[观察] §8.2`
- `R2` 默认浏览器自动打开 `http://127.0.0.1:<实际端口>/`；带 `-NoBrowser` 时不打开，
  日志出现 `browser skipped`。 `[观察] §8.1`
- `R3` 服务在跑时再次双击：日志出现 `reuse ... no new process`，进程表中 `server.ts` 仍然只有 1 个。
  `[观察] §8.3`
- `R4` 首选端口被别的程序占用时，实际端口顺延到下一个候选，日志出现 `port <p> unusable`。
  `[观察] §8.1`
- `R5` Ctrl+C 或关窗口后：`server.ts` 进程数归 0，`net.connect` 到原端口失败，
  日志出现 `stopped, port <p> released`。 `[观察] §8.3`
- `R6` `%LOCALAPPDATA%\FieldStation\launcher.log` 每行以 ISO 时间戳开头，文件永不超过 200 KB。
  `[观察] §8.1`
- `R7` `Start-FieldStation-GUI.cmd` 在没有 `node_modules` 的机器上也能起窗口：日志出现
  `launch electron 8.0.1 (chromium 80.0.3987.86) node 12.13.0` 与 `did-finish-load`。
  `[观察] §6`
- `R8` Electron 窗口关闭后：`node server.ts` 子进程被杀、端口释放、`electron.log` 出现
  `stopping server pid` 与 `quit exitCode=0`。 `[观察] §8.3`
- `R9` `node --test --test-force-exit "packages/desktop/test/*.test.ts"` 6 项全过。
  `[观察] §8.1`
