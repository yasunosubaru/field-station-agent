## 1. 职责

本子系统是 NovAtel Application Suite 的"改设备"的一半（另一半是 status 类只读视图）。

| 层 | 职责 | 证据 |
|---|---|---|
| 配置页（Config 面板 7 页） | 读设备当前配置 → 渲染表单 → 收集 diff → 逐条下发二进制命令 → 汇总 OK/ERROR | `01_解包/app/view/genericConfig.js:44-154` |
| 设备管理页 | 授权码、文件导出/删除/USB 拷贝、固件升级、重启/恢复出厂 | `01_解包/app/view/deviceRestart/deviceRestart.js:20-110` |

| 事件页 | 把 8 类遥测日志翻译成 Good/Moderate/Poor 事件，历史 + 导出 `.esl` | `01_解包/app/view/events/events.js:555-627` |
| 卫星跟踪页 | `SATVIS2`+`TRACKSTAT`(±`LBANDTRACKSTAT`) 合成二维/三维载噪比与锁定时间图 | `01_解包/app/view/satelliteTracking/satelliteTracking.js:110-186` |
| 干扰监测 (ITK) | `ITPSDFINAL` 流式拼帧 → Plotly 2D/3D 频谱；陷波/带通滤波器配置 | `01_解包/app/view/js/interferenceToolKit.js:4064-4211` |

只写本地 `userStore`，其余每个页面都是"读日志→改→下发二进制命令→等 `<OK/<ERROR`"的同一套骨架。

## 2. 入口与加载顺序

### 2.1 装载机制（tile 内嵌，不是独立窗口）

`[观察] 01_解包/app/jarvisInterface.js:4779-4816`：
`createComponent(componentName, tab, parent, isLongHornOrGIII)` 用
`$('#'+parent).load("./../"+componentName+"/"+componentName+".html")` 把页面 html **注入到主窗口的一个 div**，
没有 `BrowserWindow`。全应用只有一个 Electron 窗口（`01_解包/app/main.js:81,102`，
`win.loadURL('file://'+__dirname+'/view/html/index.html')`）。

变体选择（`jarvisInterface.js:4782-4791`）：

| 设备 | html 路径 |
|---|---|
| 普通 OEM | `./../<name>/<name>.html` |
| GIII (`featuresList.getIsGIII`) | `./../<name>/giii-<name>.html` |
| LongHorn (`getIsLongHorn`) | `./../<name>/lghn-<name>.html` |

各页面的容器 id（`jarvisInterface.js:945-972`）：
`#config-pos-<tab>`、`#config-ports-<tab>`、`#config-log-<tab>`、`#config-align-<tab>`、
`#config-span-<tab>`、`#config-radio-<tab>`、`#config-gnss-<tab>`、`#config-spoofing-<tab>`；
GIII 只保留 `#config-log-<tab>` 一个 Tab（`jarvisInterface.js:973-999`）。

`[观察]` 注入完成后立刻 `eval(componentName).processLanguage(tab)`（`jarvisInterface.js:4816-4841`），
并对 `spanConfig`/`alignConfig`/`positionConfig` 做**按 tab 后缀化的 id 改写**（`4834-4898`），
原因是这些页面里写死了 `id="imu-X-value"` 之类，多设备共存必须去重。副作用：`spanConfig` 的
`for=`/`id` 被加上 `-<tab>`，所以查 DOM 必须带 tab 前缀。

**配置页本身不是独立窗口**；`terminalConsole`（`jarvisInterface.js:2416`）、`events`
（`:1655`）、`satelliteTracking`（`:1501`，`createComponent(..., "tile-"+index+"-"+tab)`）
也都是内嵌到 tile / 侧栏里的组件。

## 3. 数据结构（逐字段）

### 3.1 全站统一的"三态"数据模型

每个配置页都有同构的三个字典（以 portConfig 为例，`01_解包/app/view/portConfig/portConfig.js:2`）：

| 名称 | 类型 | 语义 | 写入者 | 清空者 |
|---|---|---|---|---|
| `dh_xxxData[tab][msgID]` | `Object` | 设备**原始**回包（按 msgID 分桶，再按 port/field 分桶） | `dc_updateData` | `resetDataObject(tab)` |
| `dh_xxxDefaultData[tab][msgID]` | `Object` | 上电时快照 = "默认值/基准值"，用于算 diff 和字段回填 | `dh_createDefaultData` | 同上 |
| `dh_xxxChangedData[tab][msgID]` | `Object` | 用户改动（稀疏，只存差异） | `dh_updateChangedData(...)` | Apply/Cancel 后清空 |

`[观察]` diff 的判定方式一律是"用户值与 DefaultData 相同就删掉这个 key"，
例如 `gnssConfig.js:97-99`：
`(defaultData.angle !== parseFloat(cur)) ? changed.angle = parseFloat(cur) : delete changed[msgId]`。
因此 `isDataChanged(tab) = Object.keys(changed).length !== 0`（`gnssConfig.js:130-140`、
`portConfig.js:4708`、`spanConfig.js`、`networkingSettings.js:1594-1600`）。

### 3.2 命令帧参数对象（`parameter`）

`[观察] 01_解包/app/view/genericConfig.js:160-164`

```
new parameter(len, typ, val)  // len=字节数, typ='enum'|'ulong'|'ushort'|'float'|'double'|'string'|'char'|'boolean', val=值
```

各类型的 `len` 一律由调用方显式给出（`4`/`2`/`1`/`8`），代码**不做自动推导**。
数据映射的书写形式固定为 `[{字段名:[值, 类型, 字节数]}, ...]`，例如
`portConfig.js:1441-1450`（LOG 命令）：

| 字段 | 类型 | 字节 | 说明 |
|---|---|---|---|
| `port` | enum | 4 | 端口枚举，`THISPORT_30`=222（`NovatelIdConstants.js:2088-2148`） |
| `messageID` | ushort | 2 | 十六进制转十进制的日志 ID，如 `BESTPOS`=42 |
| `messageType` | char | 1 | 格式位（见 §5.4） |
| `reserved` | char | 1 | 恒 0 |
| `trigger` | enum | 4 | `ONNEW`0/`ONCHANGED`1/`ONTIME`2/`ONNEXT`3/`ONCE`4/`ONMARK`5/`ONALL`6 |
| `period` | double | 8 | 秒；非 ONTIME 时被强制 0（`portConfig.js:1415-1416`） |
| `offset` | double | 8 | 恒 0 |
| `hold` | enum | 4 | `NOHOLD`0/`HOLD`1，缺省 `"HOLD"`→1 |

### 3.3 各页关键结构

**portConfig**（`portConfig.js:2-26`）：以 msgID 为一级键，二级键是端口名字符串；
`connectedComPort[tab] = {comPort, discardResponse}`（`:23`、`:4697`）用于识别"用户当前连的那个串口"——
若把该口 interfacemode 改成 NONE/NONE，回包会断，所以 `discardResponse=true` 且 loader 时间从 8 s 拉到 20 s（`portConfig.js:2348-2351`）。

**positionConfig**：`dh_positionConfigChangedData[tab]` 里除 msgID 桶外，还塞了**非 msgID 的两个裸键**
`surveyTime`、`accuracy`（`positionConfig.js:1179-1180`），这是全站唯一的例外，读取时必须特判。

**spanConfig**：`dh_spanConfigChangedData[tab][CONNECTIMU_MSGID]` 是**单对象**（不是按 port 分桶），
`IMUPort`/`IMUType`；`SETINSROTATION_MSGID` 才按设备（`IMU`/`ANT1`/`ANT2`/`USER`）分桶（`spanConfig.js:3017-3069`）。

**loggingConfig**：`storageSelected[tab]` ∈ {`Onboard`,`LocalFile`}；目的地端口由它决定——
`FILE`（板载）或 `<connectedPortName>_29`（本地文件，虚拟口 29）（`loggingConfig.js:4215-4219, 2958-2990`）。
`desktopFileSettings[tab] = {maxFileTime, diskFullAction}`（`:2556-2562`）。

**radioConfig**：`radioConfigGenericData[tab]` 存轮询状态机
`{currentSatelDetectIndex, radioDetectionStarted, satelStatusCheck, satelStatusDefectCheck, isSatel4ConfigCommandSent, isSatel9ConfigCommandSent}`（`:338-341, 936-937, 973-974`）。
`satelPorts` 是探测顺序数组，最多试 3 个口（`currentSatelDetectIndex < 2`，`:385-387`）。

**satelliteTracking**：`dh_satelliteTrackingData[tab][msgID]`；双天线时 `TRACKSTAT` 的第二份存在
`[msgID+"_1"]`（`satelliteTracking.js:127-136`）。`trackingUIObject[tab]` 保存
`{antenna:PRIMARY|SECONDARY, constellation, graph:carrierToNoise|lockTime, sortby:trackingprn|elevation, gridLines, elevationMask, highestLowestValues}`
（默认值 `:90-98`）。`constellationMap` 做显示名映射：`GLONASS→GLO`、`GALILEO→GAL`、`BEIDOU→BDS`（`:99-108`）。

**events**：`EventHandlerObject[tab][eventId] = {startTime, state, alive, description, actualStr, endTime, freqValue}`（`events.js:1737-1757`）；
`eventId = <毫秒时间戳>_<事件短名>`（`alive` 用开始时间，已结束用结束时间，`:1722-1727`）。
`description` 是 `data-lang-*` 字符串而不是文案，渲染时才 `__(events_data_lang_map[description])`（`:1742`）。

**interferenceToolKit**：`combinedLogResponseData[tab]` 拼接多帧 PSD
`{[i]:{frequency,sample}, noofSamples, tab}`（`interferenceToolKit.js:4116-4127`）；
`filterTraces[tab][idx].traceData = {x:[Hz],y:[dB]}`（`:3704-3713`）。

### 3.4 端口枚举（byte 级，两套！）

`commandsAndEnums` 里每个命令都自带一份 `port` 表，**数值互不相同**，不能混用：

| 命令 | 表位置 | COM1 | FILE | THISPORT_30 | 备注 |
|---|---|---|---|---|---|
| `log` / `unlog`（LOG/UNLOG 消息的 port 字段） | `NovatelIdConstants.js:2088-2148`、`:2028-2075` | 32 | 224 | 222 | 含 `COM1_29`=61、`BT1_30`=6590 等虚拟口 |
| `serialconfig` / `interfacemode`（配置命令的 port 字段） | `:1368-1432`、`:1579-1600` | 1 | 7 | 6 | `ALL`=8 |
| `unlogall` | `:1974-1990` | 32 | 224 | 222 | 与 log 表同构 |

`[观察]` `NovatelIdConstants.PortIdentifierConstants.THISPORT_30 = 222`（`:714-717`）
与 LOG 表一致，但与 `serialconfig` 表的 `THISPORT=6` **不一致**——写复现器时必须按"这条命令自己的表"取值。

## 5. 报文/协议细节

### 5.1 二进制命令头（28 字节）

`[观察] 01_解包/app/controller/frameCommand.js:6-56, 85-99`

| 偏移 | 长度 | 字段 | 固定值/来源 |
|---|---|---|---|
| 0-2 | 3 | Sync | `AA 44 12` |
| 3 | 1 | header length | `0x1C` = 28 |
| 4-5 | 2 | message ID | uint16 **LE**，= `commandsAndEnums[name].messageId` |
| 6 | 1 | message type | 恒 `0x00`（命令请求） |
| 7 | 1 | port address | 恒 `0xDE` = 222 = `THISPORT_30` |
| 8-9 | 2 | message length | 仅**参数体**长度（不含头、不含 CRC） |
| 10-11 | 2 | sequence | 0 |
| 12 | 1 | idle time | 0 |
| 13 | 1 | time status | 0 |
| 14-15 | 2 | week | 0 |
| 16-19 | 4 | ms | 0 |
| 20-23 | 4 | receiver status | 0 |
| 24-25 | 2 | reserved | 0 |
| 26-27 | 2 | receiver sw version | 0 |
| 28.. | n | 参数体 | 顺序拼接 |
| 28+n..+3 | 4 | CRC32 | 见 §5.3 |

**端口地址恒为 222 是本设计的关键约定**：所以任何"给某串口发 LOG"都必须把端口写进**参数体**，
而不是改头里的 `port address`。

### 5.2 参数体的类型写入与 4 字节对齐

`[观察] frameCommand.js:59-99`（预对齐）、`:101-138`（写入）

- 字符串：先补 `\0` 到长度为 4 的倍数；若已是 4 的倍数且末字符不是 `\0`，**再加 4 个 `\0`**
  （`:63-75`）——即定长字段后总有一个 4 字节全零的"结束符块"，复现时漏掉会整体错位 4 字节。
- `enum`/`ulong` → `setUint32 LE`；`ushort` → `setUint16 LE`；`char` → `setUint8`；
  `float`/`double` → IEEE754 LE；`short`→`setInt16`；`novatelchar`→逐字节写 charCode。
- **`boolean` 类型没有实现分支**：`fill_command_request` 里只列了
  `enum/ulong/short/ushort/float/double/novatelchar/string/char`（`:101-137`），
  但 `positionConfig.js:389-390` 用 `{bool1:[0,'boolean',4]}` / `{bool2:[0,'boolean',4]}` 组 `RTKANTENNA`。
  `[推断]` 这两个字段实际停在 `ArrayBuffer` 初值 0，只占位不写入 —— 因为两处调用方传的都是 0，
  结果与"写入 0"等价，但**若将来要传 true 就会静默失败**。

### 5.3 CRC32（非标准 zlib 变体）

`[观察] 01_解包/app/controller/crc.js:65-87`：`ulCRC` 初值 `0`，循环 `table[(crc ^ byte) & 0xFF]`
+ 右移 8 位查表，**没有 `0xFFFFFFFF` 初值、也没有结果取反**。表本身是标准反射多项式
`0xEDB88320` 的 256 项（`crc.js:2`）。
`[推断]` 因此结果与 `zlib.crc32` 不同；范围是**整帧（含 28 字节头）**（`frameCommand.js:97`
在 `binaryCommand` 最后一步调 `req_crc(buffer)`，此时 buffer 已含参数体）。
CRC 以**小端 4 字节**附在帧尾（`crc.js:46-59` 逆序回填）。
算例：`SAVECONFIG`(id=19) 无参数 → 帧长 32，前 28 字节为 `AA 44 12 1C 13 00 00 DE 00 00` + 18 个 0，
末 4 字节为该 28 字节的上述 CRC32。

### 5.4 LOG 的 messageType 编码（页面的"格式"三选一）

`[观察] portConfig.js:1377-1395`（发送）、`:1348-1366`（UNLOG 同规则）

| UI 选项 | 无 `_1` 后缀 | 有 `_1` 后缀 | 含义 |
|---|---|---|---|
| `Binary` | 0 | 1 | 二进制；`_1` 表示带时间 |
| `ASCII` | 32 | 33 | ASCII |
| `Abbr ASCII` | 64 | 65 | 短 ASCII |

`_1` 后缀来自 LOGLIST 里的同名日志（同一消息 ID 的第二种格式），
`unlogMessage` 会先把名字里的 `_1` 去掉再查 ID（`portConfig.js:1350-1353`）。
`[推断]` `+1` 是 NovAtel 的 "time tag 使能" 位，代码只用了这一个位组合，没有其他位操作。

### 5.7 ASCII 帧（终端/加载配置共用的组帧器）

`[观察] frameCommand.js:186-243`，对一行 `LOG BESTPOS ONCHANGED`：

1. 多空格压成一个（`:188`）；`LOG`/`UNLOG` 后若第二个 token 不是合法端口名
   （查 `NovatelPortNamesList`，`:139-153`），**插入 `thisport`**（`:206-210`）；
2. 前缀 `\r\n#` + 命令名 + `,THISPORT_30,0,0,UNKNOWN,0,0,0,0,0;` + 其余参数（`,`
   连接）（`:220-230`）；
3. CRC 计算范围 = `tempreq.substring(3)`（**跳过 `\r\n#`**）（`:231`），转 8 位十六进制小写补零（`:232-237`）；
4. 追加 `*<crc>\r\n`（`:238-240`）。

算例：`LOG BESTPOS ONCHANGED` → `\r\n#LOG,THISPORT_30,0,0,UNKNOWN,0,0,0,0,0;BESTPOS,ONCHANGED*<crc8>\r\n`。

### 5.8 SOFTLOADDATA（固件升级）原始帧

`[观察] 01_解包/app/view/deviceUpdate/deviceUpdate.js:309-353`

- 头：`AA 44 12 | 28 | msg_id=1218 | port=222`（注意这里**手写**，`hdr_len=28`、`msg_id=1218` 直接赋常量）；
- 体：`offset(uint32) + data_len(uint32) + data(bytes)`；

### 6.2 回包判定（核心状态机）

`[观察] jarvisInterface.js:3922-3930`：解析层按**头部第 6 字节**（`data.getUint8(6)`，即 message type）
分流——`!=0` 视为**命令应答**，送 `genericConfig.commandResponseHandler(logData,msgID)`；
`==0` 视为**日志数据**，继续走各日志解析。

`[观察] genericConfig.js:44-154` 的汇总算法：

1. 对每个 feature（如 `portConfig`）维护 `cmdReqLst[feature][msgID] = {values:[], length:n}`，
   `placeCmdReq` 每调一次 `length++`（`:13-24`）；
2. 收到应答把 `logData.Commanddata` 压入 `values`（`SAVECONFIG` 除外，`:46-51`）；
3. 只要某 msgID 的 `values` 里 `ERROR` 的出现下标 ≤ `length-1` → 整体 `ERROR`；
   若出现 `UNKOWN`(0) → 本 feature 尚未完成（`flag=false`，不回调）；
4. 全部完成才调 `<page>.handle*CommandResponse(overallResponse, tab)`（`:85-152`）。

`[观察] commandResponseEnums`：`UNKOWN=0 / OK=1 / ERROR=2`（`NovatelIdConstants.js:2650-2655`）。
所以"没回包"= 停在 0，永远不会误判成成功——这是该状态机能收敛的原因。

`[推断]` 由此推出各页面的超时语义：`handle*CommandResponse` 里普遍用
`clearTimeout + setTimeout(2000~2500ms)` 收尾（`portConfig.js:2304-2313`、
`spanConfig.js:3344-3367`、`alignConfig.js:1055-1058`、`radioConfig.js:1028-1032`），
即**回包后等 2~2.5 s 的静默期再关 loader**，让后续零散应答也进来。

### 6.8 satelliteTracking 解析

`[观察] satelliteTracking.js`

- 入站：`TRACKSTAT`(83)、`SATVIS2`(1043)、`CHANCONFIGLIST`(1148)、`RXSTATUS`(93)、
  `LBANDTRACKSTAT`(1201)、`LBANDBEAMTABLE`(1718)、`BESTPOS`(42)、六个 `*ECUTOFF`(50/1114/735/2134/1350/1582)。
- `SATVIS2` 按星座拼装：`tabsatsdata[tab][system] = 整个报文`，**只有 `sequence == 0`（末片）才转表**
  （`:142-153`）；星座码 → 名称用 `NovatelIdConstants.satvisConstellationMap`：0 GPS、1 GLONASS、2 SBAS、
  5 GALILEO、6 BEIDOU、7 QZSS、9 NAVIC（`NovatelIdConstants.js:77-86`）。
  每颗星取 `satelliteId → prn`、`azimuth`、`elevation`、`health`（`:1676-1690`）。
- `TRACKSTAT`：逐通道，`numberOfChannels==0` 直接返回；`channelTrackingStatus`（32 位整数）按位切：

| 字段 | 位区间 | 换算 | 证据 |
|---|---|---|---|
| 信号类型 | bit 6..11 | `parseInt(bin.slice(6,11),2)` → `ConstellationWiseSingalEnums[星座][值]` | `:1704-1714` |

| 是否参与解算 | `chtr & 0x1f ∈ {0x04,0x0b}` | 布尔 | `:2653-2656` |

  `get_slicedbytes` 先把值 `toString(2)` 左补零到 32 位再 slice（`:1720-1735`）——补零是必须的，否则高位切片会错位。

### 6.9 interferenceToolKit 流式拼帧

`[观察] interferenceToolKit.js`

- 入站靠 `jarvisInterface.js:4113-4141` 分发：`ITPSDFINAL`(1968)→`updateChart`、`ITFILTTABLE`(1991)→`updateFilterTable`、
  `ITSPECTRALANALYSIS`(1967)→`updateSpectralAnaylisStatus`、`ITFRONTENDMODE`(2039)、
  `ITBANDPASSBANK`(2022)、`ITPROGFILTBANK`(2023)、`CHANCONFIGLIST`(1148)、`ITDETECTCONFIG`(2143)。
- **拼帧规则**（`:4064-4159`）：`noofSamples` 为本次片长度，`sequenceId` 为片号；
  `sequenceId != 0` 时把样本追加到 `combinedLogResponseData[tab][上一长度 + i]`；
  `sequenceId == 0` 表示**最后一片**，此时才 `updateLineChart()` 或 `prepareSChartData()+updateSurfaceChart()`（历史模式）。
  重复片（`previousSequence[tab] === sequenceId`）直接丢弃。
- FFT size 从 `status` 字段位 8..10 取：`(spectraldata.status & 0x0700) >> 8`，与当前选择不一致时
  重启光谱命令并重画（`:4071-4080`）。
- 2D 图：`x = sample.frequency`（Hz），`y = sample.sample`（dBm，**不做对数换算**，直接用报文值），
  Y 轴范围自动 `[min-10, max+10]`，变动超过 10 dB 才重设以免抖动（`:3521-3561`）。
- 3D 历史图：`maxInterval=1`（分钟）、`updateInterval=2`（秒）→ 30 帧
  （`:1-2`、`:4170-4186`）；满 30 帧后把 `currentPSDUpdateInterval` 强制设回 `"2000"`、`currentFFTSize="2K"`，
  串口连接时降为 `"1000"`/`"1K"`（`:4201-4207`）。
- 命令：光谱参数走 `ITSPECTRALANALYSIS`（`:3182-3233`，关闭时发**纯 ASCII** `itspectralanalysis off`，`:3235`）；
  陷波 `ITPROGFILTCONFIG`(2000)（`:3235-3284`）；带通 `ITBANDPASS BANKS`(1999)（`:3285-3326`）；
  前端模式 `ITFRONTENDMODE`(2039)（`:3327-3349`）；总开关 `ITDETECTCONFIG`(2143)
  **成功后再补一条 `SAVECONFIG`**（`:5863-5869`）。
- 滤波器只允许 `PF0`/`PF1` 两个可编程滤波器，都被占用返回 `"NONE"`（`:3136-3167`）；
  带宽选项 0.15 / 0.5 / 1.0 MHz（`:1563-1565`）。
- 日志请求原文：`log thisport_30 itfilttableb onchanged 0 0 hold`（`:5795`）、
  `log thisport_30 chanconfiglistb once 0`（`:5800`）。
- **告警阈值**：ITK 自身没有数值阈值。`[观察]` 全文件只有一个 `serial-itk-warning-msg`
  提示（串口带宽不足，`:993-996`）；真正的"是否检测到干扰"由接收机在 `ITDETECTSTATUS` 里判，
  `events.js:629-663` 只做布尔聚合（`detectionType` 命中即 `itkDetected=true`）。
  `[未知]` 接收机侧的判定门限（多少 dBm 算干扰）不在本包代码里，见 §9。

**A. 装载与入口**

**B. 组帧与协议**

- `R7` 二进制命令头 28 字节，sync `AA 44 12`，`hdr_len=0x1C`，msgid/message length 为**小端 uint16**，byte 6（message type）=0，byte 7（port address）恒 `0xDE`(222)。`[观察] frameCommand.js:6-56`

- `R14` LOG 的 `messageType`：Binary=0、ASCII=32、AbbrASCII=64，名字带 `_1` 时各 +1。`[观察] portConfig.js:1377-1395`
- `R15` `period` 在非 `ONTIME` 触发时被强制置 0，`offset` 恒 0，`hold` 恒 `HOLD`(1)。`[观察] portConfig.js:1415-1416, 1439`
