# 07 国际化与安装/更新

> 覆盖范围：`view/languageSupport/*`、`view/languageSettings/*`、`view/json/*`、`view/js/help.js`、
> `updater.js`、`create-shortcut.js`、`view/autoUpdates/*`、`view/updateApplication/*`、
> `shortcuts/Unzip/*`、`LoadConfig.bat`、`Apps/`、`view/addApplication/*`（仅注册相关部分）、
> `model/userStore.js`、`model/serverModel.js`、`controller/serverConnectV2.js`、`main.js`。
> 全部为 NovAtel Application Suite 2.11.0（`package.json:3`）ASAR 解包产物。

---

## 1. 职责

本子系统负责五件事，彼此只在「读写 userData」和「重启应用」两处耦合：

1. **界面文字的多语言替换**：8 份静态词典 + `jsIn` 全局字典 + `data-lang-*` 属性标记，
   通过 79 处 `processLanguage()` 完成刷新。
2. **帮助系统**：一份 1.3 MB 的内联 HTML 帮助正文（`view/js/help.js`），按当前组件 id
   滚动定位到对应锚点。
3. **在线更新**：从 AWS API Gateway 取版本元数据 → 从 S3 取文件清单并下载到 `<root>/nextversion`
   → Windows 生成 `updater.bat` 并执行 / Linux 覆盖 AppImage 后重启。
4. **安装与卸载**：Squirrel 事件桩（`main.js`）、快捷方式创建（Windows 用 `windows-shortcuts`，
   Linux 用 `.desktop` 文件）。
5. **非核心应用（NonCore App）注册**：把第三方应用的前端资源合并进 `app.asar`（Windows）
   或重新打包 AppImage（Linux），并在 `userSettings.json` 里登记版本。

`[观察]` 本子系统不含任何 GNSS 报文解析，也不参与串口/网络通信。

## 3. 数据结构

### 3.1 语言文件的三段式结构

8 份语言文件结构完全一致，以 `en.js` 为例：

```
1: //English  Language template        ← 8 个文件全都是这句（复制粘贴残留）
2: var Language = Language || {};
3:
4: Language.EN = {                     ← 对象名 = 语言代码大写
5:     'CURRENT_OPMODE' : 'Current Operating Mode',
...
1923: jsIn.addDict(Language.EN);        ← 最后一行，把词典塞进全局 _dict
```

`[观察]` 三个固定锚点：第 1 行是过期注释、第 4 行是对象头、最后一行是 `addDict`。
`[观察]` 属性是**扁平**的 `'KEY': '字符串'`，没有嵌套对象、没有数组；个别值用 `+` 拼接多段字符串
（`en.js:1916-1918` 的 `LUCIAD_GRAPHICS_WARNING_CONTENT`）。

### 3.2 命名规则（全部为观察所得）

| 规则 | 例 | 反例（说明规则不是绝对的） |
|---|---|---|
| 键名大写 + 下划线分词 | `CURRENT_OPMODE`、`SELECT_OPMODE` | `Install_Relaunch`（`en.js` 内混合大小写）、`LBANDNONSTATUSRED`（无分词） |
| 缺键值直接复用键名 | `LUCIAD_GRAPHICS_WARNING_TITLE` | — |
| 占位符写 `%1`/`%2` | `VERSIONAVAILBALE: "%1 is now available,you have %2."` | 部分键无占位符却仍被 `.replace()` 调用（无害） |
| 允许 HTML 片段 | `LUCIAD_GRAPHICS_WARNING_CONTENT` 含 `<br><br>` | — |

`[观察]` 拼写错误被当作正式 key 使用：`VERSIONAVAILBALE`（`en.js` 尾部，updateApplication 使用）、
`RECEIVER_OPERIONAL_STATE`（`jarvisInterface.js:980`）。复现时必须原样保留，否则该文案永远显示键名。

缺失统计（以 `en.js` 为基准）：

| cn / de / eg / es / fr / pt | **45**（完全相同的一组） | 2：`AUTHORIZATIONS`、`NTRIPLINKRED` |

`[观察]` 那 45 个缺失键集中在四组功能上（分组为本文的归纳，`[推断]` 依据是它们同时缺席于 6 份
同源词库、且对应的 UI 模块在源码里较晚出现）：

- 非核心应用安装器：`UPDATEAPP`、`SELECTUPDATEAPPTEXT`、`UNABLE_FETCH_AWS`、`VERSIONAVAILBALE`、
  `RELEASENOTES`、`UPDATINGAPP`、`NONCORE_APP_VERSION_MSG`、`NEW_NONCORE_APP_VERSION_AVAILABLE`
- 型号/授权：`ACTIVATE`、`ACTIVE_MODEL`、`CHANGE_MODEL`、`DETECTED_MODEL_INFO`、`MODEL_INFO`、
  `AUTHORIZATION_MANAGEMENT`、`AUTH_EXPIRY_DATE`、`PERMANENT`、`APP_NOT_AVAILABLE`
- 定位配置 MSM：`RTCMV3_MSM`、`MSM1`…`MSM7`
- 车辆设置：`ALL_WHEEL_ACKERMANN`、`ARTICULATED_FRONT/REAR`、`ZERO_TURN_FRONT/REAR`、`SKID`、
  `VS_QUESTION_1..4`

结论：**任何非英语界面下，非核心应用安装器整屏、型号授权区、MSM 选择项、车辆设置向导都是英文**。
`[推断]` 推理链：这些模块调用 `__('UPDATEAPP')` 等 key（`updateApplication.js:200`、
`addApplication.js` 多处），`jsIn.translate` 在 `_dict` 无此键时返回键名本身（`jsin.1.2.min.js:9`），
而这些键只有 `en.js` 提供 —— 但 `en.js` 的词典在启动时就已 `addDict` 过，所以实际显示英文原文而非
`UPDATEAPP` 字样，前提是「英文字典先加载、后加载的语言不覆盖它」。该前提成立（见 §5.3 回退链）。

## 4. 接口清单

### 4.1 `jsIn` / `__`（`view/css/jsin.1.2.min.js:9`，单行压缩）

| 成员 | 签名 | 语义 |
|---|---|---|
| `jsIn.addDict(dict)` | `(object) => void` | `for(key in dict) _dict[key]=dict[key]`。**不清空、不递归、不校验**，后写覆盖先写 |
| `jsIn.translate(text, param)` | `(string, string[]?) => string` | 取 `_dict[text]`；取不到时若 `_notFoundError` 为 false 则**返回 text 本身**，否则 `throw "No entry found for key {...}"`。`param` 存在时用 `{%1}`,`{%2}`… 正则替换 |
| `jsIn.showNotFoundError(show)` | `(boolean?) => boolean` | 开关上一条；全库无调用 → 恒为 `false` |
| `window.__` | `= jsIn.translate` | 全应用唯一翻译入口 |

### 4.2 语言子系统（`jarvisInterface.js`）

### 5.4 版本比较算法（`serverModel.js:193-230`）

```
isUpdateAvailable(currentVersion, newVersion):
  if newVersion == undefined            → false
  cRelease = currentVersion.split('-')      // 丢掉 -beta 之类后缀
  nRelease = newVersion.split('-')
  cVer = cRelease[0].split('.') 取 [0],[1],[2]
  nVer = nRelease[0].split('.') 取 [0],[1],[2]
  if (cVer[0] > nVer[0])  → false           // ← 字符串比较，见下
  for i in 0..2:
      if (Number(cVer[i]) < Number(nVer[i])):
          serverModel.newVersion = newVersion   // 副作用
          return true
  return false
```

要点与边界：

- 只比前三段，第四段（build 号）被忽略。
- `cVer[0] > nVer[0]` 是**字符串**比较（`cVersionRMM` 来自 `split`）。当主版本位数不同时会错：
  当前 `9.1.0`、新版 `10.0.0` 时 `"9" > "10"` 为 `true` → 直接返回 `false`，
  **跨 10 的升级永远不提示**。当前 `2.11.0` 不受影响。
- 段数不足时 `Number(undefined)` 为 `NaN`，所有 `<` 均为 false → 返回 `false`（不提示更新）。
- 唯一写入 `newVersion` 的地方就是这个函数，`autoUpdates.updateFailed()` 用它拼错误文案
  （`autoUpdates.js:375-379`），比较函数返回 `false` 时该值保持 `0`。

### 5.5 下载完整性（没有校验和）

`GetObject`（`369-481`）只做两件事：

- **长度校验**：`finish` 时 `expectedBytes !== null && receivedBytes !== expectedBytes` → `reject('Download incomplete')`
  （`424-435`）。`expectedBytes` 来自 `response.ContentLength`。
- **停滞检测**：15 s（`const timeout = 15 * 1000`，第 401 行）无 `data` 事件即销毁流并 `reject('Download stalled')`。

`[观察]` 全文件检索 `sha|md5|checksum|ETag|hash` **无任何命中**。S3 对象被完整下载后直接解压
（`unzipFile`/`unzipFileLinux`，`495-514`），不验签、不比对哈希。这是可复现实现里最需要注意的
安全缺口：中间人只需提供一个长度正确的 zip 即可。

### 5.6 `data-lang-*` 属性的完整语义

**语义**：属性本身**不携带任何信息**，只是一枚「这个节点属于哪个翻译槽」的标记；值恒为空字符串
（`attr(name, "")`）。没有任何代码读取 `data-lang-*` 的值。

**没有通用替换器**：全库检索不到「遍历 DOM 找 `data-lang-` 前缀 → 去前缀 → 查表」的代码。
唯一对属性名做解析的地方是两处**删除**逻辑（`genericView.js:600,1041`）和一处
**生成**逻辑（`genericView.js:281`）。真正的替换是每个模块在 `processLanguage()` 里逐条写死的：

```js
$('[data-lang-version-available]').html(__("VERSIONAVAILBALE"))
$('[data-lang-release-notes]').html(__("RELEASENOTES"))
// updateApplication.js:694-695
```

**属性名与键名的对应**：绝大多数是「键名小写、`_` 换 `-`」（`SPOOFING_TITLE` → `data-lang-spoofing-title`），
但**并不保证**，存在三类偏差：

| 偏差类型 | 例 |
|---|---|
| 键名含 `-`，属性原样保留 | `key = "PORTSTATUS-COMPRED"` → `data-lang-portstatus-compred`（`portStatus.js:502`） |
| 属性名与键名不同源，需人工配对 | `data-lang-auth-invalid` ↔ `INVALID_AUTHORIZATION_CODE`；`data-lang-model-invalid` ↔ `MODEL_INVALID_FOR_THIS_RECEIVER`（`genericView.js:267-268` ↔ `1109-1110`）；`data-lang-start-pb` ↔ `START`（`playback.js:1777`） |
| 同一属性挂在不同键上 | `data-lang-height-msl` / `data-lang-height-ellipsoidal` 由运行时按单位切换（`jarvisInterface.js:1951-1957`） |
| 自动派生时**不换下划线** | `genericView.js:281` 生成 `data-lang-auth_expiry_date` |

**批量替换算法（实际形态）**：

```
切换语言时（applyLanguageChanges, jarvisInterface.js:1361-1373）
  $.getScript(filePath) 成功
   → deviceTileTranslation()
   → statusComponentsProcessLanguage(tab)      22 个模块
   → configComponentsProcessLanguage(tab)      12 个模块
   → welcome / playbackControl / convert / addApplication / updateApplication / genericView.basicpopupProcessLanguage
每个 processLanguage 内部形如：
  $('[data-lang-x]').html(__('KEY'))       // 全局选择器 → 会命中所有 tab 的同名节点
  $('#'+tab+' [data-lang-y]').html(...)    // 或限定在某个 tab 内
```

**嵌套节点**：`.html()` 会**整体替换**匹配节点的 innerHTML，所以被替换节点内部的子元素会被丢弃。
为此代码在使用 `.html()` 前必须保证子结构可重建（例：`updateApplication.js:264-268` 先把
`<div class="app-loading-progressStatus">` 与 `<p data-lang-loading-text>` 一起拼进字符串，
后续 `$('#'+app+'app .app-download-update-text').text(...)` 再单独改子节点）。
`[观察]` 因此**不能**用「只遍历叶子节点」的通用算法替换这套实现。

**动态创建节点的补翻**：两条并行手段——

1. 创建时立刻 `__()` 填好文本（例：`genericView.js:281` 之后 `newBtn.attr(...)`；`updateApplication.js:449-460`
   建卡后立即 `.html(__("VERSIONAVAILBALE").replace(...))`）。
2. 同时挂上 `data-lang-*`，等下一次 `processLanguage()` 再翻一遍。
   例：`autoUpdates.js:148-150` 先 `removeDataLangAttr("#loader-text-id")` 再
   `attr("data-lang-applying-updates","")` 再直接写 `textContent`，三步保证「当前文案即时生效 +
   下一轮语言切换能找回来」。

**属性选择器作用域**：`$('[data-lang-x]')` 未限定 tab，因此在多 tab 场景会命中所有 tab；
`$('#'+tab+' [data-lang-x]')` 才是单 tab。两种写法在代码中混用（对比 `jarvisInterface.js:2036` 与 `2035`）。

`[观察]` 下载是**串行**的（一次只有一个 `downloadFile` 在飞），`downloadrequests` 数组只用于
`cancelDownload()` 时统一 abort。

### 6.3 应用更新（Windows vs Linux 完全不同的两条路）

**Windows**：`applyChanges()`（`serverModel.js:290-400`）→ 500 ms 后
`$.getScript(<root>/nextversion/updater.js)`。

注意：执行的是**下载下来的** `updater.js`，不是 ASAR 里的 `app/updater.js` 副本；
`filePath = serverConnect.DownloadPath.NextVersionPath`（`serverModel.js:393`）。

`updater.js` 的全部动作：

```
1. HTTPS GET 版本接口（同一 URL，IsWin=T）取 AppVersion.S
2. 生成 updater.bat 文本（51-147），含：
     日志路径 <root>/nextversion/log-updater-bat
     powershell Stop-Process NovAtelApplicationSuite -Force
     Expand-Archive win-unpacked.zip → win-unpacked
     reg query HKCU\Software\NovAtel Inc.\NovAtel Application Suite /v Path
     比较注册表 Path 与 %cd%：
        相等 → flag_build=prod，robocopy 到注册表 Path
        不等 → flag_build=dev， robocopy 到 %cd% (= %var_app_path%)
     两条分支末尾都：
        powershell Start-Process Graph_Setup.exe -ArgumentList '/S','/D=<root>\Graph' -Verb RunAs -Wait
     prod 额外：
        reg add ...\Uninstall\NovAtel Application Suite /v DisplayVersion /d <ver> /f
        reg add HKCU\Software\NovAtel Inc.\NovAtel Application Suite /v Version /d <ver> /f
     清理 for /D %%d in (nextversion\*) do rmdir /s /q
     Start-Process <root>\NovAtelApplicationSuite.exe
3. fs.writeFileSync(updater.bat)
4. shell.openPath(updater.bat)      ← 用系统默认方式打开 .bat
5. ipcRenderer.send('close-app')
```

`[观察]` 已知缺陷：
- 第 155 行引用未定义的 `scriptFilePath`（应为 `batFilePath`），`ok` 分支会抛 ReferenceError，
  但此时文件已写完，不影响结果。
- `updater.js` 顶部没有 `require('fs')`/`require('path')`/`ipcRenderer`，依赖页面全局。
- **路径推算少了一级**：`updater.js` 自己被下载到
  `<root>\resources\nextversion\updater.js`（`serverConnectV2.js:37` + `serverModel.js:396`），
  所以 `__dirname = <root>\resources\nextversion`；而 `updater.js:6` 取 4 级父目录
  （`'..','..','..','..'`）得到的是 `<root>` 的**上一级**，不是 `<root>`。
  连带后果：`bat` 里的 `var_app_path`/`var_app_zip_path`/`var_winunpacked_path` 全部基于
  `%cd%`（`updater.js:60-65`），而 prod/dev 判定拿注册表 `Path` 去和这个错误的 `var_app_path` 比。
  `[推断]` 若 `Path` 与 `%cd%` 不等（正常情况），`flag_build` 会停在 `dev`，`robocopy` 目标就是
  那个错位的 `%var_app_path%` —— 即文件被复制到应用根目录的上一级。
  `[未知]` 实际是否触发，取决于 `shell.openPath(.bat)` 时的 cwd 与真实安装路径，
  需要一次实机安装 + 更新才能定论；这是复现时最应优先验证的一条。
- `dev` 分支的 `robocopy` 目标写的是 `%var_app_path%`，`prod` 分支写的是 `!var_registry_path!`
  （`updater.js:102` vs `118`），两条分支的目标来源不同，不能合并。

**Linux**：`applyChanges()` 的 else 分支（`306-391`）：

```
按 process.arch 决定文件名：x64 → NovAtelApplicationSuite_64bit.AppImage
下载文件必须存在于 <APPIMAGE 目录>/nextversion/<name>
备份当前 AppImage 到 <name1.AppImage>（1 后缀）
删旧 → 复制下载文件到位 → chmod 0777 → 删下载文件
fsextra.remove(<APPIMAGE 目录>/nextversion)
ipcRenderer.send('close-App')

```

三个 IPC 的差异：

| IPC | 输入 AppImage | 打包源目录 | 成功后动作 | 失败路径 |
|---|---|---|---|---|
| `repack-appimage` | `process.env.APPIMAGE`（当前正在跑的） | `<当前目录>/extractedAppImage/squashfs-root` | 删 `extractedAppImage`、`noncoreapps`、旧 AppImage → 改名 → 删 temp → 重启 | 写 `error.log` + `dialog.showErrorBox` + `reply({success:false})` |
| `update-appimage` | `<APPIMAGE 目录>/nextversion/...AppImage`（**下一个版本**） | `<nextversion>/extractedAppImage/squashfs-root` | 只覆盖该 nextversion 文件，**不重启** | 同上，且 `throw` |
| `delete-appimage` | `process.env.APPIMAGE` | `<当前目录>/extractedAppImage/squashfs-root` | 删目录 + 删旧 AppImage → 改名 → 删 temp → 重启 | 同上，且**没有 noncoreapps 清理** |

三者都用 `appimagetool-x86_64.AppImage`（从解包目录里取，`main.js:227`），都以
`bash -c 'ARCH=x86_64 "<tool>" "<src>" "<out>"'` 调用，输出名统一为
`NovAtelApplicationSuite_64Bit.AppImage`（大写 B）。

`[观察]` 大小写不一致：下载/替换路径用 `64bit`，重打包产物用 `64Bit`。在大小写敏感的
Linux 文件系统上，`update-appimage` 覆盖的是 `64bit`（`main.js:294`），而 `repack`/`delete`
产出的新文件跑完就被 `rename` 回**原路径**，所以只在「重打包后又被别的逻辑按 `64bit` 查找」时才暴露。

`[观察]` `main.js:350-355` 与 `421-425` 的 `catch` 块里引用了 `appImagePath`，该变量是 `try` 内的
`const` → catch 内访问会再次抛 ReferenceError，`dialog.showErrorBox` 实际上永远不会执行。


1. 语言按钮的插入点是 `settingsMenu.querySelector(".language-options")`（`jarvisInterface.js:6177`），

`languageSettings.json` 里对应条目。

`[观察]` 外部证据支持"曾经是双语、现在被关掉"：

## 8. 复现清单

> 每条都是可验收的行为断言。`[观察]` 均带 `文件:行号`。

**词典与查表**

- **R1** 每份语言文件必须是三段式：第 1 行注释、第 2 行 `var Language = Language || {};`、
  第 4 行 `Language.<CODE> = {`、最后一行 `jsIn.addDict(Language.<CODE>);`，且对象属性为扁平
  `'KEY': '文本'`，不含嵌套对象/数组。 `[观察] 01_解包/app/view/languageSupport/en.js:1-4,1923`
- **R2** 8 个对象名分别为 `EN/CN/DE/EG/ES/FR/PT/RU`，与 `languageSettings.json` 的 code
  大写一致；不一致会导致 `Language[userLanguage[...]]` 取到 `undefined`。 `[观察] 同目录 8 个文件第 4 行 + languageSettings.json:2-29`
- **R3** 键条目数必须为：en 1753（去重 1673）、cn/de/eg/es/pt 1707（1630）、fr 1707（1630）、
  ru 1607（1548）；计数口径为 `^\s{0,8}['"]?KEY['"]?\s*:` 且行首非 `//`。 `[观察] §3.3 统计表`
- **R4** 同一文件内允许重复定义同一键（en 80 处、其余 77 处、ru 59 处），语义为**后者覆盖前者**。
  `[观察] jsin.1.2.min.js:9 addDict 逐键赋值；en.js:19/358 的 OFF`
- **R5** `__('不存在的键')` 必须返回字符串 `"不存在的键"` 本身，绝不抛异常；开关
  `jsIn.showNotFoundError` 保持未调用（默认 false）。 `[观察] 01_解包/app/view/css/jsin.1.2.min.js:9`
- **R6** 占位符有两套并存机制：`jsIn.translate(text, params)` 认 `{%1}`；业务代码主流用法是
  手工 `.replace("%1", x)`，不得把两者混为一套。 `[观察] jsin.1.2.min.js:9 vs updateApplication.js:452-455`
- **R7** 切换语言后，新词库缺失的键必须显示**上一个加载过的语言**的文本（不是英语、不是键名），
  因为 `_dict` 只增不清。反例验收：先切中文再切德文，`UPDATEAPP` 应显示中文。 `[观察] jsin.1.2.min.js:9（无 delete）+ jarvisInterface.js:1361`
- **R8** 语言清单只有 7 条，`ru` 必须缺席；表现是俄语无法被选择、`Language.RU` 永不被加载。
  `[观察] languageSettings.json:1-30（无 ru）对比 ru.js:4`
- **R9** 非英语词库相对 en 必须缺失 45 个键（cn/de/eg/es/fr/pt 完全同一组）与 135 个键（ru），
  且缺的那 45 个必须包含 `UPDATEAPP`、`SELECTUPDATEAPPTEXT`、`VERSIONAVAILBALE`、
  `NONCORE_APP_VERSION_MSG`、`MSM1`…`MSM7`、`VS_QUESTION_1`。 `[观察] §3.3 缺失统计`

**加载与切换**

- **R10** `languageSettings.json` 的 `filePath` 必须是 `../languageSupport/xx.js` 形式，且由
  `$.getScript` 加载；相对基准是 `view/html/index.html`。 `[观察] languageSettings.json:4 + jarvisInterface.js:1361`
- **R11** 启动时必须且只能静态引用 `en.js` 一份词库；其余词库靠运行时注入。 `[观察] index.html:129（唯一的 languageSupport 引用）`
- **R12** `userLanguage` 的键必须是 `<languageName 全小写>-lang`，值是 code 大写；且只在
  `loadLanguageData('')` 分支填充。 `[观察] jarvisInterface.js:6142-6146`
- **R13** 语言 id 的取值域必须恰好是
  `{english,chinese,german,arabic,spanish,french,portuguese}-lang`。 `[观察] jarvisInterface.js:6145 + 6171,6174`
- **R14** 语言切换匹配算法必须是 `languageId.split("-")[0]` 与 `languageName.toLowerCase()` 全等，
  匹配不到时回落到 `en`。 `[观察] jarvisInterface.js:1354-1359`
- **R15** 语言切换后的刷新必须覆盖 79 处 `processLanguage` 定义中的持久可见部分，调用入口固定为
  `deviceTileTranslation` + `statusComponentsProcessLanguage`（最多 22 项）+

  `[观察] jarvisInterface.js:1362-1373、1375-1435；全库 79 处 processLanguage 定义`
- **R16** `userSettings.json` 的 `language` 字段在**每次启动**被无条件写成 `"english-lang"`，

  `[观察] updateApplication.js:259-268 + genericView.js:250`
