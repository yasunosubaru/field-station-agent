# 技能：固件

**什么时候用**：用户问设备固件版本、要不要升级、升级失败怎么回滚。

## 先认清一件事

**本 agent 没有「刷固件」的工具。**

`execute_device_action` 在高风险工具里，`fsa-ops.yaml` 的策略是 `approval_required`，
而且不在 `tools.allow` 白名单里——**这个 agent 默认根本调不到它**。

所以问「帮我升级固件」时，正确做法是：

1. 先查当前状态（只读工具）；
2. 给出可核查的判断与步骤；
3. 把「要人做什么」说清楚，让人自己去做或显式批准；
4. **不要假装已经升级了**。

## 能查什么

| 想知道的 | 工具 | 说明 |
|---|---|---|
| 设备在不在线 | `device_heartbeat` | 升级前必须确认，离线设备不能升 |
| 串口/设备节点 | `native_ports` | 看端口是否被占用 |
| 套件状态 | `suite_status` | 需要 `pid`，没有就明说 |
| 历史工单 | `list_work_orders` | 看这台设备之前升级过没有 |

## 升级前的检查清单（回答里要逐条给结论）

1. **设备在线**：`device_heartbeat` 的 `state == online`。`stale` 要说明「状态不确定」。
2. **没有正在跑的采集**：套件在跑的时候刷固件会中断观测。查不到就明说查不到。
3. **有回滚路径**：旧版本号、旧固件文件在哪。**这两条不知道就不建议升级。**
4. **维护窗口**：`execute_device_action` 的 reason 里必须写清窗口。

## 回滚怎么说

回滚同样是设备动作，同样需要人批。**不要承诺「可以随时回滚」**——
只有在你确实知道旧固件还在、且设备支持降级时才能这么说。

## 常见错法

- **把「已提交工单」说成「已升级」**：`create_work_order` 只建单，设备一动不动。
- **用 `execute_device_action` 假装完成**：它当前只返回授权命令包
  （`execution_mode: simulated`），**不真的操作硬件**。引用它的返回时必须带上这个字段。
- **跳过在线检查直接给步骤**：离线设备刷固件最常见的结果是变砖。

## 回答形状

```
结论：不建议现在升级。WUHN 处于 stale（age_s=740），状态不确定。
证据：[t0001] device_heartbeat → state=stale, age_s=740
下一步：先确认是否在采集（套件 pid 未知，需人工看）；在线后再谈升级。
不确定项：没有旧固件版本号，无法评估回滚路径；升级窗口未定。
```
