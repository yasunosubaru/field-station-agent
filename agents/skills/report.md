# 技能：报告

**什么时候用**：用户要日报/周报、要汇总交接、要一句话结论。

## 报告的四个固定部分

每份报告都是这四段，顺序不变。缺哪段就明写「无」，不要省掉。

```
结论：<一句话，明确 ok/degraded/critical/unknown>
证据：<每条 [call_id] 工具名 → 关键字段>
下一步：<一条可执行动作，或「需要用户批准 X」>
不确定项：<工具没覆盖到的部分，没有就写「无」>
```

## 三类结论，词表固定

| 场景 | 允许的词 |
|---|---|
| 台站状态 | `ok` / `degraded` / `critical` / `unknown` |
| 动作执行 | `succeeded` / `failed` / `waiting` |
| 数据质量判据 | `accepted` / `rejected` / `not_applicable` |

**不许自创词。** 「基本正常」「大致没问题」这种说法会让下游的机检和人眼都对不上。

## 证据怎么引

- 每条证据以 `[call_id]` 开头，`call_id` 必须来自**真的成功调用过**的那一次。
- 格式：`[t0001] station_health → health_score=0.87, missing=3`
- **只写工具真的返回了的字段**。没返回的字段不许出现在证据里。
- 一条结论至少要有一条证据。引不到就把结论降级成 `unknown`。

## 汇总多个台站时

- 先按 `station_id` 分组，**不要跨台站求平均**——不同台站的量纲和基线都不同。
- 每个台站单独一行结论，最后再给整体判断。
- 整体判断只能是「最差的那个」再退一档，不许比最差的还好。

## 时间范围

报告里出现的时间必须是**工具返回的**，或用户明确给的。
不许写「过去一小时」这种靠当前时刻推算的范围——你不知道工具缓存了多久。

## 常见错法

- **把 `unknown` 写成 `ok`**：这是最坏的一种，用户会以为已经确认过了。
- **同一件事在两段里说成不同结论**：写完先自己核对一遍「结论」和「证据」是否对得上。
- **报告里出现没调过的工具名**：审阅的人会以为那条证据是真的。

## 一份合格的日报

```
结论：degraded——WUHN 缺测率 12%，BADG 正常。
证据：
  [t0001] station_health → WUHN health_score=0.87, missing=3/25
  [t0002] station_health → BADG health_score=0.99, missing=0/25
  [t0003] device_heartbeat → WUHN state=online, age_s=42
下一步：WUHN 连续 2 小时缺测则建单（需你确认后再建）。
不确定项：BADG 的供电读数没有提供，健康度只覆盖了传感指标。
```
