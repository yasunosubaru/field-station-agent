## 4. 纪律与红线（附本会话踩过的坑）

### 4.1 提交

* **不要 `git add -A` / `git add .`**，逐个列路径（仓库规矩，`CLAUDE.md` 第 3 节）。
* **这个 checkout 会被多个会话同时用**。本会话真实的坑：另一个会话把文件 `git add` 进暂存区后，
  我的 `git commit`（不带 pathspec）把**它的**文件一起提交了。
  → **提交时一律带路径**，或者干脆用临时索引：

  ```powershell
  $env:GIT_INDEX_FILE = "$env:TEMP\my-index"   # 只用我自己那一个文件做一次提交，不碰共享索引
  git read-tree HEAD
  git add -- <我的路径>
  git commit -m "..."
  Remove-Item Env:\GIT_INDEX_FILE
  ```
* 提交前 `git status` 复核暂存范围；发现别人的文件在暂存区时**不要替我提交**。

### 4.2 改动边界

* `逆向/01_解包/`（本机不入库）是**只读证据**，所有 `文件:行号` 都指向它，不许改。
* `PROVENANCE.md` 表里的搬运件只读；确需改动走「立 issue → 先写让测试变红的回归 → 更新登记表 → 证明样本逐字节未变」。
* `逆向/tools/remote/*.ps1` 必须**纯 ASCII**（PS 5.1 无 BOM 按 GBK 读，中文字面量会解析炸掉）；主机名/路径一律走参数。
* 不引入第三方依赖（`tools/make_cli_figures.py` 的 matplotlib 是已登记的可选依赖）。

### 4.3 数字联动（改一处就得改三处）

新增或删除 `tools/*.py`、`harness/*.py`、`src/fieldstation/agents/*.py` 会改变软著源程序文档的规模，
必须一起动：

```powershell
& $py tools/make_copyright_source.py --out "docs/m7/软著-源程序.txt" --summary "logs/copyright_source_summary.json"
# 然后把这三处的数字改成 summary 里的值：
#   docs/m7/软著-软件说明书.md   （{files} 个文件、{lines:,} 行、{pages_total} 页）
#   docs/m7/一页摘要.md          （同一组数字）
#   docs/m7/软著-申请信息.md     （源程序量）
& $py -m unittest tests.test_copyright_source tests.test_m7_summary
```

同理：改 `src/` 或 `tests/` 里的 `.py` 后，README 的机维护块要跑 `& $py tools/sync_code_counts.py` 重生成
（它拒绝在「有未入库 `.py`」时生成，先 `git add`）。

### 4.4 真机与不可逆动作

* 重启、固件刷写、配置下发这类动作**一律走人工闸门**：`workflows/*.yaml` 里声明 `gate`，执行到那里停下等批准。
* 驱动原版套件 GUI 时不许用坐标（`tools/uia_driver.py` 只认控件名，找不到就报 `GuiUnavailable`）；
  套件必须带 `--force-renderer-accessibility` 启动，否则 UIA 看不到网页内容。

  **资产上传必须走本地代理** `http://127.0.0.1:7897`（钉 IP 会 404）。
* `git push` / `git fetch`：直连时通时不通，失败就加 `-c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897`。
* `gh` 的 keyring token 有时报 invalid，`gh auth token` 或 `git credential fill` 拿到的同一个 token 可用（`repo` scope）。
* **不要用填充串去试探额度或上下文**（账号级风控，见 `~/.config/opencode/AGENTS.md`）。
