## 1. 这一轮修好的两件事（新会话不必重做）

### 1.1 Octop 调模型全超时 → 根因是缺 `User-Agent`

- 现象：四条线全部停在「连接模型服务超时或网络异常」，日志是 `openai.APITimeoutError` / `httpx.ConnectTimeout`
- 真因：`api.commandcode.ai` 前面有 Cloudflare，**不带 `opencode` 这个 UA 会被 403 拦掉**
- 实测矩阵（2026-11-10）：

| 请求方式 | 结果 |
|---|---|
| 直连 + 默认 UA | HTTP 403 ×3 |
| 直连 + `opencode/1.2.3` | **200 / 401（看 key）** |
| 走 7900 代理 + 默认 UA | HTTP 403 |
| 走 7900 代理 + `opencode/1.2.3` | **200** |

- 修法：给 Octop 的 provider 加 `extra_json = {"headers": {"User-Agent": "opencode/1.2.3"}}`
  （已写入 `octop.db` 的 `providers.extra_json`，provider id=1）
- 验证：`POST /api/admin/providers/1/test` → `{"ok": true, "latency_ms": 9260}`
- **注意**：`/api/admin/providers` 的 GET 不返回 `extra_json`，从 API 看不出来，要查库确认。

### 1.2 worktree 里测试多出 7 项红 → 根因是两个目录没进 git

- 现象：主仓库 1995 项只有 1 项红，worktree 里同一套测试有 7 项红
- 真因：`逆向/01_解包/` 和 `逆向/02_证据/` **不在 git 里**（未跟踪），`git worktree add` 不会带过去。
  需要读原版套件页面的测试（`tests/test_suite_field_parity.py` 等）A 侧字段抽到 0 个 → 失败
- 修法：给全部 4 个 worktree 建 junction 指向主仓库那两份（不占空间、不改原文件）：

```powershell
cmd /c mklink /J "<worktree>\逆向\01_解包" "<主仓库>\逆向\01_解包"
cmd /c mklink /J "<worktree>\逆向\02_证据" "<主仓库>\逆向\02_证据"
```

- 效果：A 线 worktree 的 `suite_field_parity` 从 6 项红降到 1 项红
- **新会话注意**：新建 worktree 必须重做这一步，否则测试会莫名其妙变红
