# All powered-FSA · 干净机验收清单

用法：找一台**没有装过 Node.js、没有装过本产品**的 Windows 10/11 x64 机器（或一个干净的
Windows 用户账户），按顺序做。每条都写了「应该看到什么」；看不到就不要打勾，按最后一节取证。

**状态说明**：标 **[当前]** 的项目对应本轮并行实现的 Agent 部分。合入前它们应当记为
「未通过」，不要提前打勾；标 **[当前]** 的项目今天就能验。

## 1 拿到程序

- [ ] **[当前]** 从发布页下载 `AllPoweredFSA.exe`，SHA256 与发布说明一致。
- [ ] **[当前]** 文件是单个 exe，不需要安装器、不需要解压出一堆 DLL。
- [ ] **[当前]** 在一台**没有 Node.js** 的机器上双击能启动（证明 Node 是自带的）。

## 2 第一次启动

- [ ] **[当前]** 双击后出现启动提示，说明正在解压 / 启动本地服务，不是白屏。
- [ ] **[当前]** `%LOCALAPPDATA%\AllPoweredFSA\app-<版本>\` 出现，里面有 `runtime\node.exe`。
- [ ] **[当前]** 40 秒内出现主窗口；超时会显示明确错误，而不是一直转圈。
- [ ] **[当前]** 关闭窗口后，任务管理器里没有残留的 `node.exe`（整套进程树被结束）。
- [ ] **[当前]** 第二次启动明显更快（复用已解压目录，不重复解压）。
- [ ] **[当前]** 升级到新版本后，旧的 `app-*` 目录被清理，新目录带 `.ready` 标记。

## 3 两种模式

- [ ] **[当前]** 默认落在 **Agent 工作台**，不是专业面板。
- [ ] **[当前]** 顶栏能在「Agent 工作台」与「专业面板」之间来回切，状态不丢。
- [ ] **[当前]** 三栏宽度符合预期：左 280、右 320；窗口拉窄到 1100 以下收右栏，800 以下收左栏。
- [ ] **[当前]** 空态显示四个建议 chip：健康度 / 质控 / 导出 PDF / 重启。
- [ ] **[当前]** 快捷键可用：`Ctrl+N` 新会话、`Ctrl+K` 命令面板、`Esc` 取消生成。
- [ ] **[当前]** 专业面板有六个页签：Manage / Playback / Convert / GRIT / Graph / Workflows，另有主页。
- [ ] **[当前]** 切换深色 / 浅色主题，文字与控件都还能读（不出现深底深字）。

## 4 模型通道

- [ ] **[当前]** 第一次启动、没填 key 时，界面明说「已回退到 fake」，不是静默失败。
- [ ] **[当前]** `fake` 通道能完整跑一轮对话；断网后仍然可用。
- [ ] **[当前]** 同样的输入在 `fake` 下给出同样的回答（确定性，可录屏复现）。
- [ ] **[当前]** 填一个 OpenAI 兼容服务（`base_url` 不带 `/v1`）后，回答正常返回；流式逐字出现。
- [ ] **[当前]** `base_url` 误填成带 `/v1` 的地址时，错误消息里能看到完整 URL（便于定位）。
- [ ] **[当前]** 设置页只显示「已配置 key」，**不显示 key 内容**；重新保存后旧 key 被覆盖。
- [ ] **[当前]** 把 `secrets.bin` 拷到另一个 Windows 账户下，提示 key 解不开、要求重填。
- [ ] **[当前]** 本机 Ollama 通道能连上；模型名、地址与配置文件一致。

## 5 日常任务（每条都看「结果 + 证据」）

- [ ] **[当前]** 健康度：问「现在台站怎么样」，返回读数与阈值，工具卡有 `agent:call_id`。
- [ ] **[当前]** 质控：问「检查今天这段观测」，逐条给判定与规则编号，不只给一句结论。
- [ ] **[当前]** 导出 PDF：产物卡出现，文件能打开，卡上的 `sha256` 与文件实际哈希一致。
- [ ] **[当前]** 重启：出现审批卡；**拒绝**后流程停住，没有任何 RESET 发出。
- [ ] **[当前]** 重启：**批准**后才执行；`restart.json` 里有 RESET 回执与回来后的 VERSION。
- [ ] **[当前]** 新建工程：Process 之前停下等确认；批准后工程目录与四步预处理回执都在。
- [ ] **[当前]** 加设备：端口列表来自真实机器；连接成功后 VERSION 回读的型号与设备一致。
- [ ] **[当前]** 装应用：Install 之前停下；装包哈希、安装回执、应用列表三者能对上。

## 6 审批与证据

- [ ] **[当前]** 审批卡写清动作（含参数）、风险、影响；没有「只写一句要重启」的卡。
- [ ] **[当前]** 待审批期间，同一调用没有结果卡；决定后先出现决定记录，再出现结果。
- [ ] **[当前]** 决定后卡片禁用，显示决定人与时间；备注被保存。
- [ ] **[当前]** 会话 JSONL 第一行是 `meta`，之后事件只追加；关掉再打开能完整重放。
- [ ] **[当前]** 工具卡折叠的 JSON 与 `sessions\<id>.jsonl` 里同一次调用一致。
- [ ] **[当前]** 失败时出现失败卡，分类属于环境 / 输入 / 执行 / 产物 / 能力之一，且给出原因。

## 7 专业面板（只读边界）

- [ ] **[当前]** Manage 的配置页与状态瓦片能读出现有设备/样本的真实值。
- [ ] **[当前]** Playback 能打开样本工程，时间轴、事件带、地图联动正常。
- [ ] **[当前]** Convert 能完成一次格式转换，结果文件可打开。
- [ ] **[当前]** GRIT 的频谱与 Signal Matrix 不错位；窗口拉窄时布局堆叠而不是重叠。
- [ ] **[当前]** Graph 能打开工程、出图并导出 PDF；PDF 页数与内容正常。
- [ ] **[当前]** Workflows 页签列出流程目录；参数、审批门、失败分类、证据下载都在。
- [ ] **[当前]** 专业面板里**找不到**「直接下发配置 / 直接升固件 / 直接装应用」的写按钮——
      这类动作只能从 Workflows 走。

## 8 数据目录与卸载

- [ ] **[当前]** 用户数据集中在 `%LOCALAPPDATA%\AllPoweredFSA\`：`sessions\`、`artifacts\`、
      `jobs\`、`settings.json`、`secrets.bin`、`runtime.json`、`logs\`。
- [ ] **[当前]** `runtime.json` 只有当前用户可读（换账户读不到）。
- [ ] **[当前]** `jobs\` 在 `app-<版本>` 之外；升级后旧 job 仍在。
- [ ] **[当前]** 关窗后删除 `%LOCALAPPDATA%\AllPoweredFSA\` 与 exe，系统里没有残留服务/自启动项。
- [ ] **[当前]** 卸载前把 `jobs\` 与 `artifacts\` 拷走，换机器后证据仍能读。

## 9 诚实性（这一节最容易漏）

- [ ] **[当前]** 服务端没起来时，界面显示「不可用」并给原因，不显示假数据。
- [ ] **[当前]** 工具失败时界面显示失败，不把上一轮结果当成本轮结果。
- [ ] **[当前]** 模型说了一个没有工具支撑的数字时，界面上没有对应的工具卡——按未验证处理。
- [ ] **[当前]** 断网后，除模型通道外的功能（专业面板、历史会话、证据查看）仍可用。
- [ ] **[当前]** 任何页面都不出现「示例数据」被当成真实设备读数的情况（合成数据必须标注）。

## 10 不通过时怎么取证

按这个顺序留材料，别只写「不行」：

1. 截图：出错界面 + 任务管理器进程列表。
2. 会话：`sessions\<id>.jsonl` 原文件。
3. 流程：`jobs\<job_id>\` 整个目录（`job.json`、`audit.jsonl`、`artifacts\failure.json`）。
4. 日志：`logs\` 下对应时间段的文件（先确认没有 key/token）。
5. 环境：第 0 节的表，加 exe 的 SHA256。
6. 复现步骤：从双击开始的每一步，包括输入的原话。

分享材料前先脱敏：本机路径、账户名、API key、设备序列号都可能出现在证据里。
