# ADR-010：套件台重做（不叠皮）+ RPA 收口

- 状态：**Accepted**（2026-11-04 负责人："套件台写的不行，这 UI 太烂"；"先把 RPA 做好"）
- 日期：2026-11-04
- 关联：ADR-008（壳与四视角）、ADR-009（引擎）、`docs/spec/2026-11-04-v4-实施基线.md`

---

## 1. 背景：两件事都没做好

**套件台**：现在的做法是"1:1 克隆 + 最后加载一份 `modern.css` 覆盖"。结果是：
字号/间距/圆角各写各的、卡片会被内容撑破（Ports 最后一列被切）、顶部条要靠补丁抬高度、
同一个页面里混着原版的 17px OpenSans 与我们的等宽栈。这不是"设计不好"，是**方法错了**——
覆盖式皮肤只能改颜色，改不了栅格与组件结构。

**RPA**：8 条流程里 2 条真全自动、3 条到闸门、3 条被环境卡住；
选择器靠人工对着界面抄文字，套件一升级就可能全废，而且**没有套件时无法回归测试**。

## 2. 决定一：套件台重做，保留语义、重建组件

| 保留 | 重建 |
|---|---|
| 信息架构：六个页面、每个页面的分区与字段 | 布局：左导航 / 中内容 / 右检查器（原版没有右栏，这是新增） |
| 数据契约：记录号、字段名、`--` 的语义、状态机 | 组件层：Tailwind + shadcn 风格组件，统一栅格与字号档位 |
| 行为语义：只读镜像、写操作走流程 | 表格：固定表头、列宽可拖、数字右对齐、密度可切（紧凑/舒适） |
| 与原版的对照关系 | 空态/错误态：每个卡片必须写"没有数据 + 为什么" |

**明确退役**：`panels/modern.css` 这种"最后加载覆盖"的做法。新页面直接写组件，
不再在旧 class 体系上贴皮。

**技术**：与 Electron 壳同一套（Tailwind + shadcn 风格组件）；长表用虚拟滚动；
图表用轻量 SVG，不引重型图表库；所有数值等宽、单位小号。

**验收**：1280 / 1440 / 1920 三档不横向溢出；信息不丢（与原版逐项对照表）；
对比度 ≥ 4.5:1；键盘可达；切换"紧凑/舒适"不重排数据。

## 2.5 补充决定（2026-11-04）：原版套件直接嵌入

负责人追加：**原版套件直接嵌入**。套件台因此变成**两个挡位**，而不是重写六个页面：

| 挡位 | 内容 | 用在哪 |
|---|---|---|
| **增强视图** | 我们重做的高频页：Manage（状态/配置）、Workflows（流程与证据）、Graph（导出与工程） | 日常运维、要联动我们数据的页面 |
| **原版视图** | 原版套件窗口**直接嵌进面板**，其余页面（Playback / Convert / GRIT）原样可用 | 低频页、需要与厂商界面逐像素一致时 |

技术路线（W3 spike）：

- 原版仍是独立进程，正常运行（不改二进制、不打补丁）；
- Electron 侧用 FFI（koffi）调 `user32.SetParent` 把它的 HWND 挂进套件台的面板容器，随布局同步尺寸；
- 同时保留 `--remote-debugging-port`，用于取数、注入与流程驱动——**嵌入不等于只能看**；
- 嵌入失败（DPI/焦点/层级异常）自动退回"独立窗口 + 一键切回"，不许卡死。

对 RPA 的影响：E7 从"外挂驱动一个看不见的窗口"变成"操作我们自己的内嵌实例"，
窗口生命周期、可见性、注入时机都可控；选择器仍是同一套，但他们不再依赖用户先手动打开套件。

范围收敛：W3 从"六个页面全重做（3 周）"缩为"三个高频页 + 检查器 + 嵌入（2 周）"。

## 3. 决定二：RPA 收口四件事

### 3.1 校准工具（`tools/rpa_calibrate.py`）

连上套件后，按流程逐步 dump 可交互元素（文本 / role / 层级 / 可见性 / bounding box），
生成或更新 `tools/uia_selectors.json` 与流程里的 locator，输出 diff 供人确认。
**目的**：套件升级后，改映射从"人肉翻页面"变成"跑一次工具 + 看 diff"。

### 3.2 DOM fixture 回放

每次成功跑通，保存该步的 DOM 快照（去掉动态值）为 fixture；
CI 里用无头浏览器回放定位逻辑，**不需要装套件也能测出选择器失效**。
门禁：8 条流程的 fixture 回放全绿，否则不许合。

### 3.3 通道升级（能绕开 GUI 的就绕开）

按优先级逐条试：内部 API / CLI / 文件格式，最后才是 GUI。
已确认：`gui.graph.export` 走 Node API 可全自动。
待查：Graph 的工程文件格式能否直接生成；应用安装是否有内部安装接口；固件刷写是否有官方命令行。
**查不到就如实标 `blocked`，不猜。**

### 3.4 真机验收清单 + 失败分类

8 条各写：接上真机后跑什么、看什么、证据存哪。没有真机的标 `blocked: hardware`，
不写成"已完成"。失败分类沿用现有六类，新增 `hardware_missing`。

## 4. 边界

- 不改业务语义：套件台仍是只读镜像，写操作只走流程 + 闸门；
- 不追求 DOM 逐字节一致：parity 用**字段/状态对照表**衡量"信息不丢"，不用 diff 页面；
- 不为了自动化而绕过闸门：不可逆动作永远停一次。

## 5. 验收

1. 套件台三档分辨率不溢出，Ports/Logging 这类密集表格完整可读；
2. 原版六个页面的字段与状态逐项对得上（对照表进文档）；
3. 8 条流程：要么 deterministic 全自动，要么有明确的 assisted 协议与验收清单；
4. 无套件环境下，fixture 回放能抓出被人为改坏的选择器；
5. `modern.css` 从仓库删除，`index.html` 不再引用。
