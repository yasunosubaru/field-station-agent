# ADR-005：M5 集成通道（消息总线 + 共享黑板 + 输入留痕）

- 状态：Accepted
- 日期：2026-10-20
- 关联：issue #60–#63、#75；KI-11；`agents/bus.py`、`agents/pipeline.py`、`agents/blackboard.py`

## 背景

spec §4 对运行时提了三条硬要求：消息路由「agent 间通信走消息总线，不共享隐藏状态」、
上下文管理「共享黑板（台站/告警/工单）读写受控、并发语义明确」、决策留痕「任一结论
可回放到工具输出」。M5 把五类 Agent 串成一条链，需要把这三条变成一套可测的通道设计。

## 决定

1. **消息总线承载阶段间的数据流**：进程内、同步、确定性、无中间件；`msg_id` 是
   顺序号（`m0001` 起，不含时间戳/随机量）；payload **全量**进 `message` 事件；
   `refs` 指向消费的上游 `msg_id`。
2. **黑板是第二条、且是声明式的通道**：键 `<命名空间>/<路径>`，命名空间固定
   `station` / `alert` / `order`；值是 JSON dict、**整值替换**；每键版本只增不减
   （**删除后重建也不回退**，防 ABA）；写默认 CAS（`create` / `update` /
   `delete`），无条件覆盖必须显式 `upsert`；`RLock` + 值进出深拷贝；变更事件在锁内
   按提交顺序回调、读不发事件。
3. **能力由阶段声明单点决定**：`PipelineStage.board_reads` / `board_writes` →
   `BoardView` → `Pipeline` 把对应方向的工具注入该阶段**克隆的**注册表。阶段注册表里
   预置任何黑板工具一律报错；没声明就没有工具，也没有别的路径能碰到黑板。
4. **输入全量留痕**：每个阶段在 `runtime.run` 之前写 `stage_input`
   （`agent` / `i` / `input_digest` / `note` / `msg_ids`）；结论仍走 ADR-004 契约。
5. **链路是串行的**：不引入并发执行。黑板的线程安全是给「外部读 / 将来并行」准备的
   性质，不是当前链路的并发模型；当前链路的确定性依赖串行。

## 被否的方案

- **进程外消息中间件**（Redis / RabbitMQ）：没有跨进程需求，只增加部署与不确定性
  （spec §8 的 YAGNI）。
- **黑板就地修改 / 字段级合并**：读者会看到写者改到一半的状态；整值替换 + 版本号
  已经够回答「现在是什么」。
- **默认 last-writer-wins**：两个写者各按旧版本做决定时，后写的赢且前一个判断连同
  依据一起消失；所以默认 CAS，覆盖要显式。
- **黑板能力走 `config/agents/*.json` 的 tools 白名单**：会与阶段声明形成两处声明，
  且克隆注册表里预置的工具无法被声明约束（M5 终审实测的泄漏）。
- **`message` 事件只存 digest**：M5-4 要核对「消息全量可见、无隐藏状态」，digest 让
  只看日志的复核者无法还原消息内容。

## 后果

- 五阶段链的 trace 自包含：消息、工具调用、结论、输入（`note` + 消费的 `msg_ids`）
  都在同一条文件里；M5-4 的审计据此做双射与 refs 闭合核对。
- **任何 trace 变化都要重 bless**：M5-1 fixture 顶层 sha、M5-4 审计记录、M5-3 看板
  页面/摘要都依赖它（见 `harness/REPRODUCE.md` §3.5–§3.7）。
- 黑板当前没有常驻消费者：M5-3 看板用 `upsert` 装载 + `snapshot()` 渲染，不消费
  事件流；实时看板等 M6 部署形态。
- **单键原子、多键不原子**：跨键一致性走消息，或在黑板里聚合成一个键。
