# 本地模型通道与可复现性口径（ADR-003）

- 日期：2026-10-18
- 状态：**已定**（随本 PR 合入 `main` 后，M3-0 的「真实通道可用 + 换模型只改配置」落定）
- 关联：[ADR-001](2026-10-14-智能体运行时选型.md)、issue #50（M3-0）、issue #71（X-1 算力与通道）、PR #80
- 结论一句话：**本地通道用 `qwen3:8b`（Ollama 0.40.4），同配置短测 5 次逐字可复现；
  对外主数字仍走 API 通道的「冻结版本 + N≥5 次均值±极差」口径，本地通道只作同机回归基线**

---

## 1. 这个决策要解决什么

M3-0（issue #50）的第一行路标：*本地模型服务能起来、能返回工具调用、provider 抽象
能换模型不改代码、可复现性有实测*。X-1（issue #71）里「能不能申请到算力」一问，
在负责人这台机器上给出了**实测答案**（见 §2），并把复现性口径先定死——
M3-4 评测集建起来之前，禁止任何「默认可复现」的口头假设。

## 2. 机器实况（2026-10-18 探测，全部一手记录）

| 事项 | 实测结果 | 教训 |
|---|---|---|
| Ollama 服务 | 0.40.4，`OLLAMA_HOST=127.0.0.1:12434` | 不许猜默认端口 |
| 端口 11434 | **不是 Ollama**——被 `C:\Users\SunCh\Strata-data\bridge\bridge.py`（pythonw）占用 | 探测工具第一次探针就吃这个亏：404 报错的「Ollama」其实是个旁人 |

## 3. smoke：工具调用能回来（#50 第 1 条达成）

实测（`temperature=0, seed=42, num_ctx=8192, think=false`，HTTP 200）：

| 项 | 值 |
|---|---|
| 工具调用 | `query_station`，参数 `{"days": 3, "station": "BADG"}` —— 从中文提问里解析正确 |
| usage | prompt 198 / completion 27 |

provider 层把 Ollama 的 `{"function":{"name","arguments"}}` 归一成 runtime 认的
`{"name","args"}`（`tests/test_provider_ollama.py` 离线钉死）。
「与报文形状无关」确保 runtime/M3-1 编排感知不到这里的细节。

## 4. 可复现性口径

同输入 5 次（一句话短测）：`"中位数" ×5` 逐字一致。记录（含全部回答与用量）在
本机 `logs/probe_provider_20261018.json`；`logs/` 按仓库约定不入库，硬数字以此 ADR 为准。

三条纪律随之定死：

1. **逐字一致 ≠ 全库可复现**：这条证据只覆盖本次短测语料。M3-4 评测底座落成时
   对每个语料重跑 `tools/probe_provider_live.py`；『跑不过就换 N≥5 分布口径』。
2. **对外主数字走 API 通道**：五家主要供应商（含 DeepSeek）均不承诺 temp=0 逐次
   一致（服务端批调/MoE 路由固有非确定性，seed 不豁免，2026-10 官方定价页核查，
   见 #71 评论）。**冻结模型快照版本 + temperature=0 + top_p=1 + 每个 case N≥5 次
   报均值±极差；单次结果不进正文**。
3. **本地 Ollama 通道只作同机回归基线**：改坏本地环境的信号可以从它拿，
   拿它当对外数字由这一条堵死。

## 5. 影响与挂勾

- 成员机器：装 Ollama、`ollama pull qwen3:8b`、默认 11434 即可——
  `config/providers.json` 的默认值就是为这场景写的；端口不同的传 `--config`
  指到自己的 `config/providers.local.json`（不入库）。
- 门禁完全不受影响（skip=0）：真实通道**不进** unittest 门禁，探针不是测试，
  结论以本 ADR + 运行记录为据。
- runtime / cli 未动：多轮循环与编排入口是 M3-1 的活，本 PR 不占它的边界。
