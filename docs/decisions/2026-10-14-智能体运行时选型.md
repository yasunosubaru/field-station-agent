# 智能体运行时选型（ADR-001）

- 日期：2026-10-14
- 状态：**已定**（影响 M3 及以后；M0 已完成部分保持不变）
- 关联：`docs/spec/2026-10-13-野外台站智能体基础设计.md` §4、issue #20（同类项目调研）
- 结论一句话：**运行时用 LangGraph（备选 Pydantic AI）；平台层只做看板；trace 格式照 Langfuse；工具接口按 MCP；自研只留规则层与评测集**

---

## 1. 这个决策要解决什么

spec §4 列出智能体运行时应有六项能力，M0 只实现了其中三项（provider 抽象、trace 留痕、
单轮循环），另外三项（角色声明式配置、工具注册、消息路由/共享黑板）明确推迟到 M3 ——
因为当时没有真实消费者，提前造就是投机。

M3 起要做五类智能体协同，在此之前必须先回答四个问题：

1. 用什么框架承载协同？
2. 哪些继续自研、哪一层交给框架？
3. trace 用自研格式还是改用事实标准？
4. 工具接口按什么协议定义，避免锁死厂商？

## 2. 决策标准（按权重）

| 编号 | 标准 | 权重 | 为什么 |
|---|---|---|---|
| C1 | trace 与回放**格式可控** | 最高 | 申报书的考核指标（告警误报率、故障发现时延缩短 50%）都建立在可复现评测之上；门禁 [4]「同 seed 同 config_hash」已作为硬约束 |
| C2 | 出问题时**能查到别人踩过的坑** | 高 | 三人团队，两名大一新生，无专职运维；只能靠社区存量资料 |
| C3 | 许可证与本仓库（PUBLIC）兼容 | 高 | 本仓库已公开且**尚无 LICENSE**，默认"保留所有权利"；引入第三方必须先过合规 |
| C4 | 状态机、人工审核、重试 | 中 | spec §2 明确高风险动作须留人工审批，这是合规要求不是可选项 |
| C5 | 测试友好、可离线 | 中 | `harness/replay.py` 必须不联网也能跑；掉线不能等于门禁失效 |
| C6 | 上手成本 | 中 | 一名成员为大一 |

### 3.2 逐条说明

**LangGraph（首选）**
- C1：官方定位即把 durable execution 与 replay/time travel 做在框架内而非外挂，
  与本项目自研的 `harness/replay.py` 是同一思路
- C2：star 只有 CrewAI 的七成，**月下载是其 6.6 倍、OpenAI Agents SDK 的 3.3 倍**；
  生产使用者含 Klarna、Uber、LinkedIn、JPMorgan、Elastic ——
  出问题时能检索到同型号坑的概率高一个量级
- C3：MIT
- C4：状态图 + checkpointing + `interrupt_before/after` 原生支持人工审核
- C5：图执行可脱离网络重放（LLM 请求侧仍需 provider，本仓库已有 fake provider 兜底）
- C6：图式抽象有学习曲线，但 C2 的存量资料足以对冲

**Pydantic AI（备选）**
- C2/C3 与 C1 都合格，type safety 与 OpenTelemetry 原生是加分项
- 月下载量级明显低于 LangGraph，**这是它落在备选而非首选的主要原因**
- 若 M3 两周内 LangGraph 跑不通第一个 graph，按 §7 降级到它

**CrewAI（淘汰）**
- 上手最快，但多家第三方评测明确指出：其抽象层**超过 5 个 agent 后变得不透明**
- 本项目**正好五类智能体**，正踩该边界
- 月下载 5.2M，仅为 LangGraph 的约 1/6.6

**AutoGen（淘汰）**
- 微软已宣布并入 Microsoft Agent Framework，README 标注维护模式，
  **最后代码 push 停在 2026-04**
- star 61k（候选中最高的两个之一）与月下载 856k（候选中最高的一个）严重倒挂 ——
  正是"看 star 选型"最典型的反面案例
- 凡本仓库再出现它，一律按过时选型处理

**Microsoft Agent Framework（淘汰）**
- 定位正确（.Net/Python 一等公民、MCP 原生），但团队技术栈为 Python + WPF 历史混合，
  .NET 一等公民的优势无法兑现，迁移成本不划算

**平台层（Dify / FastGPT，仅看板）**
- **平台层与框架层的分水岭比选哪个框架更要紧**：平台型交付的是可视化编排 +
  托管 + 日志，配置为主
- 本项目 spec 的核心要求"协同编排 + **全程留痕 + 可回放评测**"在平台型里
  **留痕格式由平台决定，不可控** —— 直接违背 C1
- 因此：**平台层最多用于最后的告警看板**（Dify/FastGPT），不得进入智能体本体
- 另：Dify 为 Python/Flask 实现（不是 Java），这一条降低了二次开发门槛

**n8n（淘汰）**
- star 最高（~205k）但许可证是 **fair-code**：允许自托管商用，
  但**云端 SaaS 化与再分发有限制，且非严格 OSI 开源**
- 本仓库已公开且未定 LICENSE，引入此类组件将使合规边界失控
- 另：其核心在非 AI 的集成深度（400+ SaaS、调度、重试），AI 只是其中一环

**完全自研（淘汰）**
- C1 完全可控，但 C2 最差：无社区存量资料，三人团队无法承担维护
- 且 spec §4 六项能力全部自研等于 M0 之前设计的反面

## 4. 最终决策

| # | 决策 | 内容 |
|---|---|---|
| D1 | 运行时框架 | **LangGraph**，备选 Pydantic AI |
| D2 | 平台层定位 | Dify / FastGPT **只做告警看板**，不进智能体本体 |
| D3 | trace 格式 | 存储与查询格式**照 Langfuse 的 schema**，不自创；仍为本仓库自有文件 |
| D4 | 工具接口协议 | 按 **MCP** 定义；A2A 暂不引入（不做 Agent 网格） |
| D5 | 自研范围 | **只保留两块**：`rules/` 规则层（本项目领域壁垒）、评测集（`harness/replay.py` + `synthetic.py` fixture） |
| D6 | 明确排除 | AutoGen（停更）、n8n（fair-code）、任何平台型编排作为智能体本体 |

## 5. 对既有代码的影响

M0 已交付部分**不因本决策回滚**，仅追加接口侧的变化：

| 既有 | 处理 | 说明 |
|---|---|---|
| `agents/runtime.py`（自研单轮循环） | **保留，降级为无框架兜底路径** | 框架不可用时 `runtime.run` 仍可单轮跑通；`run(agent, user_input, trace) -> str` 签名不变 |
| `agents/trace/` | **保留，输出改为 Langfuse 兼容 JSONL** | `TraceWriter.write(kind, payload)` 契约不变，只加 schema 字段 |
| `agents/providers/` | **保留** | `fake` provider 是 C5 的落地，门禁 [4] 依赖它 |
| `harness/replay.py` | **保留，作为框架之上的评测器** | 只依赖 `providers` 与 `trace`，不依赖框架 API，因此换框架不必改评测器 |
| `harness/selftest.py` | **增补门禁 [6]** | 禁止 AutoGen/n8n 出现在 `src/`、`harness/`、`tools/` 的 import 中 |
| `CLAUDE.md §5` | 增补选型结论 | 供两名成员提交 PR 时自查 |

> **顺序要求**：任何第三方框架的引入**必须晚于** §7 的两项前置条件
> （LICENSE 已定、Notices 已登记），否则不接受 PR。

## 6. SPEC §4 六项能力的最终落点

| spec §4 能力 | M0 已做 | M3 起由谁负责 |
|---|---|---|
| provider 抽象 | ✅ 自研 | 自研（保持，框架通过适配器接入） |
| trace 留痕 | ✅ 自研 | 自研 + Langfuse schema |
| 单轮循环 | ✅ 自研 | **由 LangGraph graph 执行器替换**，`runtime.run` 保留兜底 |
| 角色声明式配置 | 未做 | 框架的 node/state 定义 |
| 工具注册 | 未做 | 框架 tool 机制 + MCP 适配层 |
| 消息路由 / 共享黑板 | 未做 | 框架 state + 自研 `memory/` |

## 7. 风险与回退

| 风险 | 触发条件 | 回退方案 |
|---|---|---|
| 接入框架后 replay 结果改变 | M3 后同 seed 下 SHA256 与 M0 基线不一致 | `logs/replay_<seed>` 按框架版本分目录存放，旧结果保留；门禁 [4] 增加版本前缀断言，不允许覆盖历史基线 |
| 团队跑不通 LangGraph 复杂图 | 两人内无法跑通第一个 graph | 按 §3.2 降级 Pydantic AI；`runtime.run` / `replay.py` 不受影响 |
| 引入第三方依赖违反"纯标准库"约束 | 门禁 [2] 扫描命中 | 需在 Global Constraints 显式豁免并登记 Notices，一律走 PR 评审 |
| fair-code 组件混入 | 有人图快引入 n8n | LICENSE 未定前禁止；门禁 [6] 显式拦截 |
| 模型侧不可复现 | 接真实 API 后同 seed 不同结果 | 正式指标改用多次运行分布的均值与极差，并在报告中如实说明（沿用 M0 已记录口径） |

## 8. 待决事项

1. **仓库 LICENSE**：本仓库 PUBLIC 且默认"保留所有权利"。正式引入 LangGraph /
   Langfuse 前必须定稿，并在 `README` 的 Notices 中逐项登记（见 issue #20 评论）
2. **台站设备侧是否支持 MCP server**：若设备侧无标准协议可接入，M4 之前需引入
   `browser-use`（~115k star）作为兜底方案，届时应另立 ADR
3. **看板是否采用 Dify/FastGPT**：M5 前决定，需单独评估部署成本与数据出境责任
