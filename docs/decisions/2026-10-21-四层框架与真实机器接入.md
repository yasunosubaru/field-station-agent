# ADR-007：四层框架的对外口径与真实机器接入路线

- 状态：Accepted
- 日期：2026-10-21
- 关联：老师口述的四层框架（语音转文字稿，非正式文档）、issue #32 / #64 / #67 / #68、
  spec §3 / §6、ADR-005（M5 集成通道）、ADR-006（API 通道选型）

## 背景

老师口述了一份四层框架：**接入层 → 数据采集层 → 数据分析层 → 问题归纳层**。它想描述的是
**真实机器上的运行形态**——设备接进来、定时采集、分析、出问题报出去——这个意图是清楚的，
也是我们目前最缺的一环（现在全部在文件与回放上跑）。

但它是语音转文字：技术选型与实现细节有明显漏洞，不能照单实现：

- 远程开串口 / SSH 隧道**没有审批与审计**，等于给台站开一个无闸门的远程控制口；
- Kafka / MQTT / Redis / ELK / Prometheus / Docker / K8s 全家桶，与「三人团队、没有真实
  设备」的现状不匹配，且会破坏「仅标准库、离线可复现」这条卖点；
- 没有验收标准、没有数据来源与许可、没有失败分类；
- **四层里没有「智能体」的位置**，而项目标题就是「利用 AI 智能体构建野外台站管理系统」。

所以需要把两件事分开定下来：**对外怎么说**（答辩与结题报告的口径）和**内部怎么做**
（现有链路与新增增量）。

## 决定

1. **四层作为部署形态与对外口径**：接入 → 采集 → 分析 → **检测与上报**。
   原「问题归纳层」改称「检测与上报」——归纳是分析层的事，检测与上报才是这一层的职责；
   不改名会被评审追问「归纳出了什么」。
2. **内核不变**：五阶段链（接入/质控/设备状态/研判/调度）+ 三层约束（模型归因 / 规则裁决 /
   人工审批）+ 证据链 + 确定性回放。四层回答「跑在哪、怎么连设备」，不替代「怎么判断、
   凭什么信、谁批准」。
3. **真实机器接入按四个增量推进**，每项都要过 DoD（测试 / 回放 / 数字回源）：
   - 任务调度 + 台账「任务失败」分类（定时未执行、轮询超时）；
   - 设备心跳（在线 ≠ 读数正常）；
   - 上报通道（Webhook，默认 dry-run，CI 不联网）；
   - 实时设备适配（串口 / 网口 + 桩），文件格式解析仍归 #32。
4. **不引入中间件与重框架**：Kafka / MQTT / Redis / ELK / Prometheus / Docker / K8s /
   Drools / SimPy 一律不引入。理由：没有可验证的设备与并发量；每引入一个组件，
   「别人能不能一键跑起来」就更难一分；三人本科团队没有运维余量。
5. **远程控制必须过审批门 + 审计**：远程开串口 / 下发指令若真要做，落成
   「审批 → 命令包 → 审计」三件套，与现有高风险动作同一条路；**不实现 SSH 隧道**。
6. **接口先 CLI + JSON 契约**：HTTP API 仅在明确需要 Web 界面时再加，且只读优先。
   老师列的七个 REST 接口是形态参考，不是当前要交付的规格。

## 四层与五阶段链的映射

| 四层（对外） | 现有实现 | 覆盖 | 缺什么 |
|---|---|---|---|
| 接入层 | `ingest/`（RINEX 2/3、CSV）+ `data/public/` 清单 | ~40% | 串口 / 网口实时接入、NMEA、远程控制 |
| 数据采集层 | 归一观测对象、合成/真实隔离归档、sha256 清单、原子写 | ~60% | 数据库 / 索引、入库去重（幂等）、断点续传 |
| 数据分析层 | 质控判据、设备健康度、研判结论契约、回放复校 | ~70% | 仿真推演、预测（**回放 ≠ 仿真**） |
| 检测与上报 | 设备降级告警、工单与审批审计、六类失败台账、静态看板 | ~60% | 心跳、任务监控、推送通道 |
| **（四层没有）决策与审批** | 总线 / 黑板 / 结论契约 / 证据链 / 审批门 / 台账 | — | — |

## 被否的方案

- **照搬四层 + 中间件全家桶**：不可验证（没有设备、没有并发量），运维面过大，
  且会把「离线可复现」这条已经验证过的性质弄丢。
- **按四层重写现有链路**：现有链路有回放基线、证据链与 481 条测试；重写等于把
  已经拿到的证据全部作废。
- **用 SimPy 做「仿真推演」替代回放**：回放是**验证**（同输入必须同输出），仿真是
  **生成假设场景**。要做也是先做注入式场景（`harness/dryrun_trial.py` 已在做），
  不是引入仿真框架。
- **SSH 隧道直连设备**：安全敏感、无运维能力；且与审批门的设计直接冲突。
- **把语音稿当规格逐条实现**：稿子自己承认是「大体意思」；逐条实现会把漏洞一起实现。

## 后果

- 结题报告 §4 用四层口径叙述，但每个数字与证据仍指向五阶段链的日志与回放基线；
- 真实机器到位前，适配器用桩 + 回放验证；到位后**只换适配器，不动链路**；
- 新增 M6-4 / M6-5 / M6-6 三个 issue（调度与任务失败、心跳、上报通道），
  #32 扩展实时设备适配；
- 「问题归纳层」一词在对外材料中不再使用，统一「检测与上报」；
- 如果老师坚持要远程控制，先走 ADR 修订，不在代码里悄悄开通道。
