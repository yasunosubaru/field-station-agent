# ADR-008：壳与四个视角（OpenChamber fork · 四视角等价 · 套件台）

- 状态：**Accepted**（2026-11-04 负责人确认：四台等价、名字用「套件台」）
- 日期：2026-11-04
- 关联：ADR-009（引擎分层）、`docs/spec/2026-11-04-v3-四视角双运行时.md`
- 结论一句话：**壳用 OpenChamber 的源码 fork；四个台是同一套内核的四个等价视角，不是四种人、不是权限分区；第四个台叫「套件台」。**

---

## 1. 为什么要定这件事

0.2.0 的界面是自己写的三栏，四个台的说法一直含糊：一会儿按"用户角色"分，一会儿按"功能模块"分。
负责人的口径很清楚：

> 四台没有明确的区分，不存在什么特定的人，这四台是相互同等、相互等价的，只不过视角不同，
> 这四个都能有完整的全功能。

所以它不是"四个应用"，也不是"四个角色"，而是**一个产品里的四个工作区布局**。

## 2. 决定

### 2.1 壳：OpenChamber 源码 fork

- 界面层取 OpenChamber 2.5.3 的 `packages/ui` + `packages/web`（MIT），保留其主题系统、
  会话/流式/Markdown/文件、工具与面板的渲染契约；
- 外层容器**仍用现有 WinForms + WebView2**（起本地服务 → 读端口 → 指过去），
  不默认引 Electron（省约 400 MB）；将来需要托盘/多窗口再评估；
- 剥掉它的云/中继/遥测与 coding 专用面，保留可复用的工作区与面板能力。

### 2.2 四个视角等价

| 视角 | 默认摆什么 | 能力 |
|---|---|---|
| 对话 | 会话、工具卡、审批卡 | **全部** |
| 编队 | bot 列表、日程、任务树、交互抽屉 | **全部** |
| 数据 | 批次、质控、检索、评测 | **全部** |
| 套件 | 六页签、8 条流程、证据抽屉 | **全部** |

规则：

1. **能力不分区**：任何视角都能发起任何动作；
2. **状态共享**：同一会话池、同一任务表、同一批工具、同一条 trace；
3. **跨视角深链是硬要求**：对话里的 job 卡片能跳到套件台的闸门；套件台选中的设备能跳回编队台建任务。
   做不到这条，四个台就还是四个 app。

### 2.3 命名

第四个台统一叫 **套件台（Suite）**，替换文档与代码里的"专业面板 / 专业台"。

## 3. 未采用

| 候选 | 为什么不用 |
|---|---|
| Open WebUI | 聊天中心的产品形态；另外三个视角只能挂侧边，与"等价"冲突 |
| LibreChat / LobeHub | 同上，且要常驻 Mongo/Postgres，便携性差 |
| 只留 WinForms + 自写页面 | 每加一个视角都要自己写布局，正是这次的痛点 |
| 默认 Electron | +400 MB，且我们已有可用的 WebView2 壳 |

## 4. 验收

1. 四个视角都能进，导航/主题同一套；
2. 任一视角能发起全部四类动作（对话提问、bot 派活、查数据、跑流程）；
3. 跨视角深链双向可用；
4. 断网可用；干净机双击可起。
