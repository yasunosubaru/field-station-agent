# ADR-008：界面底座改用 Open WebUI，四个台都长在成熟框架上

- 状态：**Proposed**（等负责人批准后改 Accepted）
- 日期：2026-11-04
- 关联：ADR-001（运行时）、ADR-007（四层口径）、issue #112 / #113 / #114、`docs/spec/2026-11-04-v2-四台七引擎.md`
- 结论一句话：**四个台不再自己写界面，统一长在 Open WebUI（fork）上；三个台用它的原生页面，只有「专业台」是我们自己的一个路由（它是显示层）。**

---

## 1. 这个决策要解决什么

0.2.0 的界面是我们自己写的（`逆向/04_重实现/packages/app/src/web/`，约 2 万行 CSS/JS 手写三栏 + 卡片）。
它证明了两件事：**能把事做出来**，以及**再往上加界面会失控**——每多一个台，就多一套自己的布局、
空态、表格、表单、弹窗、权限与审计显示，全部要自己维护。

负责人 2026-11-04 的要求很直接：

> 这四个台都要有面向人的界面，建议你别自己写，框架就用我之前附加文件给你的成熟框架，你就在上面深度特化定制化就行。

所以要定的是三件事：

1. 用哪个成熟框架做底座；
2. 四个台分别长在它的哪个面上（哪些是原生、哪些是特化）；
3. 许可证、体积、离线、单 EXE 这几条硬约束还成不成立。

## 2. 候选（只从负责人给的那份清单里选）

| 候选 | 类型 | 为什么不是它 |
|---|---|---|
| **Open WebUI** | Chat UI + Workspace + Admin，Python 后端 + SvelteKit | **选它**，见 §3 |
| LibreChat | Chat UI，React + MongoDB | 要常驻 Mongo；便携单 EXE 里再加一个数据库服务不划算 |
| LobeHub | Chat + Agent + 知识库，Next.js | UI 最漂亮，但 2.0 后强制 Postgres；部署与体积对我们过重 |
| AnythingLLM / Dify / FastGPT | 知识库 / 工作流平台 | 业务流编排强、设备侧弱；我们是「驱动厂商软件」不是「搭业务流程」 |
| Cherry Studio | 桌面 Electron 客户端 | 它本身是客户端，我们要的是「四个台一个产品」；且它没有 Python 后端可挂引擎 |
| OpenMausBot / Orca / open-duet | Agent Workspace 派 | 借它们的**模式**（每个 bot 独立工作区/记忆），不引它们的壳：再嵌一层前端就是两套 UI |

## 3. 决定

**底座：Open WebUI（fork 一份，版本固定）。**

选它的四条理由，按权重：

1. **后端就是 Python 3.11 + FastAPI。** 我们的七个引擎全是 Python，可以直接同进程挂载，
   不用再造一层 Node 桥；它默认 **SQLite**，和我们的台账天然同库同备份。
2. **它已经把「面向人」的东西做完了**：会话、流式、Markdown/代码块、文件上传、知识库、
   模型管理、用户与权限、管理后台、深浅主题、i18n。这些正是我们手写界面里最贵、最容易做丑的部分。
3. **扩展点是官方接口，不是 hack**：原生 **MCP（Streamable HTTP）** 接我们的工具面；
   **Pipe Function** 允许把一个自定义模型接进来——正好把 LangGraph 循环挂成「一个模型」。
4. **许可证允许 fork**：Open WebUI License（BSD-3-Clause + 品牌条款）。条款只约束
   「≥50 用户/30 天」的部署，我们单机单用户，但**仍然保留 "Open WebUI" 署名并声明是 fork**，
   不去碰这条线。

**四个台的映射（三个原生 + 一个自建）：**

| 台 | 长在哪 | 我们特化什么 |
|---|---|---|
| ① 会话台 | 原生 Chat | 挂 Pipe（LangGraph 循环）、工具卡渲染我们的领域工具、审批卡走 Actions |
| ② Bot 台 | 原生 Workspace → Models（一个 bot = 一个 workspace model，自带提示词/知识/工具）+ 新增 `/fleet` 看板路由 | 每个 bot 的工作区、记忆条数、今日任务、失败原因；暂停/接管；派活全流程 |
| ③ 专业台 | **新增 `/pro` 路由**（唯一自建页面，纯显示层） | NovAtel 六页签镜像 + 8 条流程 + 证据抽屉；视觉重做（`panels/modern.css` 覆盖皮肤） |
| ④ 数据台 | 原生 Workspace → Knowledge / Files + 新增 `/data` 路由 | 观测批次、质控通过率、迟滞设备、数据缺口；数据集版本与评测得分 |

`/fleet`、`/data`、`/pro` 都是同一个 SvelteKit 工程里的路由，**复用 Open WebUI 自己的组件与主题**，
不新写框架、不引第二套设计系统。

## 4. 代价（先说清楚）

| 项 | 代价 | 处置 |
|---|---|---|
| 依赖 | 后端依赖变多（fastapi / sqlalchemy / uvicorn / chromadb / onnxruntime 等），解压后估计 400–500 MB | 只装 CPU 版、去掉用不到的（如 whisper/TTS）；预算是 W0 的事，实测后写进本文 |
| 向量库重叠 | 它自带 Chroma，原计划用 LanceDB | **只留 Chroma**：LlamaIndex 用 chroma 作为向量后端，一份库两处读（Open WebUI 的知识页浏览 + 我们的 `fsa.kb.search`） |
| 品牌条款 | ≥50 用户不得改标识 | 单机单用户；保留署名 + 「fork，非官方」声明 |
| 上游漂移 | fork 之后跟版成本 | 固定 tag，只在 `docs/upstream/openwebui.md` 记录我们改了哪些文件；不追 main |
| 语言 | 它默认英文 | `zh-CN` 语言包 + 我们三个路由自己写中文文案 |

## 5. 未采用

- **不再引 OpenChamber**：它是给 coding agent 用的壳，没有 Workspace/知识库/管理面，
  四个台里三个要自己补——正是这次要终止的做法。
- **不再引 OpenCode 当宿主循环**（原方案 A 的 247 MB 单二进制）：底座换了之后用不到，
  LangGraph 直接作 Pipe，详见 ADR-009。
- **不引 Claude Code Best 当内核**：仓库无 LICENSE，是逆向的 Anthropic 产品；只借它的
  workflow-engine 与回放思路（已在 `harness/` 里体现）。
- **不自己写第二套设计系统**：颜色/字号/圆角全部走 Open WebUI 的主题变量，专业台用覆盖皮肤，
  不许再出现第三套 token。

## 6. 怎么验证这条决策成立了

1. fork 起来能 `serve`，中文界面，深色，单机无云；
2. ① 会话台能跑通一次「问健康度 → 调 `fsa.station.health` → 回答」；
3. ③ `/pro` 能显示六页签里至少 Manage 与 Workflows 的真实数据；
4. ④ 知识库能检索到入库的 NovAtel 帮助原文；
5. ② bot 列表能看到至少 2 个 bot 与它们今天跑过的任务；
6. 卸载/断网仍可用（模型走本地或已配置的 API）。

任一条不成立，回到本文改决策，不在代码里打补丁。
