# ADR-004：Agent 归因结论契约

- 状态：Accepted
- 日期：2026-10-18
- 关联：issue #52、#53

## 背景

自由文本无法机械区分“看起来有依据”和“真的引用了工具输出”。M3 的可追溯硬指标要求每条结论都能回到成功执行过的工具调用。

## 决定

Agent 最终结论只接受单个 JSON object：

```json
{
  "attribution": {
    "fault_type": "nonphysical_rmse",
    "evidence": [
      {
        "call_id": "t0001",
        "tool": "magnitude_verdict",
        "finding": "RMSE 超过物理上限"
      }
    ]
  },
  "recommendation": "拒绝该输出并复查定平链路",
  "confidence": 0.99
}
```

校验规则：

1. 顶层字段只能是 `attribution / recommendation / confidence`。
2. `evidence` 至少一条；`call_id` 必须对应一条 `tool_result.ok=true` 的 trace 事件。
3. `evidence.tool` 必须与该 `call_id` 的工具名一致。
4. 同一 `call_id` 不得重复引用。
5. `confidence` 必须是有限数值且在 `[0, 1]`。
6. 校验失败时 runtime 抛 `ConclusionRejected`，trace 写 `conclusion_rejected`，不得把自由文本当有效结论返回。

## Trace

- `tool_call` 与 `tool_result` 共用稳定的 `call_id`（`t0001` 起）。
- 契约校验通过时写 `conclusion_valid`，记录结论摘要与引用的 `call_id`。
- 工具入参写入 trace；需要完整工具返回时由 `capture_tool_results=True` 显式开启。
- token 与耗时写独立的 metrics sink，不混入要求逐字节可复现的决策 trace。

## 后果

M4 的五类 Agent 复用同一契约。修改字段或放宽证据要求必须新增 ADR，不能只改 prompt。
