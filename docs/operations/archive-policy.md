# 归档策略（M4-4）

状态：初版（2026-10-19）

M4-4 的步骤里写着「定归档策略（放哪、留多久、怎么命名）」。这份文件把三件事
分别定下来，并把「不做」的部分也写明——留着不定的部分没人知道边界在哪。

## 放哪

- 归档根目录由**调用方**在装配时给定（`ArchiveExportTool(root=...)`），工具不
  自己猜路径。当前接线（测试与 `harness/m4_agents_replay.py` 回放）都用临时
  目录；真实部署时接外部存储（移动硬盘 / 备份盘），与 `store/product.py` 的
  隔离口径一致。
- 产物一律走 `store.product.py` 的 `write_*` 落盘，**不允许调用方自己拼
  `synthetic/` 路径**——隔离由同一个函数保证，绕过它等于把这道约束关掉。

## 怎么命名

- 相对路径由调用方给定，工具只接收和校验（拒绝绝对路径与 `..` 逃逸）。
- `synthetic=true` 时由 `store/product.py::_isolated` 强制改写为
  `<父目录>/synthetic/SYNTHETIC_<原文件名>`，且**幂等**：文件名已带
  `SYNTHETIC_` 前缀、父目录已是 `synthetic/` 时不叠加第二遍。
- 合成产物的 JSON 载荷里带 `_synthetic_note` 标记，文件名前缀与标记同时存在，
  两层都可核对（`tests/test_m4_archive.py` 钉死）。

## 留多久

- **初期不做自动清理，也不做过期删除。** 数据量小、磁盘便宜，而自动删除是
  这个项目里最容易造成不可逆损失的一类动作；没有真实数据量与存储预算之前，
  定保留期只会定出一个没人验证过的数字。
- 真实数据接入、存储预算明确之后，保留期与清理策略另起 ADR，并在门禁里加
  对应的核对（例如「归档目录随备份校验通过」）。

## 隔离红线

- 合成数据不得与真实数据混放：`synthetic/` 子目录 + `SYNTHETIC_` 前缀是
  机械可查的判据，而不是口头约定。
- 高风险设备动作的归档同理：命令包与执行记录只能经 `store/product.py` 落盘。
