## 2. 指标定义

### Q1 故障发现时滞（主指标）

对纳入的每个故障事件 `e`：

- `t_occur(e)`：故障真实发生时间（来自 M1-b 口径的运维记录/标注；精确到分钟）；
- `t_detect(e)`：系统首次产生对应告警的时间（`alert` 首次写入或告警消息时间，
  取更早者）；
- 时滞 `Δ(e) = t_detect(e) − t_occur(e)`（秒）。

报告 `median(Δ)` 与 IQR（P25–P75），以及事件数 `n`。

**基线**：`Δ_base` 用 M1-b 的同一口径（人工发现时间 − 真实发生时间）。
**缩短比例**：`R = 1 − median(Δ_sys) / median(Δ_base)`。

- 优先**配对**：同一事件在基线与系统下都有观测；否则只能做描述性对比，并明确写
  「非配对，不声称因果」。
- 基线拿不到时：**不使用估计值当分母**；Q1 改为可自证指标（见 §5）。

### Q2 归因准确率

- 每个标注样本有唯一 gold `fault_type`；系统输出 `attribution.fault_type`。
- 每类 `P_c = TP_c / (TP_c + FP_c)`、`R_c = TP_c / (TP_c + FN_c)`、
  `F1_c = 2P_cR_c / (P_c + R_c)`；**macro-F1 = 各类 F1 的算术平均**（不按样本数加权，
  避免大类淹没小类）。
- 同时报告混淆矩阵与每类支持数；类别集合以标注指南为准，评估前冻结。
- 标注一致性：双人独立标注，Cohen's κ；**κ < 0.6 先修指南再评估**，不拿分歧数据
  硬算。

### Q3 结论可追溯率

对每条结论：

- 记 1，当且仅当它的 `evidence_call_ids` **全部**能在同一阶段的
  `tool_result(ok=true)` 事件里找到（`--verify-log` 已在做同一件事）；
- 否则记 0，并记录原因（call_id 缺失 / 工具失败 / 跨阶段引用）。

`可追溯率 = 通过数 / 结论数`。目标 **100%**（这是机械性质，不是统计指标）。

### Q4 告警精确率 / 召回率

- gold 事件来自台账/标注；系统告警与事件的匹配规则**预先固定**：
  同一台站 + 同一类型 + 时间差 ≤ **W = 15 分钟**（W 在试运行开始前冻结）。
- `precision = TP / (TP + FP)`、`recall = TP / (TP + FN)`；同时报告 FP/FN 清单
  （类型、台站、时间），不只报一个比例。

### Q5 人工介入

- 每事件统计：审批次数（`approval` 事件数）、人工补录/修正次数、从告警到工单批准
  的等待时间（若有人工审批）。
- 报告 `median` 与 IQR；审批拒绝路径单独计数（拒绝不是失败，是正确行为）。

### Q6 成本

- token：`prompt_tokens` / `completion_tokens`，按事件与阶段汇总（来自
  `logs/*_metrics.jsonl` 的旁路，不进基线 sha）。
- 耗时：provider 与工具调用的 `duration_ms`，报告 median 与 P90；注明机器与模型。
- 本地通道与 API 通道各一组；API 不可得时如实写「仅本地」并标注模型规模。

### Q7 稳定性

- 同一输入、固定 seed、`temperature=0` 重复 **N=5** 次：
  - 结论 `fault_type` 的一致率；
  - trace 是否逐字节相同（本地 fake/固定 seed 通道应当相同；真实模型通道单独报）。
- API 通道若在 `temperature=0` 下不能复现，按 spec §5 改报「5 次运行的均值与极差」，
  不声称可复现。

## 3. 数据与样本

- **纳入**：试运行期内、数据源可用的全部故障事件；事件必须有 `t_occur` 与可核对的
  检测记录。缺 `t_occur` 的事件单列「无法配对」，不删除、不插补。
- **排除**：只有「数据源中断」而没有故障事件的时段，不进入 Q1；其可用性进 M6-1 台账。
- **样本量**：主指标目标 `n ≥ 30`；不足 30 时照实报告 n 与区间，并标注「探索性」，
  不做事后加样本。
- **标注集**（Q2/Q4）：按 #54 的指南；标注文件、仲裁记录与 κ 一并入库。

## 4. 统计方法

- 集中趋势：中位数 + IQR（不假设正态）。
- 区间：bootstrap 百分位 95% CI，**1000 次重采样，seed=42**；配对设计按事件重采样。
- 配对比较：`n ≥ 10` 且配对成立时用 Wilcoxon signed-rank；否则只做描述性对比。
- 多重比较：Q1 单独判定；Q2–Q7 报效应量与 CI，不宣称「显著」。
- 缺失值：不插补；在表中注明缺失数与原因。

## 5. 判定规则（先写死）

| 指标 | 判定 |
|---|---|
| Q1 | **成立**当且仅当 `R ≥ 50%` 且 bootstrap 95% CI 下界 > 0（配对/同口径）。不成立就照实写实际值，不宣称达标 |
| Q1（无基线） | 报「告警→工单时延」与「人工介入次数」的绝对值；明确标注「无基线对比」，不计算 R |
| Q2 | 报 macro-F1 与 95% CI；不设事后及格线。若团队要设门槛，必须在试运行前写进本文档 |
| Q3 | 目标 100%；任何 <100% 逐条列原因 |
| Q4 | 同时报 precision 与 recall 及 FP/FN 清单；不合成单一分数 |
| Q5–Q7 | 报中位数/IQR、均值/极差（稳定性）与样本量；不做「更好/更差」的显著性宣称 |

## 9. 效度威胁与不声称的内容

- **样本**：单站、短周期、合成/真实样本比例；结论不外推到其他台站。
- **基线口径**：M1-b 的「发现时间」若与系统口径不同，必须写明差异；不做口径换算
  上的猜测。
- **标注主观性**：κ 与仲裁记录公开；κ 低时结论降级为「探索性」。
- **模型漂移与通道差异**：本地模型与 API 分开报；换模型/版本要重跑。
- **人为因素**：审批等待时间受值班安排影响，单独列，不混入系统时滞。
- **不声称**：因果、泛化、超过样本量的精度、「50%」在 CI 跨 0 时成立。
