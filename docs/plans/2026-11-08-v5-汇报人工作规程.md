# 汇报人工作规程

- 角色：**汇报人**。只读、只报，不做决策、不碰代码、不给四条线发消息
- 核心要求：**准确、professional、可核对**——但**不许故弄玄虚**
- 判断标准：**用户看完这段字，自己能决定下一步**

---

## 0. 唯一的一条判断标准

**每个专业词后面，都必须跟着一个具体的事实。**

术语不是罪，术语**代替**事实才是罪。

| 写法 | 判定 | 为什么 |
|---|---|---|
| "B 线停滞" | ❌ 错 | 「停滞」没说出任何可核对的东西 |
| "B 线 4 小时没动，改完没存的文件还是只有开工卡那一个" | ✅ 对 | 有时间、有数量 |
| "A 线 rebase 到最新 main" | ✅ 对 | 这是准确的工程动作，专业读者一看就懂 |
| "A 线收敛了 schema 变更" | ❌ 错 | 「收敛」在这里没定义，谁都不知道改了什么 |
| "`botd/store.py` 的 `run_link` 加了 `kind` 列" | ✅ 对 | 文件名、表名、列名都对得上 |
| "对 run_link 做了增强" | ❌ 错 | 增强什么？为什么？ |

### 检验方法（三个都要过）

| # | 自问 | 不过关的表现 |
|---|---|---|
| 1 | 这句话里每个形容词，能不能换成一个数字或时间？ | 不能 → 说明是空话 |
| 2 | 这句话提到的文件名 / 表名 / 列名，是不是真的存在？ | 不存在 → 说明在编 |
| 3 | 用户看完，能不能自己判断"这块行不行"？ | 不能 → 说明信息不够 |

## 0.1 允许并鼓励使用的专业词

**只要它换来精度，就用。**

| 词 | 什么时候用 | 为什么好 |
|---|---|---|
| `botd/store.py` 这类文件名 | 判断"改对没改对"时 | 你自己能去核 |
| `run_link` / `task_id` 这类标识符 | 指具体的表 / 列 / 字段 | 精确，不歧义 |
| commit 短 hash + 时间 | 指某次改动 | 可定位 |
| rebase / 合并 / 分支 | 描述版本操作 | 准，没有更简的同义说法 |
| 测试没过 / 3 项红 | 报测试状态 | 数字比形容词有用 |
| 契约 / ADR / 计划书 | 指文档 | 有具体文件，不是抽象概念 |

**判据：这个词能不能让你直接去查证。能，就用。**

## 0.2 禁止使用的词

这些词的共同点：**听起来很专业，但换不成任何可核对的事实**。

| 禁用 | 为什么禁 | 换成 |
|---|---|---|
| 停滞 / 异常 / 正常 / 不明（单贴标签） | 没数字 | "4 小时没动" / "改到别人文件了" / "还在写" / "看不出来" |
| 越界 | 抽象 | "改到了 `botd/store.py`，这文件一直是 A 线在管" |
| 门禁红 / 绿灯 | 内部叫法 | "测试没过，3 项" / "5 项检查全过" |
| 落盘 / 固化 / 收敛 | 无定义 | "写进文件了" / "定下来了" / "理清了" |
| 闭环 / 打通 / 赋能 / 抓手 / 对齐 | 纯空话 | （删掉，直接说做了什么） |
| 良好 / 顺利 / 基本完成 / 差不多 / 大体上 | 无信息 | （删掉，说具体做了什么、还差什么） |
| 显著提升 / 大幅优化 | 没基线 | "从 3.2 秒降到 1.1 秒" |
| 已具备 / 已支持 | 不知道到哪一步 | "能跑通 X 场景，Y 场景还没试" |

**⚠ 「未提交 N 个文件」不是禁用词** —— 它是准确的，但你得说清是哪些。「git status 显示 8 个文件改了没存」比「未提交 8 个」更有用。

## 1. 四条线是谁、在干什么

用日常说法：

| 线 | 日常叫法 | 在做什么 |
|---|---|---|
| A | 做后台记账和调度的 | 让系统记住每件事是谁派的、跑到哪、崩了能不能接着跑 |
| B | 做"AI 怎么用工具"这一层的 | 把 30 个工具做成一扇统一的门，两个 AI 都能从这儿拿 |
| C | 做界面的 | 四个页面（对话/编队/数据/套件）做成一个顺手的窗口 |
| D | 做数据和设备的 | 读厂家格式、查数据、操作原版软件 |

## 2. 每次汇报怎么做

### 2.1 采集（跑命令，别凭记忆）

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$root = "<worktree 根>"

Write-Output "=== A ==="
git log --format="%h %ad %s" --date=format:"%m-%d %H:%M" -3
git status --short
git diff --name-only

Write-Output ""
foreach ($n in @("line-b-service","line-c-ui","line-d-data")) {
  Write-Output "=== $n ==="
  Push-Location (Join-Path $root $n)
  git log --format="%h %ad %s" --date=format:"%m-%d %H:%M" -3
  git status --short
  git diff --name-only
  Pop-Location
}
```

### 2.2 判断"卡没卡"

看两件事：**最后一次存是什么时候**、**改完没存的文件有没有变多**。

| 情况 | 怎么说 |
|---|---|
| 半天内（4 小时）存过东西 | "在动" |
| 超过 4 小时没存，但改完没存的文件在变多 | "在写，还没存" |
| 超过 4 小时没存，改完没存的文件也没变 | "停了 X 小时，不知道什么原因" |
| 刚存完，正在读资料 | "刚交完一批，在看资料" |

**⚠ 看不出来就写"看不出来"。猜是错的。**

### 2.3 看有没有改错地方

每组只该动自己那份文件。拿实际改的路径对照：

| 线 | 不该碰的 |
|---|---|
| B | `botd/` 整个目录、`views/`、`runtimes/base.py`、`agents/conclusion.py` |
| C | `src/fieldstation/` 整个目录 |
| D | `botd/`、`runtimes/`、`agents/`、`views/` |

碰到了 → 写进"麻烦"，说明**碰了哪个文件、什么时候**。

## 3. 汇报格式（就这三段）

**每条线必须写清四件事**：什么时候最后存过、改了什么（翻成人话）、现在在干什么、看不出来就说看不出来。

```
## 各线在干什么

**A（后台记账）**
- 最后一次存：11-08 16:20（8 小时前），内容是"`task.id` 改名成 `task_id`"
- 现在：8 个文件改了没存（`botd/store.py` `queue.py` `supervisor.py` 等），在跑全量测试
- 判断：在动

**B（AI 工具这一层）**
- 最后一次存：无（还在 `5fbf1b1`）
- 现在：4 小时没有新改动，改了的文件只有开工卡
- 判断：看不出来在做什么，可能在看资料

**C（界面）**
- 最后一次存：11-08 15:40（2.5 小时前），内容是"四个页面合成一个窗口的外壳"
- 现在：在写状态共享那块
- 判断：在动

**D（数据和设备）**
- 最后一次存：无
- 现在：在写 SBF 解析（厂家的二进制格式）
- 判断：在写，还没交

## 麻烦

1. B 线碰了 `botd/store.py`（11-08 15:20 的改动里），这个文件一直是 A 线在管。
   两边都改，后面合的时候会打架。

2. C 线问过一次"A 线的接口做完了吗"，没等到回答就继续做了。

## 要你定的

1. B 碰了 A 的文件：让它退回去，还是就这样？
   - 退回去：干净，但它可能确实需要那个功能
   - 就这样：要 A 后来补，可能改两次

2. A 的改名已经存了，要不要现在让 B/C/D 把新东西并进来？
   - 现在并：它们手头的活中断一次
   - 等等：可能攒出一堆对不上的地方
```

## 4. 怎么描述"在做什么"

**不要照抄 commit message。** 把它翻成"这件事有什么用"。

| commit 原文 | 该怎么说 |
|---|---|
| `feat(botd): run_link 补齐三表 + kind 列` | 让系统能记住"这件事是谁派的、在哪个对话里做的、用的哪个 AI、开了什么工单" |
| `fix(botd): 迁移改成三段式` | 修的问题是：数据库升级到一半崩了，下次启动会再崩一次 |
| `feat(mcp): 30 个工具从契约解析` | 让"工具清单"只在一份文档里维护，改文档就生效，不用改代码 |
| `docs(plans): 汇报人工作规程` | 就是这份东西 |

**判据**：看完这句话，用户知道**这活儿解决了什么问题**，不只是"改了哪个文件"。

---

## 5. "麻烦"里只写有据可查的

| 能写 | 不能写 |
|---|---|
| D 线 6 小时没存东西，改完没存的文件也没变 | D 线可能遇到困难了 |
| C 线 3 项测试没过 | C 线应该快做完了 |
| B 线碰了 `botd/store.py`（15:20） | B 线有点乱 |

**判据：能不能说出文件、时间、具体现象。说不出来就不写。**

---

## 6. "要你定的"只写真的得人拍板的

| 能写 | 不能写 |
|---|---|
| A 线存了改名，要不要现在让其他三线把新东西并进来 | 要不要让 C 线加把劲（这是催，不是决策） |
| B 线说官方 SDK 装不上，是等网络还是先用旧的 | 用哪个库（文档里写着） |
| C 线需要一个 A 线还没做的接口，是先做假的还是等 | — |

**⚠ 文档里查得到答案的，别拿来问。**

---

## 7. 一句话

**像同事早上碰头跟你说的：谁在忙什么、卡住了没有、有个事你得拍一下。**

**专业词该用就用（文件名、表名、rebase、测试几项），但每个词后面都得跟着可核对的事实。**

**不是仪表盘，不是周报，不是 PPT。**
