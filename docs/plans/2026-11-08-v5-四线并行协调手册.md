## 2. 你每天要做的三件事

### 早上（5 分钟）

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$root = "<worktree 根>"
$main = "<仓库根>"

Write-Output "=== 四条线各自的最新提交 ==="
Push-Location $main; Write-Output ("A: " + (git log --oneline -1)); Pop-Location
foreach ($n in @("line-b-service","line-c-ui","line-d-data")) {
  Push-Location (Join-Path $root $n)
  Write-Output ("$n : " + (git log --oneline -1))
  $s = git status --short
  if ($s) { Write-Output ("    未提交: " + ($s | Measure-Object).Count + " 个文件") }
  Pop-Location
}
```

**看三样**：

| # | 看什么 | 意味着 |
|---|---|---|
| 1 | 有没有新提交 | 有进展 |
| 2 | 未提交文件多不多 | 多说明在做大改动，或在攒着 |
| 3 | A 线是否已提交 Bot-7 | 决定要不要通知 B/C/D rebase |

### 中途（按需）

**只在三种情况下主动发消息**：

| 情况 | 发什么 |
|---|---|
| A 线改了共用文件（`store.py` / `base.py` / `conclusion.py`） | 通知受影响的线 |
| 某条线卡住超过半天没动静 | 问「卡在哪，试过什么」 |
| 发现某条线越界改了别人的文件 | 立刻纠正 |

**⚠ 不要「每小时问一次进度」** —— 那会让它们把时间花在汇报上。

### 晚上（10 分钟）

```powershell
# 各线的提交汇总
Push-Location $main
git log --oneline --all --since="1 day ago" --graph
Pop-Location
```

**记三行**：

```
A：今天做完什么，明天做什么
B/C/D：同上
明天最该盯的一件事：
```


### 模板 2 · 通知共用文件已改

```
【协调方】共用文件已变更，请 rebase

- <文件2>：<改了什么>
```

```
- 报告需求（哪一行、要什么行为）

```

## 4. 合并策略

### 4.1 顺序（有依赖关系，不能随便）

```
第一轮：A 线（Bot-6/7 + Bot-1/2/8）
   ↓  因为 B/C 都依赖 store.py 的表结构
第二轮：B 线（工-1 / 智-*）
   ↓  因为 C 的对话视角要连 MCP
第三轮：C 线（视-0~6）
   ↓  因为它要读 B 和 A 的接口
第四轮：D 线（设/引/RPA）
   ↓  独立，但放最后避免干扰
```

**⚠ 但如果 D 线先完成，可以先合 D**（它和最前面的三条耦合最少）。
**原则是：被依赖的先合。**

### 4.2 合并方式

**这次不用「rebase 后 fast-forward」，用 merge commit。**

```powershell
# 在主工作区
Set-Location "<仓库根>"
git checkout main
git merge --no-ff line-b-service -m "merge: B 线 服务面（工-1 / 智-4 / 智-0b / 智-3 / 智-5）"
```

**为什么用 `--no-ff`**：

| 方式 | 后果 |
|---|---|
| `--no-ff`（保留 merge commit） | 历史里能看到「这是一条线」，出问题能整条回退 |
| fast-forward（拉平） | 分不清哪些 commit 是 B 线的 |
| squash | 丢掉中间过程，出问题无法定位到哪个 commit |

### 4.3 合并前必须做的三件事

| # | 做什么 | 为什么 |
|---|---|---|
| 1 | 那条线的分支上五个门禁全绿 | 门禁红的不许合 |
| 2 | `git diff --stat main...<branch>` 看过 | 确认没有意外的大文件 / 不该改的文件 |
| 3 | 检查有没有越界改别人的文件 | 越界的合进来会埋雷 |

**第 3 件的命令**：

```powershell
# 看 B 线改了哪些文件，人工对照「B 线不准改」的清单
git diff --name-only main...line-b-service
```

## 7. 一句话

**并行的难点不是「同时做」，是「不互相踩」。**

所以：

> 文件所有权先定死 → 共用文件归一个人 → 被依赖的先合 → 门禁绿才准合。

**四条线里只要有一条越界，四条都会红。** 发现越界要**当天**纠正，不要等到合并。
