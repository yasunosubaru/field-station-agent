- **依据（负责人原话）**：

- **这条是什么**：**做成一个应用窗口，不是四个 iframe 拼起来的容器。**
  外壳（顶栏 / 左导航 / 右栏 / 底栏）全局一份；中间主内容区**在同一个文档里换内容**。
  四个视角共享同一份状态（`state.ts` 单一 store），切换视角不重拉数据。
- **实测依据（2026-11-08 在真机上打开 Mrite 2.6.12 截的图，不是靠文档推测）**：

  | Mrite 的实际做法 | 本项目怎么做 |

  | 顶部一条状态条（Logo + 版本 + 一句话 + 头像），全局唯一 | 台站名 / 模型 / 运行时 / 端口 / 套件连接状态 |
  | 中间主内容区，**换页面只换中间** | 同一个文档换内容，**不是 iframe** |
  | 右侧常驻栏（公告 / PDF 预览），跟着当前页面变 | 会话信息 / 任务详情 / 批次信息 / 字段检查器 |
  | 底部状态条（激活状态 + 当前模型），永远在 | DBOS / LangGraph / Letta / 队列 状态 |
  | 一条主流程条**只在当前页面出现一次**（上传赛题→智能求解→生成论文→输出PDF） | 「提问 → 取数 → 判断 → 工单 → 证据」，**只在对话页出现**；它是**当前任务进度**，不是功能导航 |

  1. `pause` 后下一步不被领走（不是立刻抛异常）
  2. 正在跑的那一步**跑完**才停
  3. `resume` 后能继续
  4. `retry` 后 `attempts` 增加且新参数生效
  5. `takeover` 后 executor 不再被调用
  6. pending 的 pause **不等于**已暂停（与 `effective_boundary` 语义一致）
- **依赖**：Bot-1、Bot-2

## 4.5 全局准则：界面要像专门为这个项目做的

> 负责人原话（2026-11-08）：「就像 mrite 是专为数模设计的页面，最终整体软件的
> **用户操作界面也要顺手，条理清晰有逻辑，深度服务于这个项目的功能**」
> 「对比 Mrite 太粗糙，到时候要**像 mrite 那样专职化界面**就行」

这不是某一条任务，是**贯穿全部界面工作的准则**：

| 准则 | 具体判断 |
|---|---|
| **专职化，不是通用后台** | 每个控件都要能回答「这个项目为什么需要它」。放不进去的通用控件（用户管理、权限矩阵、租户切换）一律不要 |
| **一条主流程贯穿** | 提问 → 取数 → 判断 → 工单 → 证据。界面要让人看到自己现在在这条路径的哪一步 |
| **一个窗口，不是拼起来的** | 外壳（顶栏/左导航/右栏/底栏）全局一份；主内容区同页换内容；四视角共享一份状态 |
| **信息密度优先** | 这是运维台，不是营销页。数字等宽、单位小号、表格不画重线、密度可切 |
| **空态要说为什么** | 每个卡片没数据时必须写「没有数据 + 为什么」，不许只留一片空白 |

**验收口径**：拿 Mrite 的完成度当尺子。做不到那个程度的界面，不算做完。

**排期位置**：界面（视-0 ~ 视-6）可以放到后面做（负责人：「这个也可以放到后面做，就是个界面」），
但**接口要先定**，否则四个页面各写各的，再收就贵。
