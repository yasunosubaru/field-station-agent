# 数据字典

状态：草稿

> 主责：成员A（台站侧信息）+ 成员B（质控判据），见 [调研记录表](调研记录表.md)
> 门禁：`python tools/check_datadict.py` —— 状态改成「完成」后必填列的漏填会拦下来

## 这份表为什么有门禁

M1-a 的验收标准写着「每个字段都有单位与采样率」。用眼睛核对这句话等于没门禁，
提交者说填完了就当填完了。这个项目的铁律是**每个对外声明都要能由脚本回源核对**，
所以完整性判据交给机器：状态写「完成」而必填列留空，退出码非 0，PR 合不进来。

两种状态的区别：

| 状态 | 什么时候用 | 门禁行为 |
|---|---|---|
| `草稿` | M1 进行中，表还没填完 | 只报字段数与待补数，**不算失败** |
| `完成` | 声称填完了 | 必填列逐格核对，缺一即失败 |

分成两态是有意的。M1 开局的骨架表是空的，那不是缺陷 —— 把草稿态也判成失败，
门禁第一周就天天红，红久了就没人看了。

## 填表须知

**必填列**（七列）：字段、单位、采样率、单位类型、缺失标记、质控判据、来源设备。
**可留空**：允许范围、备注。

- `单位类型` 只能填 `数值` / `布尔` / `文本`，别的会被判成非法。
- `采样率` 写频率，如 `0.2 Hz`、`1/min`、`1/30s`。
- `缺失标记` 写设备用什么值表示缺测。**必须问清楚**，不能填 `0` 或 `null` 蒙过去 ——
  这一列错了，M3 的质控 Agent 会把缺测当正常值算进去。
- `质控判据` 写一句人话判据，如「越出 0–60 判异常」。写「暂无」不是判据；
  确实没有就填「待补：没有既判据，待与运维确认」。
- 暂时拿不到的填 `待补：原因`。**带原因的待补算填了，光写「待补」不算** ——
  「暂时拿不到」有信息量，「不知道」没有。
- 一行一个字段。表头不要改名也不要调顺序，脚本按列序读。
