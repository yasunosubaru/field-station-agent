# 新手上手：把代码跑起来

给第一次接触这个仓库的人。目标：半小时内在自己电脑上跑通全部测试，并且知道怎么
只跑自己那一个文件、怎么让程序停下来看变量。

跑通之后做什么，看 issue 与 [分工与后续工作](分工与后续工作.md)。

---

## 1. 先弄清一件事：这里没有「双击就能打开的软件」

这个仓库不是 exe，也不是网页。里面是三样东西：

| 目录 | 是什么 |
|---|---|
| `src/` | 系统本身的代码 |
| `tests/` | 测试，验证 `src/` 的代码对不对 |
| `harness/`、`tools/` | 仓库自己的检查工具 |

所以「打开程序」只有一种意思：**把代码放到本机一个文件夹里，用编辑器打开这个
文件夹，在编辑器自带的终端里敲命令**。没有安装步骤，也不需要装第三方库。

## 2. 装三样东西

| 要装的 | 版本要求 | 从哪装 |
|---|---|---|
| Python | 3.11 或更新 | python.org 下载安装包 |
| Git | 任意新版本 | git-scm.com |
| VS Code | 任意 | code.visualstudio.com |

装 Python 时**必须勾上 `Add python.exe to PATH`**，否则终端里敲 `python` 会报找不到。

装完开一个新的 PowerShell 验证，两行都要有版本号输出：

```powershell
python --version
git --version
```

## 3. 把仓库放到本机

```powershell
git clone https://github.com/yasunosubaru/field-station-agent.git
cd field-station-agent
```

`git clone` 会在当前目录下建一个 `field-station-agent` 文件夹。以后所有命令都在
**这个文件夹里**执行。

## 4. 用 VS Code 打开这个文件夹

```powershell
code .
```

`. ` 指的就是当前这个文件夹。或者用 VS Code 的「文件 → 打开文件夹」，选中
`field-station-agent`。

左侧能看到 `src`、`tests`、`harness` 这几个文件夹，就说明打开对了。

## 5. 在 VS Code 里开终端

按 **Ctrl + `**（反引号，Esc 下面、数字 1 左边那个键）。

终端出现在编辑器下半部分。**看一眼它显示的路径**：必须以 `field-station-agent`
结尾。不是的话，说明打开的是别的文件夹，或者终端落在子目录里 —— 先 `cd` 回仓库根目录。

下面所有命令，都在这个终端、这个目录下敲。

## 6. 第一件事：跑通全部测试

```powershell
$env:PYTHONPATH="src"
python -m unittest discover -s tests -t .
```

最后一行是 `OK` 就成功了。

两句各自的意思：

- `$env:PYTHONPATH="src"` —— 告诉 Python 去哪里找 `fieldstation` 这个包。代码在
  `src/` 下而不是仓库根目录，**不设这一句就会 `ModuleNotFoundError`**。它只对当前
  这个终端窗口有效，每开一个新终端都要重新设一次。
- 第二句是仓库的固定测试命令：从 `tests/` 里把测试都找出来跑一遍。

一个细节要记住：**输出里的跳过数必须是 0**。`unittest` 不把跳过当失败，静默跳过会让
门禁看起来是绿的，所以本仓库把「跳过数为 0」也当成一条判据。

## 7. 只跑自己那一个文件

写代码时不用每次都跑全量。三种粒度：

```powershell
# 只跑一个文件
python -m unittest tests.test_qc_stats -v

# 只跑文件里的一个类
python -m unittest tests.test_qc_stats.TestMedian -v

# 只跑一条用例
python -m unittest tests.test_qc_stats.TestMedian.test_odd_count_takes_middle -v
```

写法规律：**文件路径的斜杠换成点，`.py` 去掉**，后面可以继续跟类名、方法名。

`-v` 会把每条用例一行行打出来，哪条红哪条绿一眼看清；去掉 `-v` 只剩最后的汇总。

## 8. 让程序停下来看变量（断点调试）

1. 在 VS Code 里点行号**左边**的空白处，出现红点，就是断点。
2. 按 **F5** 启动调试。第一次会让你选配置，选 `Python File`。
3. 程序停在那行，左侧「变量」面板能看到当前每个变量的值，上方工具栏可以
   单步跳过、单步进入、继续。

想看测试里的断点，最省事的办法是直接用 Python 跑那个测试文件本身 —— 每个测试文件
末尾都有这三行：

```python
if __name__ == "__main__":
    unittest.main()
```

于是这样跑，断点照样会停：

```powershell
$env:PYTHONPATH="src"
python tests/test_qc_stats.py
```

（`python -m unittest ...` 那种跑法也能调试，只是要多配一份 `launch.json`，
新手先用上面这种。）

## 9. 提交前，先把仓库自带的门禁跑一遍

| 命令 | 它在查什么 |
|---|---|
| `$env:PYTHONPATH="src"; python harness/selftest.py` | 五项一致性硬门禁，任一项红就非零退出 |
| `python tools/audit_claims.py` | 文档里写的数字能不能在仓库里对上 |

这两条在 GitHub 上每个 PR 都会自动再跑一遍（`.github/workflows/ci.yml`）。
本地先跑，能省掉一轮「推上去才发现红」。

如果动了 `src/` 或 `tests/` 下的 `.py`，还要同步 README 里的代码量：

```powershell
git add <你新增或改动的文件>
python tools/sync_code_counts.py
```

它有一步硬要求：**新增的 `.py` 必须先 `git add`，再跑这个脚本**。否则它会拒绝执行
并列出还没入库的文件名 —— 它只统计入库文件，先跑就会把错的数字写进 README，
等 CI 炸了才发现。

## 10. 常见报错对照

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `ModuleNotFoundError: No module named 'fieldstation'` | 没设 `PYTHONPATH` | 先跑 `$env:PYTHONPATH="src"` |
| `python: 无法将"python"项识别为 cmdlet...` | Python 没装，或装时没勾 PATH | 重装并勾上 Add to PATH，然后重开终端 |
| 输出 `Ran 0 tests` | 命令写错，或不在仓库根目录 | 检查是不是 `-s tests -t .`，检查终端当前路径 |
| 中文输出成乱码 | 控制台编码不是 UTF-8 | 先跑 `$env:PYTHONIOENCODING="utf-8"` |
| 找不到 `tests` 目录 | 终端落在子目录里 | `cd` 回 `field-station-agent` |
