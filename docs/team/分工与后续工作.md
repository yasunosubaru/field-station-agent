申报书「三、人员分工」把 **数据质量校验 Agent 与设备状态监测 Agent** 写在汪志广名下，
而本文档把智能体实现归到负责人。两者**不一致**：

- **申报书已提交，不宜为内部安排改动**；本文档是**内部执行口径**，规定的是
  "谁在什么时间把什么交付出去"，不是对外承诺的角色。
- **本节的处理**：汪志广按本文档做规则层与测试（次要），两个智能体的**实现由负责人出**，
  他负责**测试侧联调**——工作内容仍覆盖申报书那两个 Agent，只是交付责任上移。
- 若你认为应以本文档为准，**结题材料里人员分工的表述要与本文档对齐**，别让两份对不上。

### 边界规则

1. **谁的模块谁的 issue** —— issue 的 Assignee 就是该文件目录的唯一负责人；
   需要动别人的目录，先在 issue 下评论。
2. **搬运件（`PROVENANCE.md` 表内 10 个文件）一律只读**。
   确需改动 → 先开 issue 说明，PR 里必须带 `PROVENANCE.md` 的「改动」列更新。
   源项目已结项，改一处就可能全仓静默失真。
3. **`src/` 与 `tests/` 下不得出现 `gnsstec` 字符串**（含注释与 docstring）。
4. 合并一律走 PR；**不直接 push `main`**（`CLAUDE.md §3`）。
5. 固定测试命令：
   ```powershell
   $env:PYTHONPATH="src"; python -m unittest discover -s tests -t .
   ```
   **`skip == 0`** —— `unittest` 对 skip 不报错，静默跳过会让门禁假绿。
   这是本项目最贵的一条教训（源项目 `test_qc_wiring` 三项静默跳过、selftest 停在 3/5）。
