## 2. 摘要

面向野外台站（GNSS 观测站）的日常运维，本项目把「数据接入 → 质控 → 设备状态监测 →
故障研判 → 运维调度（高风险动作过人工审批）→ 数据归档 → 运行看板」串成一条可回放、
可核对的智能体链路。核心约束是三层：**模型只做归因、规则做裁决、高风险动作必须人工
审批**；每条结论都要引用具体工具调用作为证据，跨阶段不能借用证据。

当前状态：链路在「公开气象数据 + 合成观测」上跑通，五阶段 / 7 条消息 / 8 项机械核对
全过；31 天试运行演练中注入 15 次全检出、16 个干净日零误报；全套工程门禁
（全部测试全绿且 skip 0、5 项发布自检、3 项数字回源、脱敏守卫）可复现。真实台站样本与公开 GNSS
观测（CRINEX 编码）尚未打通，报告中逐处标注，不把合成样本的结论当真实结论。

## 3. 项目背景与目标

### 3.1 背景

野外台站运维的三个现实问题：

1. **数据在、判断不在**：观测数据能收，但「设备是不是坏了、坏在哪、要不要派人」仍靠人；
2. **判断不可复现**：同一批数据，不同人给的结论不同，事后无法追溯；
3. **高风险动作缺少闸门**：重启、断电、改配置这类动作，模型直接执行是不可接受的。

### 3.2 目标

- 把上述流程做成一条可运行、可回放、可核对的链路；
- 结论可追溯到工具调用与数据来源（证据链）；
- 高风险动作必须停在人工审批门；
- 用公开数据把全流程跑通，形成结题标准（spec §6 DoD）的演示与可复用模板。

### 3.3 范围（不做什么）

- 不做台站硬件改造；
- 不做 GNSS 精密定位算法（观测侧只做质控与设备判断）；
- 不追求「全自动无人值守」——审批门是设计的一部分，不是缺陷。

## 4. 研究内容与技术路线

### 4.1 五阶段链路

| 阶段 | 做什么 | 关键约束 |
|---|---|---|
| 1 接入 | 读 RINEX 2/3（含 gzip）、CSV；公开数据源登记与取数 | 数据来源、许可、校验和必须登记 |
| 2 质控 | 周跳 / 相位阶跃、连续性、量级判据 | 判据给计数与历元索引，不给「好/坏」 |
| 3 设备状态 | 读数健康度（缺测 / 质量标记 / 阈值状态） | 看 `status`，不看单一健康分 |
| 4 研判 | 检索规程 + 按证据给结构化结论 | 结论必须引用成功的 `call_id` |
| 5 调度 | 建工单；高风险动作过审批门 | 放行与拒绝都要留审计 |

### 4.2 三层约束

- **模型**：只做归因与解释（本仓库用事实合成器替代模型做确定性演示，真模型通道另测）；
- **规则**：判据、阈值、结论契约由代码裁决；
- **人**：高风险动作停在审批门。

### 4.3 工程方法

- 确定性回放：trace 不含时间戳与随机量；基线用 sha256 钉死（fixture + 日志 + 复校）；
- 五项发布自检 + 数字回源 + 脱敏守卫 + 环境快照；
- 每次改动走 PR，CI 绿才合入。

## 10. 结论与展望

结论：三层约束（模型归因 / 规则裁决 / 人工审批）在工程上是可落地的；可回放与证据链
不是附加功能，而是让「智能体说它判断对了」这句话可以被核对的前提。

展望（按优先级）：

1. 真实样本到位后，用同一套回放与台账重跑，替换所有合成数字；
2. 打通公开 GNSS 观测（#99 决策）或接入台站原始数据；
3. 把审批门扩展到更多高风险动作，补操作审计的检索视图。
