## 4. 模板经验（后续复用的配方）

八步：

1. **先登记数据源** —— `data/public/manifest.json`：来源 / 许可 / 署名 / 校验和 /
   取回日期 / 用途 / 口径边界；
2. **取数 + 校验 sha256** —— 不符即失败，不默默换基线；
3. **映射到本仓数据模型** —— 不引入第二套判据；缺测记 `None` + `missing`；
4. **用既有判据算** —— `station_health` / `slip_detect` / `knowledge_search`；
5. **结论从工具返回派生** —— `FactProvider`：plan 决定调什么，compose 按返回的数字拼结论；
6. **全链留痕** —— 消息 + trace + 审批 + 归档 sha；
7. **机械核对** —— 本演示 8 项 checks，全过才算跑通；
8. **汇报 = 数字 + DoD 逐条 + 边界**（本文件）。

可复用骨架（都在本仓里，换数据源时照抄）：

| 位置 | 作用 |
|---|---|
| `harness/public_data_full_run.py::FactProvider` | 两段式事实合成器（plan / compose） |
| `_payloads()` / `_tool_results()` | 从对话里取上游 payload 与工具返回 |
| `_checks()` | 8 项机械核对清单 |
| `harness/public_data_replay.py::readings_from_open_meteo` | 公开数据 → 设备读数的映射 |
| `data/public/manifest.json` | 数据源登记与许可 |

三条踩过的坑（已写进代码注释）：

- 拼结论时 `messages[-1]` 是**工具返回**，上游 payload 要从**最后一条 user 消息**取 ——
  取错会让上游结论静默变空（第一版就踩了）；
- 设备是否异常要看 `status`（degraded），不能只看 `health_score`（有质量标记时它仍是 1.0）；
- 归档产物没有 `bytes` 字段，别把 `None` 写进结论文案。

## 5. 边界（这份演示**不能**当什么）

- 观测侧是**合成**的；公开观测（CRINEX）未通 → #99；
- 设备侧是**环境再分析**（ERA5），不是台站仪器实测；供电 / 链路 / 安防仍无公开对应物，
  仍用 synthetic 设备异常场景；
- −10 °C 是**演示用示例阈值**，不是工程判据；
- 「模型」被事实合成器替代 —— 演示的是**链路、判据与证据链**，不是模型能力；
- 因此**不**构成 M6-2 任何指标（时滞 / 准确率）的达标证据（口径见
  `docs/operations/evaluation-protocol.md`）。
