# M1 调研与 M2 接入层 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用一个月拿到真实台站的数据字典与故障基线，再据此把 `ingest/` 与 `store/` 扩成能读真实数据的接入层，给 M3 的第一个真 Agent 供数。

**Architecture:** M1 是调研，产出三份文档加一份脱敏样本，全部可勾选、有验收人，代码替代不了。M2 是代码，沿用 M0 的门禁：TDD、replay 回放、`audit_claims` 回源。M2 只扩 `ingest/` 与 `store/`，**不动 `rules/` 与 `agents/`** —— 那两个目录是 M3 的战场。

**Tech Stack:** Python 3.11 纯标准库；`unittest`；`harness/selftest.py` 五项门禁；`harness/replay.py` 确定性回放。

**Spec:** [`docs/spec/2026-10-13-野外台站智能体基础设计.md`](../spec/2026-10-13-野外台站智能体基础设计.md)
（§3.2 数据来源与合成 fixture 的边界、§4 运行时六项能力、§6 Definition of Done、§7 看板字段与 Milestone）
**选型依据：** [`docs/decisions/2026-10-14-智能体运行时选型.md`](../../decisions/2026-10-14-智能体运行时选型.md)

## Global Constraints

以下每条对 M1 与 M2 的全部任务同时生效，抄自 spec 与 `CLAUDE.md`：

- `main` 不直推，一律分支加 PR，`protect-main` 要求 1 个审批（admin 豁免）。
- 搬运件（`PROVENANCE.md` 表内 17 个文件）一律只读；确需改动先立 issue、先写让测试变红的回归、PR 带 PROVENANCE 改动列、证明真实样本行为逐字节未变。
- 固定测试命令 `$env:PYTHONPATH="src"; python -m unittest discover -s tests -t .`，**skip 必须为 0**。
- `python harness/selftest.py` 五项门禁必须 exit 0。
- `README.md` 的 `CODE_COUNTS` 块由 `tools/sync_code_counts.py` 生成，不手改。
- `src/` 与 `tests/` 下不得出现 `gnsstec` 字符串，含注释与 docstring。
- 个人信息（姓名、学号、电话、邮箱、协作者 GitHub 用户名）不进公开仓库；样本数据先脱敏再入库。
- M0 不碰真实台站数据的限制**到 M2 解除**，但解除的前提是 M1 三件交付物齐了。

### 三条边界（错了整个 M2 就白做）

1. **合成流和真实流的分离不能破。** `synthetic.generate()` 出来的数据写进
   `synthetic/` 子目录，`product._isolated()` 已经做了这件事。真实数据绝不能
   漏进合成产物路径，测试 `test_pipeline.py` 管这一条。
2. **fixture 是评测的锚。** M2 换真实 fixture 时，旧 fixture 必须留在 git 历史里
   另起文件名，不许覆盖。门禁 [4]（同 seed 同 config_hash）依赖可回溯。
3. **`rules/` 与 `agents/` 本阶段不动。** 数据模型的字段定了，质控判据和 Agent 才有
   输入；反过来先写 Agent 会写出猜字段的代码。

## Review Focus

spec 是愿景文档，它说软件必须做什么，不说它一定会遇到什么。以下五类是
本阶段最可能让使用者踩空、而任何任务的测试都不会自然覆盖的输入，每条都
钉到拥有那个代码的任务里。

| # | 输入或条件 | 一个理性的人会期待的行为 | 钉到 |
|---|---|---|---|
| 1 | 真实台站数据**字段缺失或为空**（如 `REGISTRY` 里空值 env） | 跳过该字段并记录，不抛未捕获异常 | M2-2 |
| 2 | 时间戳跨 GPS 周 rollover 或闰秒 | 换算正确，不产生负时长或重复 epoch | M2-1 |
| 3 | 同站多传感器单位不一致（V 与 mV 混写） | 统一到数据字典声明的单位再入库 | M2-1 |
| 4 | 脱敏样本里混入看似正常实为编造的坐标 | 台账校验拦下，`validate()` 报错而不是静默接受 | M2-3 |
| 5 | 合成流与真实流在同一目录下被误当成一类 | 产物路径带 `synthetic/` 前缀，测试能分辨 | M2-4 |

## Definition of Done

沿用 spec §6，一条 issue 完成的充要条件：

1. 合并进 `main` 走 PR，没直推
2. 固定测试命令全绿，skip 为 0
3. `python harness/selftest.py` exit 0
4. 新增的实测声明都能被 `tools/audit_claims.py` 回源核对
5. Agent 相关改动可被 `harness/replay.py` 回放复现
6. README 的代码量块由 `sync_code_counts.py` 同步过一次
