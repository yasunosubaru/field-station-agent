# Agent 桌面版 · W0 接口契约（冻结）

> 版本：2026-11-03 W0｜所有并行工作包以本文件为准；改契约先改这里，再改代码。
> 产品名：**All powered-FSA**；EXE：`AllPoweredFSA.exe`。

## 1. 进程与端口

```text
AllPoweredFSA.exe (WinForms + WebView2)
  └─ runtime/node.exe packages/app/src/server.ts --port 0        → stdout "READY <nodePort>"
       └─ (首次 /api/agent/*) python tools/agent_server.py        → stdout "AGENT_READY <agentPort>"
            --port 0 --token <random> --node-url http://127.0.0.1:<nodePort> --repo <root>
```

- 只监听 `127.0.0.1`。
- Node 对所有请求校验 `Host` 与（有的话）`Origin` 必须是 `127.0.0.1:<port>` / `localhost:<port>` / `[::1]:<port>`，否则 403：防 DNS rebinding 与跨站页面调用本机 API。
- Node → Python 请求头：`Authorization: Bearer <token>`。
- Python → Node 请求头：`X-FSA-Token: <token>`。
- 壳把 token 写 `%LOCALAPPDATA%\AllPoweredFSA\runtime.json`，权限仅当前用户。
- 关闭窗口：壳 `Kill(entireProcessTree)`，先 Python 后 Node（或整棵树）。

## 2. 事件模型（会话 JSONL 与 SSE 共用）

一行/一个 `data:` 就是一个事件：

```json
{"type":"message","id":"m1","role":"user|assistant","content":"...","ts":"ISO"}
{"type":"tool_call","id":"c1","name":"station_health","args":{},"risk":"low|medium|high","status":"running"}
{"type":"tool_result","id":"c1","ok":true,"summary":"...","data":{},"evidence":{"agent":"ops","call_id":"t0001"},"duration_ms":12}
{"type":"approval","id":"a1","call_id":"c1","risk":"high","reason":"...","prompt":"...","status":"pending|approved|rejected"}
{"type":"artifact","id":"f1","name":"x.pdf","kind":"pdf|csv|json|png|html","path":"artifacts/<sid>/x.pdf","sha256":"...","source_call":"c1"}
{"type":"plan","items":[{"title":"...","status":"todo|doing|done|blocked"}]}
{"type":"error","class":"environment|input|execution|artifact|capability","message":"..."}
{"type":"token","id":"m2","delta":"文字"}
{"type":"done","session_id":"s1"}
```

- 事件只追加，不改写；`id` 标识**实体**：`tool_call` 与它的 `tool_result` 共用同一个 id，
  `approval` 的 pending 与决定共用同一个 id，`token` 与完整 `message` 共用同一个 id。
  同一实体可多次出现，后者覆盖/补齐前者；事件顺序按文件/流顺序。
- 审批：`approval.status=pending` 时同一 `call_id` 不得出现 `tool_result`；决定后先写 `approval` 再写 `tool_result`。
- SSE：`event: agent\ndata: <json>\n\n`；结束 `event: done`。

## 3. Python Agent HTTP API（`tools/agent_server.py`）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/health` | — | `{ok, version, provider, model, tools}` |
| GET | `/tools` | — | `{tools:[{name,description,risk,source,params}]}` |
| GET | `/sessions` | — | `{sessions:[{id,title,updated_at}]}` |
| POST | `/sessions` | `{title?}` | `{session_id}` |
| GET | `/sessions/{id}` | — | `{session, events:[...]}` |
| POST | `/sessions/{id}/message` | `{text,attachments?}` | `text/event-stream` |
| POST | `/sessions/{id}/approval` | `{approval_id,decision,note?}` | `{ok}` |
| POST | `/sessions/{id}/cancel` | — | `{ok}` |
| GET | `/sessions/{id}/artifacts` | — | `{artifacts:[...]}` |
| GET | `/sessions/{id}/artifacts/{name}` | — | 产物原始字节（attachment） |
| GET | `/settings` | — | `{provider,base_url,model,temperature,has_key,fake_fallback}` |
| POST | `/settings` | `{provider?,base_url?,model?,temperature?,api_key?}` | `{ok,settings}`（key 只写 `secrets.bin`，不回声） |

错误统一 `{ok:false,error,class}`；HTTP 400/404/409/500。

## 4. Node 代理（`packages/app/src/agent-bridge.ts`）

同路径挂在 `/api/agent` 下：

- `GET /api/agent/health`
- `GET/POST /api/agent/sessions`
- `GET /api/agent/sessions/:id`
- `POST /api/agent/sessions/:id/message`（SSE 透传，逐块 flush）
- `POST /api/agent/sessions/:id/approval`
- `POST /api/agent/sessions/:id/cancel`
- `GET /api/agent/sessions/:id/artifacts`
- `GET /api/agent/sessions/:id/artifacts/:name`（原始字节，attachment）
- `GET /api/agent/tools`
- `GET/POST /api/agent/settings`

要求：懒启动 Python；启动失败返回 503 `{ok:false,error:"agent server unavailable: ..."}`；token 不写日志；SSE 不缓冲（`Content-Type: text/event-stream`，`Cache-Control: no-cache`，`Connection: keep-alive`）。

### rpa（Python → `tools/workflow_cli.py`）
`workflow_list` low · `workflow_describe` low · `workflow_run` 按流程 risk ·
`workflow_status` low · `workflow_gate` high（批准=执行不可逆） · `workflow_resume` medium ·
`workflow_cancel` medium · `workflow_artifacts` low

规则：`workflow_run` 返回 `waiting_approval` / `waiting_operator` 时，Agent 必须发审批卡；
`workflow_gate` 只允许 `approved|rejected`，`workflow_resume` 只允许 `done|failed`；
任何一步失败都写 `error` 事件，不抛未捕获异常。

## 6. 会话存储

```text
%LOCALAPPDATA%\AllPoweredFSA\
  sessions/<id>.jsonl
  artifacts/<id>/
  settings.json
  secrets.bin          # DPAPI
  runtime.json         # 端口/token，仅当前用户
  logs/
  jobs/                # workflow jobs（NAS_WORKFLOW_JOBS）
```

会话 JSONL 第一行 `{"type":"meta","session_id","title","created_at"}`；之后事件。
`GET /sessions/{id}` 原样返回事件（UI 可重放渲染）。

## 7. Provider

- `fake`：确定性演示，默认；不联网。
- `openai_compatible`：`base_url + /v1/chat/completions`，`Authorization: Bearer`；支持 `stream=true`（SSE），失败按固定错误分类返回。
- `ollama`：沿用现有。
- 设置：`settings.json` 存 `provider`, `base_url`, `model`, `temperature`；key 只在 `secrets.bin`（DPAPI）。
- 首次启动默认 `openai_compatible` 但未配 key → 自动回退 `fake` 并提示。

## 8. UI 规格（WP1）

- 默认页 = Agent；顶部模式切换 `Agent 工作台 | 专业面板`；专业面板 = 现有 6 个 tab。
- 三栏：左 280（会话/任务）、中自适应（对话）、右 320（设备/日志/产物）；宽度 <1100 收右栏，<800 收左栏。
- 顶栏 48：产品名、模式切换、当前设备、模型 chip、设置。
- 消息：assistant 全宽 markdown；user 右对齐浅色气泡；工具卡/审批卡/产物卡/失败卡/计划卡见事件模型。
- 工具卡：图标 + 名称 + 状态 pill（running/ok/failed/approval）+ 耗时 + 折叠 JSON + 证据 `agent:call_id`。
- 审批卡：琥珀边；动作、风险、影响、批准/拒绝 + 备注；决定后禁用并显示决定人/时间。
- 输入框：多行自增高；附件、`@设备`、`/` 命令、发送；Enter 发送 Shift+Enter 换行。
- 快捷键：Ctrl+N 新会话，Ctrl+K 命令面板，Esc 取消生成。
- 主题：深色默认，浅色可切；token 见 §9。
- 空态：4 个建议 chip（健康度 / 质控 / 导出 PDF / 重启）。
- 可访问性：focus ring、aria-live、键盘可达；不引第三方 UI 库。
- 加载/错误/离线状态必须可见；不得假装成功。
