# v4 实施计划（详细）

- 日期：2026-11-04
- 对应基线：[v4 实施基线](2026-11-04-v4-实施基线.md) · ADR-008 / 009 / 010
- 总周期：**19 周**（按 3 人团队、每周 5 个工作日估；单人则按 2.5 倍算）
- 排序原则：**先收口已验证的东西（RPA），再换壳，再重做看板，最后上双运行时与 bot 编队**

---

## 0. 依赖关系（谁挡谁）

```
W0 契约 ──┬─> W1 RPA 收口 ─────────────┐
          ├─> W2 Electron 壳 + 四视角 ──┼─> W3 套件台重做
          ├─> W4 运行时 A ──> W6 E3 ──> W7 Bot 编队 ──> W9 验收
          └─> W5 运行时 B ──┘        └─> W8 数据双引擎 ──┘
```

可并行的三组：`W1 ∥ W2`、`W3 ∥ W4/W5`、`W6 ∥ W8`。
不可并行：W3 必须在 W2 之后（要壳的布局与主题）；W7 必须在 W6 之后（要图才能挂调度）。

---

## W0 · 契约与假设验证（1 周）

**目标**：把"能不能做"变成"确定能做"，并把接口写死。

| 任务 | 交付物 | 验收 |
|---|---|---|
| Letta 内嵌验证 | spike 脚本 + 结论 | 单进程内能 recall/remember；不行则记降级方案 |
| shim 验证 | `tools/anthropic_shim.py` 最小版 | Claude 侧能经它跑一次带工具的对话 |
| Electron 起壳 | 空壳能起、能加载我们现有页面 | 干净机双击可起 |
| 事件协议 | `docs/contracts/agent-events.md` | 两个运行时都能映射到同一套事件 |
| MCP 工具表 | `docs/contracts/mcp-tools.md` | 每个工具：名字/入参/出参/错误码/是否需审批 |
| `run_link` 四表 | `docs/contracts/run-link.md` | 四张表的主键与关联字段定死 |
| 20 条基准 SQL | `docs/contracts/bench-sql.md` | DuckDB 与 ClickHouse 都能跑 |
| 30 条验收任务 | `docs/contracts/eval-30.md` | 覆盖四视角，每条有期望结果 |
| fixture 规范 | `docs/contracts/rpa-fixture.md` | 快照字段、脱敏规则、回放方式 |

**出口条件**：三个假设都有结论；九份契约评审通过。任一假设不成立，先改方案再开工。

## W1 · RPA 收口（2 周，可与 W2 并行）

**目标**：能自动的全自动；不能的老实标"人工 + 验收清单"；**没有套件也能测回归**。

| 任务 | 交付物 | 验收 |
|---|---|---|
| 校准工具 | `tools/rpa_calibrate.py` | 连套件 dump 元素 → 生成/更新选择器 + diff；8 条流程都能跑一遍 |
| 选择器 lint | `tools/rpa_lint.py` | 禁坐标、禁猜测文字、禁 `sleep` 充当等待 |
| 快照采集 | `tools/rpa_fixture.py --capture` | 每步落 HTML + 关键元素 + 版本指纹 |
| 回放测试 | `tests/test_rpa_fixture.py` | 无套件环境下回放 8 条流程的定位逻辑 |
| 通道调研 | `docs/operations/rpa-channels.md` | Graph 新建/导出、应用安装、固件刷写逐条给结论（能用/不能用/怎么用） |
| 通道升级 | 至少 1 条流程从 GUI 改走 API/CLI | `gui.graph.newproject` 或 `gui.app.install` 有确定性入口 |
| 真机清单 | `docs/operations/rpa-checklist.md` | 8 条各写：跑什么/看什么/证据存哪；缺硬件标 `blocked: hardware` |
| 失败分类 | `tools/trial_ledger.py` 加 `hardware_missing` | 台账能区分"设备没接"与"流程写错" |

**出口条件**：fixture 回放全绿；CI 加门禁；8 条流程状态表进 README。

## W2 · Electron 壳 + 四视角骨架（2 周）

| 任务 | 交付物 | 验收 |
|---|---|---|
| 壳迁移 | Electron 主进程 + 预加载 | 菜单/托盘/单实例/多窗口/崩溃守护可用 |
| 启动编排 | 起 Python 服务 + 界面服务 + 就绪探测 | 40 s 内出窗口；失败有明确报错 |
| 四视角路由 | `/chat` `/fleet` `/data` `/suite` | 四个视角都能进，能力不分区 |
| 共享状态 | 会话池/任务表/工具/证据 统一数据层 | 同一 job 在四个视角看到的是同一份 |
| 深链 | `fsa://job/<id>`、`fsa://device/<id>` | 对话卡片 ↔ 套件闸门 双向跳转 |
| 主题 | 深浅 + 等宽 + 密度 | 与设计 token 一致 |

**出口条件**：四视角能点通，深链双向可用，断网可起。

**硬要求**：先写对照表再写页面；`modern.css` 删除；原版行为差异必须走显式开关。
