## 0. 这一版改了什么

| | v2 | v3 |
|---|---|---|
| 四台 | 按"人"划分 | **四个等价视角**，能力不分区，共享内核 |

## 1. 目标 / 非目标

**目标**：四个视角都能干全部活；没人值守时 bot 能连续跑几个月；海量观测数据能查得动；每个结论可回源；单 EXE、离线可用。

**非目标**：多租户/SaaS、移动端、K8s/消息中间件、patch 厂商二进制、真实台站样本（仍受 #28/#33 阻塞）。

## 2. 四个视角（等价）

| 视角 | 默认布局 | 核心入口 | 验收 |
|---|---|---|---|
| **对话** | 会话 + 工具卡 + 审批卡 | 输入框、命令面板、@设备 | 问一句能得到带证据号的回答 |
| **编队** | bot 列表 + 日程 + 任务树 + 交互抽屉 | 建 bot、派活、暂停/接管 | Supervisor 拆的每一步可复盘 |
| **数据** | 批次 + 质控 + 检索 + 评测 | 选批次、跑质控、问数据 | 换一批数据，数字跟着变 |
| **套件** | 六页签 + 8 条流程 + 证据 | 选设备、跑流程、看审计 | 与原版逐项对得上 |

**等价规则**：能力不分区；状态共享（同一会话池/任务表/工具/trace）；**跨视角深链双向可用**。

| 引擎 | 职责 | 不许做 |

## 4. E1：双运行时契约

### 4.1 内部事件协议（两方都产出）

`session.start / message.delta / message.done / tool.call / tool.result / approval.request / approval.result / usage / error{class,message}`

UI 只认这套事件，不知道下面是 A 还是 B。

### 4.2 两个实现

| | A · OpenCode（OpenChamber 源码） | B · Claude Agent SDK（官方） |
|---|---|---|
| 接 deepseek | 原生 OpenAI 兼容 | `tools/anthropic_shim.py` 转 Anthropic Messages |
| 无 shim | 不受影响 | 用它自带模型通道照常工作 |
| 会话状态 | 自有 | 自有 |
| 工具 | 直连 MCP | 直连 MCP |

### 4.3 互不依赖的验收（不是排名）

对每个运行时**分别**要求：30 条任务（覆盖四视角）都能独立完成，记录完成率/步数/token/时延/审批合规/抗错性。
**不比较名次，只证明"各自都能独立干完"**；任一方不可用时另一方不受影响。

## 5. E2：三组件协作

### 5.1 所有权

| 组件 | 拥有 | 只写这里 |
|---|---|---|
| DBOS | 执行真相 | workflow/step 表（SQLite） |
| LangGraph | 推理真相 | checkpointer + trace.jsonl |
| Letta | 记忆真相 | memory blocks / archival |
| 台账 | 业务真相 | 工单/审批/结论/产物 sha256 |

`run_link(task_id ↔ thread_id ↔ agent_id ↔ work_order_id)` 是唯一耦合点。

### 5.2 调用链

`letta.recall → langgraph.plan → 子 workflow × N →（闸门挂起）→ langgraph.verify → letta.remember → 台账`
外层永远是 DBOS；LangGraph 不定时；Letta 只在首尾。

### 5.3 交互层

任务树 + 事件流 + 三种干预（暂停/继续、改参重试、接管）+ **可与大 bot 自由对话**、可下钻到小 bot 的某一步对话/接管。
干预写在 `intervention` 表，DBOS 在步骤边界消费。

### 5.4 降级

Letta 缺 → `bot_memory` + Chroma；DBOS 缺 → APScheduler + 队列表（丢 exactly-once）；LangGraph 缺 → `pipeline.py`。

## 6. 数据：三层 + 双引擎

| 层 | 内容 | 技术 | 目标 |
|---|---|---|---|
| L0 摄取 | 帧解析 → Parquet（`station/date/hour`） | 现有 `ingest/` + 向量化 | 1 Hz 单站无压力；500 epoch/s 要实测 |
| L1 查询 | 聚合/窗口/质控 | **DuckDB（默认）** / **ClickHouse（随包可选）** | 单站单日 ≤1.5 s；看板预聚合 ≤200 ms |
| L2 语义 | 自然语言问数 | LlamaIndex（元数据卡 + 手册）+ Text-to-SQL | 答案带「分区路径 + SQL + 行数」 |

- 唯一真相是 Parquet；两引擎只读它；切换只重建聚合；
- 20 条基准 SQL 两边都跑；引擎不可用自动回落并**明示**；
- Text-to-SQL 只读 + 强制 `LIMIT` + 禁 DDL。

**换引擎阈值**：>50 亿行或需 <100 ms 多维交互 → 默认切 ClickHouse；需秒级流式看板 → 加降采样时序库。

## 7. 外壳与打包

- 容器：现有 WinForms + WebView2（起界面服务 → 读端口 → 指过去）；
- 界面：OpenChamber `packages/ui` + `packages/web` fork；
- 体积预算：**不再是硬约束**（负责人 2026-11-04：体积无所谓）。按实测记录即可，
  两个运行时 + ClickHouse + 依赖预计 1.5–2 GB；Electron 壳重新成为可选项（多约 400 MB）；
- 起不来要报明确错误，不停在白屏。

---

## 8. 非功能

离线可用；单 EXE；冷启动 ≤40 s（首次解压除外）；只监听 127.0.0.1；密钥走 DPAPI；许可保留署名；回放不联网、同 seed 同结论。

## 9. DoD

1. 四视角各自验收项全过，跨视角深链双向可用；
2. 两个运行时**各自**能独立完成 30 条任务，出一份报告；
3. bot 连续跑 7 天不丢任务，重启续跑；
4. 亿级行数据单机可查，20 条基准 SQL 通过；

6. 单 EXE 干净机可用、断网可用；数字可回源。
