## 0. 本文解决什么

0.2.0 证明了「一个 EXE + Agent 工作台 + 原版套件」能跑通，也暴露了三件事：

1. 界面自己写，加一个台就贵一分；
2. 只有「人问一句」这一种入口，没人问的时候系统是死的；
3. 判断、数据、知识、存储混在 `agents/` 一个目录里，边界看不出来。

v2 的回答是：**四个台（人看的地方）+ 七个引擎（干活的地方）**，界面长在成熟框架上，
我们只写领域层与显示层。

## 1. 目标 / 非目标

**目标**

- 四个台都有面向人的界面，且观感统一（同一个框架、同一套主题）；
- 无人值守时系统自己会干活（常驻 bot），人只负责批与复盘；
- 任何结论都能点回到「工具输出 → job → 截图/sha256」；
- 单 EXE、离线可跑、断网不瘫。

**非目标**

- 不做多租户/SaaS；不做移动端；不引 K8s/消息中间件；
- 不为「像 Mrite」而 patch 厂商二进制（只驱动它）；
- 不在这一版做真实台站样本（仍受 #28/#33 阻塞）。

## 2. 四个台

### ① 会话台 Chat

| 项 | 内容 |
|---|---|
| 谁用 | 值班的人、老师演示时 |
| 能做什么 | 问状态、看工具卡与证据、批准/拒绝、下载产物、切模型 |
| 数据从哪来 | E1 会话循环 → MCP 工具 → E3/E4/E6/E7 |
| 验收 | 问「BADG 观测质量」能返回带证据号与耗时的回答；拒绝审批后设备不动 |

### ② Bot 台 Fleet

| 项 | 内容 |
|---|---|
| 谁用 | 想让系统自己守夜的人 |
| 能做什么 | 看 bot 列表（模型/工作区/记忆/今日任务/最近失败）、开 bot 私有会话、看日程、暂停/接管、看派活链路 |
| 数据从哪来 | E2（`bot_task` / `bot_memory` / `bot_run` 三张表） |
| 验收 | Supervisor 把「今日巡检」拆成 3 步派给 2 个 worker，全程可逐条复盘；失败能说清是模型、工具还是设备 |

### ③ 专业台 Pro

| 项 | 内容 |
|---|---|
| 谁用 | 要操作接收机的人 |
| 能做什么 | 看原版六页签（只读镜像）、跑 8 条流程（带闸门）、看截图与 audit.jsonl、下载产物 |
| 数据从哪来 | E7（CDP/UIA/native）+ E5（job/证据） |
| 验收 | Manage 页设备卡与真实套件一致；跑 `gui.suite.autoupdate` 能读到真实版本号；写操作必停在闸门 |

### ④ 数据台 Data

| 项 | 内容 |
|---|---|
| 谁用 | 要判断「数据能不能用」的人 |
| 能做什么 | 看批次与质控通过率、迟滞设备与缺口、知识库检索测试、数据集版本与评测得分 |
| 数据从哪来 | E4（DuckDB）+ E6（Chroma）+ E5（台账） |
| 验收 | 每块指标都能点回源文件；换一批数据后数字随之变化，不是写死的 |

## 3. 七个引擎的接口契约

统一约定：`run(input, ctx) -> result | error`，`ctx` 带 `trace_id / job_id / actor`，
`error` 必带 `class`（`environment|input|execution|policy|unknown`）。所有调用写同一条 trace。

| 引擎 | 输入 | 输出 | 不许做 |
|---|---|---|---|
| **E1 会话循环** | 一句话 + 会话历史 + 工具表 | 文本流 + 工具调用序列 | 自己下领域结论；自己批准 |
| **E2 Bot 引擎** | 日程/事件/人手动触发 | `bot_task` 状态机推进 + 结果 | 越过 E3 直接判故障；自己批准 |
| **E3 领域编排** | 观测/设备/上下文消息 | 五阶段产物 + 结论（带证据） | 直接动设备；绕过闸门 |
| **E4 数据引擎** | 原始文件/公开数据 | 批次、质控结果、特征、数据集版本 | 改原始数据；写台账以外的表 |
| **E5 存储** | 各引擎的读写请求 | 一致性视图 | 存密钥明文；跨库事务假装成立 |
| **E6 知识** | 文档/查询 | 片段 + 出处 | 编造出处；把检索当结论 |
| **E7 设备** | 工具调用/流程步骤 | 真实 UI 结果 + 截图 + audit | 猜测控件；无闸门写操作 |

## 4. 两条端到端路径

**A. 人在问**：输入 → E1 选工具 → MCP → E3（或 E4/E6/E7）→ 结论契约 → 工具结果 →
E1 叙述 → 工具卡（耗时/证据号）→ trace。

**B. bot 在守**：日程/事件 → E2 Supervisor 拆活 → worker 调同一批 MCP 工具 →
遇写动作停闸门 → 人批 → 继续 → 结果写 `bot_memory` 与工单 → Bot 台可复盘。

两条路径**共用同一批工具与同一条 trace**；差别只在「谁发起」。

## 5. 非功能要求

| 项 | 要求 | 怎么验 |
|---|---|---|
| 离线 | 断网仍能：起界面、跑 E3 回放、查本地知识、驱动套件 | 拔网线跑一遍验收清单 |
| 单 EXE | 一个文件启动，自带 Node/Python/依赖/原版套件 | 干净机双击 |
| 体积 | ≤1.3 GB（压缩后） | `release.json` |
| 启动 | 冷启动 ≤40 s（首次解压除外） | 计时 |
| 安全 | 只监听 127.0.0.1；密钥走 DPAPI；审批不可绕过 | `docs/product/security.md` |
| 许可 | 保留 Open WebUI 署名与 NOTICE；不引无 LICENSE 代码 | `tools/audit_claims.py` + 人工复核 |
| 可复现 | 固定数据集 + seed + 模型，两次跑结论一致 | `harness/replay.py` |

## 6. 与 0.2.0 的关系

| 0.2.0 的东西 | v2 处置 |
|---|---|
| WinForms/WebView2 外壳、payload 解压、端口探测 | **保留**（换成起 Open WebUI） |
| 手写三栏 Agent 界面（`web/agent/**`） | **退役**，由 Open WebUI 原生 Chat 取代 |
| 专业面板六页签（`web/panels/**`） | **保留**，搬进 `/pro` 路由 + 换皮肤 |
| `tools/agent_server.py`（自写 SSE/审批） | **退役**，由 Open WebUI Pipe + MCP 取代 |
| Python 领域层（`agents/` / `rules/` / `store/`） | **保留**，搬进 E3 节点 |
| 8 条 RPA 流程 + `cdp_driver` | **保留不动**（E7） |
| 30 个工具 + 三条桥 | **保留**，改由 MCP 暴露 |
| 828 项测试 / selftest / 数字回源 | **保留**，全部继续跑 |

迁移顺序见 §8：**先立底座，再换循环，最后才动领域层**——反过来会同时失去可验证性与进度。

## 7. DoD（v2）

1. 四个台各自验收项全过（§2）；
2. 两条路径（人在问 / bot 在守）都能端到端跑通，且共用 trace；
3. 单 EXE 在干净 Windows 上双击可用，断网可用；
4. 原有 828 项测试仍全绿（可增不可减），`pipeline.py` 降级路径仍可跑；
5. 所有对外数字可回源；许可与署名齐全；
6. 结题材料（一页摘要 / 软著）随版本更新数字。

## 9. 风险与未决

| 风险 | 影响 | 处置 |
|---|---|---|
| Open WebUI 依赖体积超预期 | 破 1.3 GB 上限 | W0 实测；超了就裁（去 TTS/whisper、只留 CPU 版） |
| LangGraph 作 Pipe 的流式/取消不达预期 | 会话体验差 | W4 前先做一天 spike，不达标改用 Pipe 内自写循环（仍是一个循环） |
| 两个引擎同时写同一张表 | 数据错乱 | 只有 E5 有写权限，其余走它 |
| 上游套件升级改文字 | 流程停摆 | 已有：`GuiUnavailable` + 截图 + 转人工 |
| 品牌条款 | 许可风险 | ≤50 用户；保留署名与非官方声明 |
