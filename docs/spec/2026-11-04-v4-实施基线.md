# v4 实施基线：四视角 · 双运行时 · 双引擎 · 套件台重做

- 日期：2026-11-04
- 状态：**定稿实施基线**（负责人已定：Electron 壳、体积不限、套件台重做、RPA 先做、两个 Agent 运行时都做、Bot 三组件、数据双引擎）
- 取代：[v3 设计](2026-11-04-v3-四视角双运行时.md)（v2/v3 留作历史）
- 关联：ADR-008 / ADR-009 / ADR-010 / ADR-001 / ADR-007

---

## 0. 一句话

**一个 Electron 壳 + 四个等价视角 + 两条互不依赖的 Agent 链路 + 一个由 DBOS 管时间、LangGraph 管判断、Letta 管记忆的 Bot 编队 + 一份 Parquet 上的两个查询引擎；套件台重建成原版替代级看板，RPA 先收口。**

## 1. 范围

**做**：四视角界面、双运行时、Bot 编队、数据三层与双引擎、套件台重做、RPA 收口、单 EXE 打包。
**不做**：多租户/SaaS、移动端、K8s/消息中间件、patch 厂商二进制、为体积做裁剪（体积已不限）。

---

## 2. 四个视角（等价）

| 视角 | 默认布局 | 能力 | 验收 |
|---|---|---|---|
| 对话 | 会话 + 工具卡 + 审批卡 | 全部 | 回答带证据号；拒绝后设备不动 |
| 编队 | bot 列表 + 日程 + 任务树 + 交互抽屉 | 全部 | 每一步可复盘；可直接对话/接管 |
| 数据 | 批次 + 质控 + 检索 + 评测 | 全部 | 换数据数字跟着变 |
| 套件 | 左导航 + 内容 + 检查器 | 全部 | 与原版字段逐项对得上 |

规则：能力不分区、状态共享、**跨视角深链双向可用**。

---

## 3. 壳与打包

- **Electron**（OpenChamber 的 `packages/electron` 为主，`packages/ui`/`web` 为界面）；
- 保留：原生菜单、托盘、多窗口、单实例、崩溃守护；剥掉云/中继/遥测/coding 面；
- 外壳只负责：payload 解压、拉起 Python 服务与界面服务、把窗口指过去；
- **体积不设上限**，只记录实测值（预计 2 GB 左右）。

---

## 4. Agent：双运行时（互不依赖）

| | A · OpenCode（OpenChamber） | B · Claude Agent SDK |
|---|---|---|
| 接 deepseek | 原生 OpenAI 兼容 | `tools/anthropic_shim.py` |
| 无 shim | 不受影响 | 用自带模型通道照常工作 |
| 状态 | 自有会话 | 自有会话 |

硬约束：无共同前置、不共享状态、不互相代理、失败隔离不自动切换、特化源一份两份产物。
**验收**：两个运行时各自独立跑完 30 条任务（覆盖四视角），出各自报告，不排名。

---

## 5. Bot：三组件协作

| 组件 | 拥有 | 只写这里 |
|---|---|---|
| DBOS | 执行真相 | workflow/step 表（SQLite） |
| LangGraph | 推理真相 | checkpointer + trace.jsonl |
| Letta | 记忆真相 | memory blocks / archival |
| 台账 | 业务真相 | 工单/审批/结论/产物 sha256 |

`run_link` 是唯一耦合点；外层永远是 DBOS；LangGraph 不定时；Letta 只在首尾。
**交互层** = 任务树 + 事件流 + 三种干预（暂停/继续、改参重试、接管）+ 可与大 bot 自由对话、可下钻小 bot。
降级：Letta→`bot_memory`+Chroma；DBOS→APScheduler；LangGraph→`pipeline.py`。

---

## 6. 数据：三层 + 双引擎

| 层 | 技术 | 目标 |
|---|---|---|
| L0 摄取 | 现有 `ingest` + 向量化 → Parquet（`station/date/hour`） | 1 Hz 单站无压力；500 epoch/s 实测 |
| L1 查询 | **DuckDB（默认）/ ClickHouse（随包）** | 单站单日 ≤1.5 s；看板预聚合 ≤200 ms |
| L2 语义 | LlamaIndex（元数据卡 + 手册）+ Text-to-SQL | 答案带「分区 + SQL + 行数」 |

Parquet 是唯一真相；两引擎只读；切换只重建聚合；不可用自动回落并明示；20 条基准 SQL 两边都跑。

---

## 7. 套件台：重做（详见 ADR-010）

- **保留**信息架构与数据契约，**重建**组件层（Tailwind + shadcn 风格）；不再用 `modern.css` 叠皮；
- 三栏：左导航（六页面 + 设备）、中内容、右检查器（设备详情 / 证据 / 日志）；
- 表格固定表头、列宽可拖、数字右对齐、密度可切；空态/错误态必须写"为什么没有"；
- 验收：1280/1440/1920 不溢出；字段与状态逐项对得上；对比度 ≥4.5。

---

## 8. RPA：收口（详见 ADR-010）

1. **校准工具**：连上套件 dump 可交互元素 → 生成/更新选择器 + diff；
2. **DOM fixture 回放**：无套件也能在 CI 抓出失效选择器；
3. **通道升级**：能用 API/CLI/文件格式就绕开 GUI（已确认 `graph.export`）；
4. **真机清单**：8 条各写"跑什么/看什么/证据在哪"，缺硬件的标 `blocked: hardware`。

现状基线：2 条真全自动、3 条到闸门（设计如此）、3 条被环境卡住。
**目标**：能自动的全自动，不能的必须有明确 assisted 协议与验收清单，不留"半自动不明不白"。

## 10. DoD

1. 四视角各自验收项全过，深链双向可用；
2. 两个运行时各自跑完 30 条任务并出报告；
3. bot 连续跑 7 天不丢任务，重启续跑；
4. 亿级行数据单机可查，20 条基准 SQL 通过；
5. 套件台三档分辨率不溢出、字段逐项对得上；
6. 8 条 RPA 流程：全自动或明确 assisted，fixture 回放绿；
7. 828 项存量测试仍全绿，`pipeline.py` 降级可跑；
8. 单 EXE 干净机可用、断网可用；
9. 数字可回源；许可与署名齐全。

## 11. 风险

| 风险 | 处置 |
|---|---|
| 套件台重做变成"再写一遍原版" | 只做六个页面的信息架构 + 组件层，不重写业务逻辑；对照表驱动验收 |
| 双运行时维护翻倍 | 契约先行、特化同源生成、CI 校验 |
| 三组件状态打架 | `run_link` 单一耦合点 + 降级梯度 |
| RPA 仍被硬件卡住 | 如实标 `blocked: hardware`，写清单不写"已完成" |
| Electron 迁移丢现有验收 | 外壳只换容器，验收清单逐条重跑 |
