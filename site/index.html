01 / 关于这个包三部分，一个目录

你拿到的是什么

安装器把三样东西装到同一个目录。它们原本是三个独立项目，这里第一次合成一个可运行的交付物——不是四视角工作台，也不是单纯的文档集。

02 / 固定流程一条流程的真实样子

gui.graph.newproject 怎么跑

从 SBF 文件新建 Graph 工程，原版 GUI 要连续操作两个原生对话框。这条流程把它们自动化，走到最后一步停在一个人工闸门。下面是实际步骤节选——不是概念图。

01healthautomatic
探测 7788 端口与会话健康度
06open_wizardautomatic
附加 Graph 进程（--remote-debugging-port=9224），打开 New Project 向导
10choose_folderautomatic
原生 Select Folder 对话框：agent-desktop 按 accessibility ref 定位，AttachThreadInput 绕过前台锁定
12choose_fileautomatic
Receiver Data 的 Open 对话框，同上机制；不再靠坐标点击
19approve_plothuman_gate
绘图前停下，等人确认；写盘不可逆的步骤不替人决定

全部 19 步里 16 步自动、1 步人工闸门，其余为等待与断言。另有 2 条流程（固件刷写 / 设备重启确认）已推到硬件边界，缺一台真接收机做端到端。

04 / 边界哪些没做到

不把做不到写成做完了

A−B 覆盖矩阵逐项盘点原版 GUI 的 50 项功能。剩下的缺口分成三类——人工闸门、硬件边界、本机不适用，各自有不同含义。

human_gate

3 条写盘流程停在人工闸门。approve_plot、gui.app.install、gui.app.update 涉及不可逆写盘，自动走到闸门后由人批准。

hardware

3 条卡在硬件边界。设备新增、固件刷写、重启确认——代码与闸门已推到位，本机 /api/ports 只有蓝牙串口，缺一台真接收机做端到端。

not_applicable

11 项本机不适用。SPAN/IMU、双天线 ALIGN、PPP、电台、事件样本——OEM729 无对应硬件或授权，原版本机也只有空态，换机型才需要重新处置。

frontend

包内前端是 0.1.10 版。为了拿到正确的 My Applications 界面；工作树最新前端（含四视角代码）没有打进这个 exe。

unverified

原版静默安装分支未在干净机器实跑。本机已装原版，检测到后跳过；GUI 版直接内嵌原版套件，不依赖那条分支。
