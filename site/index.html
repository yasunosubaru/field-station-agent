第一步 · 摄取

观测，进来了。

rinex2 / rinex3 / CRINEX 解析成统一的观测对象，进入五阶段链路。

第二步 · 监测与质控

可用性，逐条判定。

设备侧统一观测面，数据侧逐条可用性判定——每条结论都带可回放的证据。

第三步 · 研判

高置信度放行，
低置信度停门。

规则裁决、模型归因。高风险判断落到人工审批门，不让模型自己下结论。

第四步 · 调度

派单，定时限。

运维任务带优先级与时限，超时自动升级；高风险动作只返回授权命令包。

第五步 · 归档与看板

留痕，然后呈现。

入库留痕，告警看板只读展示、不重算状态——同一份口径贯穿到底。

系统怎么流转

从台站现场到告警看板，五个阶段依次接力；每一步的输入与结论都可回放到真实工具调用。

覆盖边界 · 诚实标注

说清哪些做到了，
哪些还没做到。

A−B 覆盖矩阵逐项盘点原版 GUI 的 50 项功能。我们没有把「做不到」写成「做完了」。

35 项 B 已覆盖 1 项部分覆盖 3 项 A-only（RPA 兜） 11 项本机不适用
仍停在人工闸门graph.newproject 的原生对话框已全自动，但 approve_plot 与 app.install/update 因写盘不可逆，必须人点批准。
硬件相关未真机验证8 条流程中 3 条（设备新增 / 固件刷写 / 重启确认）的代码已推到硬件边界，缺一台真接收机做端到端。
前端版本差异v1.0.0 内嵌 0.1.10 版 My Applications 界面；工作树最新前端（含四视角代码）没有打进这个 exe。
看板是静态快照运行看板页由固定种子合成样本生成，不含生成时间戳，不会自动刷新；真实台站样本受授权阻塞。
